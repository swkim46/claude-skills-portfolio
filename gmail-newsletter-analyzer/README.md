# 뉴스레터 수집과 학습 노트 작성 도구

[포트폴리오](../README.md) / 구현 참고 · [공부하던 방식을 노트 작성에 반영한 과정](../docs/03_학습노트_설계.md)

뉴스레터와 연결된 원문을 수집하고, 완성한 노트의 형식과 누락을 검사하는 도구입니다. 같은 날짜의 노트를 수정하면 이전 판도 따로 보관합니다.

노트에 넣을 내용을 고르고 글을 쓰는 작업은 [world-study 스킬](../.claude/skills/world-study/SKILL.md)이 맡습니다. 이 폴더에는 수집·검사·파일 정리 스크립트가 있습니다. 표준 라이브러리를 사용하며, PDF 본문을 추출할 때만 `pypdf`가 필요합니다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `gmail_imap.py` | IMAP으로 메일함 검색과 본문 읽기 |
| `scan_senders.py` | 발신자별 수신 현황 확인과 수집 목록 후보 제안 |
| `digest.py` | 지정 기간의 발행분을 한 파일로 정리. 협찬·안내문 제거, 미등록 발신자와 스팸함 발행분 경고 |
| `fetch_article.py` | 본문에 연결된 원문 수집. PDF 자동 감지와 본문 추출 |
| `check_note.py` | 금지 표현, 발행분 대응, 중복, 표시 규칙, 뷰어에서 깨지는 문자 검사 |
| `cache_claims.py` | 출처 검증 결과를 저장해 같은 주장의 중복 조회 방지 |
| `tidy_versions.py` | 날짜별 최신 버전만 남기고 이전 버전을 `이전버전/`으로 이동 |
| `build_corpus.py` | 직접 작성한 노트와 해당 발행분을 연결해 작성 방식 분석에 사용할 자료 생성 |
| `newsletters.json` | 수집할 발신자, 활성 여부, 제외 사유 관리 |
| `run_tests.py` | 자체 검사 세 가지를 한 번에 실행하고 전체 실행 완료 여부와 건수를 `test_logs/`에 기록 |

## 처리 순서

1. `python3 digest.py --since "<직전 노트의 수집 시각>"`으로 그 이후 도착한 발행분을 한 파일로 모읍니다. 시작 시각은 직전 노트 머리말의 수집 시각을 그대로 사용합니다. 날짜 단위로 구간을 잡을 때 생기는 누락과 중복을 방지하기 위한 기준입니다.
2. 스킬이 자료를 읽고 노트를 작성합니다. 선별한 항목에 연결된 원문은 `fetch_article.py`로 확인합니다.
3. `python3 check_note.py <노트> --material <자료>`로 작성된 노트를 검사합니다.
4. `[AI]` 문장의 출처 검증과 사전 감사를 진행하고 교정을 반영합니다. 이미 검증한 주장은 `cache_claims.py`가 확인해 중복 조회를 줄입니다.
5. 검증 리포트와 노트의 단계별 검사를 통과한 뒤 발행합니다. 발행 뒤 감사에서 발견한 사실 오류와 판정 변경은 한 차례 반영합니다.
6. `python3 tidy_versions.py`로 날짜별 최신 버전만 남깁니다.

## 수집 목록

국내 뉴스레터 3종과 Axios의 미국 시장 뉴스레터 6종을 수집합니다. 한국 시각 아침에 노트를 작성하므로 미국 뉴스레터는 장 마감 후 발송하는 것으로 골랐습니다. 공개본의 `newsletters.json`에는 개인 전달 주소 대신 자리표시자가 있습니다. 사용 전에 자신의 주소를 입력해야 합니다.

## 노트 파일 규칙

- 파일명은 `세상공부_YYMMDD_노트_vN_M.md`입니다. 같은 날짜의 노트를 수정하면 `v1_1`, `v2_0`처럼 버전을 올립니다.
- 메인 폴더에는 날짜별 최신 파일만 두고, 이전 버전은 `이전버전/`으로 옮깁니다.
- 노트는 거시·시장, 기업·산업, 테크·AI, 정책·제도, 부동산, 지정학·해외, 생활·트렌드, 할 일·일정의 여덟 절로 구성합니다.
- 원문에서 근거를 확인한 문장에는 표시를 붙이지 않습니다. 원문에 없는 사실에는 `[AI]`, 해석에는 `[추정]`을 붙입니다.

## 설정

1. Gmail에서 2단계 인증을 켜고 앱 비밀번호를 발급합니다.
2. 저장소 루트의 `.env.example`을 `.env`로 복사해 `GMAIL_ADDRESS`와 `GMAIL_APP_PASSWORD`를 채웁니다.
3. `python3 scan_senders.py --days 30`으로 수집이 되는지 확인합니다.

자체 검사는 `python3 run_tests.py`로 한 번에 실행합니다(`check_note.py --selftest`, `cache_claims.py selftest`, `fetch_article.py --selftest`). 전체 실행 완료 여부와 건수를 `test_logs/`에 기록하며, API 키 없이 동작합니다.

## 보안

메일 접근에는 IMAP과 앱 비밀번호를 사용하며 OAuth 클라이언트 파일은 사용하지 않습니다. 앱 비밀번호는 Google 계정에서 언제든 폐기할 수 있습니다. `.env`는 저장소에 포함하지 않습니다.

## 비공개 자료

이 폴더에는 개인 학습 노트와 구독 뉴스레터 원문, 실제 분석·매매 기록과 인증 정보를 넣지 않았습니다. `세상공부/`와 `_raw_sources/`는 비어 있으며 실행 중 자료가 생성됩니다. 공개할 수 있는 학습 노트의 일부만 [실제 기록 발췌](../examples/실제_기록_발췌.md#study)에 실었습니다. 작성 규칙 분석에 사용한 노트와 원문 대조 자료는 공개하지 않습니다.
