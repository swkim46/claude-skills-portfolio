# Knowledge Map — 일상·개인 프로젝트 (start + update)

> ### ▶ 단계 게이트 — **규모별 2단** (작으면 가볍게, 크면 강제)
> 헬퍼 `SG` = `python3 <REPO>/.claude/skills/_stepgate/stepgate.py`
> - **간이 모드 (폴더 5개 미만 · 단순 start)** — SG 호출 없이 진행. 단 **아래 자가 점검은 그대로 채운다**(이게 최소 강제 레버).
> - **정식 모드 (폴더 5개 이상 · 지도 구조를 손대는 update)** — ① `SG form life-map <start|update>` → ② 정직히 답 → ③ `SG judge life-map <start|update> <id>=<값> …` → **GATE PASS 아니면 결과 제시 금지.** 게이트 루브릭 직접 열람 금지.
> `<REPO>` = 이 저장소를 클론한 **절대경로**(문서상 표기). `dir=`·`deliverable=`은 절대경로여야 하므로 호출할 때 실제 경로로 치환한다.

**대상 = `<REPO>/`**. 그 안의 `_지식지도_KNOWLEDGE_MAP.md` — "뭐가 어느 폴더에 있는지" 한눈에 보는 **포인터 인덱스**. 컨설팅 지도와 달리 *레터·전략질문·클라이언트 개념이 없다* — 생활 영역으로만 묶는다.

## B. start — 새 프로젝트의 집·이름

### B-1. 원칙
1. **생활 영역으로 배치.** 기본 축: `travel/` · `home/`(집·살림) · `health/` · `money/` · `projects/`(취미·사이드). 지도에 이미 쓰는 축이 있으면 **그것을 따른다** — 임의 프레임 발명 금지. cf. [[organize-by-user-taxonomy]]
2. **이름은 알아볼 수 있게.** 폴더명 = 주제(+시기) 명사구(예: `발리_2026.08`), 산출물 = `<주제>_vN_M.{md,html,xlsx}`. **스킬 이름을 접두사로 붙이지 말 것.** cf. [[filename-follow-workstream-convention]]
3. **여행은 한 여행 = 한 폴더.** 일정·예약·검증 리포트를 흩지 말고 그 폴더 아래로(검증 리포트는 서브폴더 가능). *실사례: 발리 일정과 그 링크 검증 리포트가 별도 최상위 폴더로 흩어져 있던 것을 한 폴더로 합침.*
4. **생성은 골격까지만.** 폴더 + `CHANGELOG.md`(1줄: 생성일·목적) + 빈 `_raw_sources/`. 본 산출물은 책임 스킬이. cf. [[deliverable-versioning]] · [[fetch-files-never-repo-root]]
5. **중복 금지.** 같은 일의 기존 폴더가 있으면 새로 만들지 말고 그걸 쓴다(스캔·지도로 먼저 확인).

### B-2. 워크플로우
1. **현 지도 통독** — `life/_지식지도_KNOWLEDGE_MAP.md`(없으면 §형식 스펙대로 신설).
2. **중복 확인 — 스캔**:
   ```
   python3 <REPO>/.claude/skills/_shared/scan_folders.py --root <REPO>/life
   ```
3. **위치·이름 결정** — 생활 영역 배정 + 폴더명 + 산출물 파일명 스템(`<주제>_v1_0`).
4. **생성** — 폴더 + `CHANGELOG.md` + 빈 `_raw_sources/`. 임시·fetch 파일은 그 폴더의 `_raw_sources/`에만.
5. **지도 스텁 등록** — §1 표에 행 추가(`현행 = (착수 — 준비 전)` · 🟢) + 헤더 "최종 갱신" 날짜. **목적 외 내용 추측 금지.**
6. **핸드오프** — 폴더경로·파일명·목적을 책임 스킬에 넘긴다.

## C. update — 델타 갱신

### C-원칙
1. **지도는 포인터다.** 셀은 1~2줄. 세부는 폴더 파일에.
2. **자동 재생성 금지 · 델타만.** "메모"·상태는 사람이 큐레이션한 것이라 파일 목록으로 재생성하면 소실된다. 스캐너로 *바뀐 것만* 고치고 나머지는 그대로.
3. **근거 있는 셀만.** 현행 산출물·상태·메모는 **폴더의 실제 파일을 읽고** 채운다. 추측 금지. cf. [[analysis-must-be-reference-grounded]]
4. **갱신 루틴 = 헤더 날짜.** 변경 로그는 `_지식지도_CHANGELOG.md`(있으면).

### C-워크플로우
1. **현 지도 통독.**
2. **스캔** — 위 B-2 ②와 같은 명령(`--json`으로 기계 판독).
3. **대조 → 델타 식별** — 신규 폴더 / 버전 상승(스캐너 newest > 지도의 현행) / 상태 변화(🟢 진행 ↔ ✅ 완료 ↔ ⏸ 보류).
4. **델타만 반영** — 해당 행만 수정. 손대지 않은 서술 보존.
5. **헤더 갱신** — "최종 갱신: YYYY-MM-DD".

### C-bis. 파일 없는 단건 조사 → 요약 등재
1. **후보 판정(맥락)** — 직전 대화가 폴더·파일이 *생기지 않은* + 의미있는(결론이 있는) 조사인가? (잡담·사소한 조회 제외.)
2. **한 줄 확인** — "이 내용을 지도에 요약으로 남길까요?" OK일 때만.
3. **§2 요약 인덱스에 1항목** — `- **[영역] 제목** (YYYY-MM-DD·파일 없음): 결론 1~2문장 + 인접 폴더.` 자족적으로.

## 형식 스펙 (지도 구조)

- **헤더**: 목적 1줄 · 최종 갱신일 · 상태 범례(🟢 진행 / ✅ 완료 / ⏸ 보류 / 🔁 상시).
- **§1 인덱스** 표: `영역 | 폴더 | 주제 | 현행 산출물 | 상태 | 메모` (셀 1줄). **start 스텁 행**: 현행=`(착수 — 준비 전)`·🟢.
- **§2 단건 조사 요약**(선택): 폴더·파일 없는 조사 — 항목당 1줄.
