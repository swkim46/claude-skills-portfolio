# Verified Research — 일상·실무

> ### ▶ 단계 게이트 — **규모별 2단** (작으면 가볍게, 크면 강제)
> 헬퍼 `SG` = `python3 <REPO>/.claude/skills/_stepgate/stepgate.py`
> `<REPO>` = 이 저장소를 클론한 **절대경로**(문서상 표기). `dir=`·`deliverable=`은 절대경로여야 하므로 호출할 때 실제 경로로 치환한다.
> **먼저 조사할 핵심 질문 수를 세고 모드를 정한다.**
> - **간이 모드 (핵심 질문 3개 미만 · 출처 5개 미만)** — SG 호출 없이 진행. 단 **종료 ledger 표 + 자가 점검은 그대로 채운다**(이게 최소 강제 레버).
> - **정식 모드 (그 이상 · 돈·건강·법적 자격이 걸린 결정)** — ① `SG form life-research publish dir=<폴더>` → ② 실물 열고 정직히 답 → ③ `SG judge life-research publish <id>=<값> … deliverable=<리포트.md 절대경로> dir=<폴더>` → **GATE PASS 아니면 '완료' 선언 금지.** 게이트 루브릭 직접 열람 금지.

**이 스킬은 조사를 *수행*한다.** 이미 만들어진 일정표·비교표를 *검증*만 할 거면 같은 폴더의 `fact-check`가 담당(둘은 한 쌍: 여기서 만들고, 거기서 감리).

검증 방법론 정본: 별도 컨설팅용 스킬의 참조 문서(비공개 — 이 저장소 미포함). **일상 주제엔 그중 출처 등급 · verbatim 확인·귀속 · 링크 생존·단위 점검만 적용**하고, 공시·사이징 파트는 건너뛴다.

## 단계

### 0. 스코프 확정 (조사 전 — 5분이 30분을 아낀다)
- **질문을 결정 가능한 형태로 좁힌다.** "제주 어디가 좋아?"가 아니라 "8월 셋째 주·2인·해변 접근·1박 20만원 이하 숙소 후보 5곳". **{포함}/{제외}를 한 줄로 못 박고** 후보마다 통과시킨다.
- **★ 무엇이 답을 결정하는지 먼저 정한다(결정 축).** 비교 대상이 여럿이면 *비교 축(체크리스트)을 먼저 만들고* 대상마다 **같은 칸을 같은 깊이로** 채운다 — 안 그러면 '자료 많은 A가 제일 좋다'는 거짓 결론이 난다. **'못 찾음'은 '없음'이 아니다**(미확인으로 남길 것).
- **기존 폴더 확인** — 같은 주제 폴더가 이미 있으면 거기 쓴다. 없고 규모가 있으면 `/life-map start`로 폴더·이름을 먼저 받는다(life 버전).

### 1. Fan-out — 후보 찾기
- 질문을 3~5개 검색 앵글로 분해(공식 정보 / 최신 변경사항 / 실사용 후기 / 반대 의견·함정 / 가격·대안).
- 병렬 WebSearch로 후보 출처를 발견한다. **★ 이 단계 결과는 발견 목록일 뿐 인용 출처가 아니다.**
- **★ 값싼 1차부터 직접 친다.** 공식 홈페이지·정부/기관 페이지·제조사 스펙은 보통 2~3회 fetch로 답이 난다. 광범위 검색은 그 뒤에.
- **★ 부재 단정은 쿼리 변형을 소진한 후에만.** '없다'고 하기 전에 동의어·다른 표기·영문명으로 재검색. 내 검색어로 안 나옴 ≠ 존재하지 않음. cf. [[exhaust-before-declaring-research-limits]]

### 2. 원문 fetch + 확인 (★핵심 게이트)
- 후보 URL을 **WebFetch 또는 curl로 직접 열어** 본문에서 수치·문구를 확인한다.
- **★ 검색요약·AI 답변을 그대로 인용 금지 (절대 게이트).** 원문 본문에서 verbatim 추출하고 grep으로 존재를 확인한다. **콘텐츠는 *링크 안 원문에서* 만든다 — 요약으로 초안 쓰고 나중에 출처 붙이는 *역순* 금지**(요약이 우연히 맞아도 불가).
- **★ WebFetch는 200을 줘도 *요약·번역*한다(silent paraphrase).** load-bearing 인용·정확한 수치는 **curl raw 본문 + grep**으로 확정(특히 비영어).
- **차단 대응 사다리** — 403/타임아웃이면 ① 브라우저 UA curl → ② Wayback(`http://archive.org/wayback/available?url=<URL>` → 스냅샷 URL에 `id_` 삽입해 raw 수신; **스냅샷 날짜 병기**) → ③ 같은 기관의 개방 채널(보도자료·공지). *로그인/구독 게이트*는 UA·Wayback 둘 다 무력 → 개방 동등 출처로 재귀속(게이트 URL을 인용으로 남기지 말 것). **자동 fetch 실패만으로 '유료' 단정 금지.**
- **PDF**: curl 다운로드 후 `pypdf`로 텍스트 추출 → grep. 이미지 스캔(0자 반환)이면 `PyMuPDF(fitz)`로 PNG 렌더 → Read로 읽기.
- **★ fetch 파일은 루트에 쓰지 않는다** — 그 과제 폴더의 `_raw_sources/`에만(스크래치는 `_tmp.<ext>` 재사용 후 삭제). cf. [[fetch-files-never-repo-root]]

### 3. 출처 등급 + 시효 (일상 리서치의 두 최대 오류원)
- **★ 등급(누가 말할 자격이 있나)** — **Tier 1 공식**(정부·기관·제조사·해당 업체 공식 페이지·약관 원문) > **Tier 2 언론·전문매체**(취재 기반) > **Tier 3 블로그·커뮤니티·AI 요약**(개인 경험·2차 전언). **Tier 3만으로 사실을 확정하지 말 것** — 방향·후보 발견에만 쓰고 Tier 1으로 확인한다. 운영시간·요금·자격요건 같은 *공식이 존재하는 사실*을 블로그로 인용하면 그 자체가 오류.
- **★ 시효(아직 유효한가) — 일상 정보의 최대 함정.** 요금·운영시간·휴무일·정책·자격요건·환율·재고는 **변한다**. 각 사실에 **확인 시점**을 달고, 출처 페이지의 *갱신일·기준일*을 함께 본다. 블로그 후기는 대개 과거 시점 — 작성일을 반드시 확인하고, 시효성 사실은 공식으로 재확인. **계절·요일 변동**(겨울 단축운영·월요 휴관·성수기 요금)을 놓치지 말 것.
- 여행·일정 조사면 이 단계 결과를 그대로 `fact-check`가 재감리할 수 있게 링크·수치를 정리해 둔다.

### 4. 적대적 재검증
- 핵심 결론(돈·건강·법적 자격이 걸린 것)은 **반대 근거를 일부러 찾아본다** — "이게 안 되는 경우", "숨은 비용", "제외 조건", "부작용". 반박이 서면 결론을 수정한다.
- **★ 조건·예외를 본문에서 확인.** 자격요건·보장범위·환불규정은 *요약 표가 아니라 약관·공고 본문*에 예외가 있다. 요약만 보고 '된다/안 된다' 확정 금지.
- **★ 분류·자격 판정은 '무엇이 가르는가'로.** 표면 라벨(이름·카테고리)이 아니라 *범주를 가르는 결정 속성*을 출처에서 확인한다. (예: '비자 면제'는 국적이 아니라 *체류 목적·기간·여권 종류*가 가른다.)

### 5. 합성 — 사실 / [내 판단] 분리
- **사실**(출처에서 나온 것)과 **[내 판단]**(내 해석·추천)을 명확히 분리한다.
- **★ 모든 [내 판단]은 근거 부착 — 없으면 삭제.** 이 조사의 출처·데이터에서 도출되거나, 비교 가능한 대안 + 출처를 동반해야 한다. 순수 LLM 일반지식 추천 금지. cf. [[analysis-must-be-reference-grounded]]
- **★ 결론은 *결정*한다.** 분석이 한 선택지를 지지하면 명확히 그것으로 결론(A vs B 택일). 모호한 상위 개념으로 판단을 비키면 조사한 의미가 없다 — 단서·대안은 결론 *뒤에* 짧게.
- **★ 답이 조건에 따라 갈리면 "상황에 따라 다르다"로 끝내지 말고, *무엇이 가르는지*를 밝힌 뒤 조건마다 각각 택일한다.** 조건만 늘어놓고 선택을 독자에게 넘기면 결론이 아니다. 갈리는 조건이 서넛을 넘으면 **"어떤 경우에 무엇"을 표로** 낸다 — 대상별 평가만 있고 상황 매핑이 없으면 조사 목적을 달성하지 못한 것. *실사례: 두 대안 비교에서 "설정에 따라 결론이 바뀐다"로 닫은 판 → "기본은 A, 이 네 경우에만 B"로 고쳐 씀.*
- **★ 결론 문단에 비교 수치를 늘어놓지 않는다.** 점수·가격·퍼센트는 비교표와 근거의 몫이다. 결론에 수치를 쌓으면 독자가 스스로 계산하게 되어 방금 내린 결정이 취소된다 — 결론은 **독자가 다음에 무엇을 하면 되는지**로 끝낸다.
- **★ 한 사례로 일반화 금지.** 후기 하나("여긴 별로였음")를 전체 판정으로 쓰지 말 것.
- **양면 판정** — 추천에는 장점과 함께 *제약·리스크·놓치는 것*을 한 문장으로 같이 적는다.
- **단위·통화** — 통화기호+숫자(₩·$·Rp), 큰 수는 자릿수 검증(원문 "420 billion rupiah" → Rp420B, ❌"420억"). 환율 적용 시 기준일 병기.
- **★ 반올림은 원값에서 한 번만** — 이미 반올림된 2차 값을 다시 반올림하면 경계값이 부풀려진다.

### 6. 산출물
- **리포트 `.md`** — 대상 폴더에 **신규 파일**(원문 덮어쓰기 금지·`vN_M` 버전). 골격:
  - 제목 + 메타라인(**조사일·조사 범위·핵심 질문**)
  - `## 결론` — 먼저. 무엇을 왜 추천하는지 + 제약 한 문장.
  - `## 비교` — 비교 축을 행으로, 대상을 열로. **각 칸 끝에 출처 라벨.** 남긴 축의 빈 칸은 '미확인'으로 명시(공란 금지).
    - **★ 축은 출처가 발표한 지표명이 아니라 *독자가 겪는 결과*로 잡는다.** 출처의 목차를 그대로 행으로 옮기면 표를 다 읽어도 무엇을 골라야 할지 안 나온다. 지표·수치는 그 축의 *근거로 칸 안에* 넣는다. *실사례: 행이 `종합 지수`·`pass@1`이던 표 → `끝까지 가는 힘`·`실패하는 방식`·`작업당 비용`으로 재편.*
    - **★ 한쪽에만 값이 있는 항목은 비교축이 아니다 — 축에서 내리고 `## 근거`로 옮긴다.** '미확인'으로 칸을 채워 축을 유지하면 비교가 성립하지 않는 표가 남는다('같은 깊이'는 칸을 메우라는 뜻이 아니라 *양쪽 다 값이 있는 축을 고르라*는 뜻).
  - `## 근거` — 항목별 사실 + 출처 링크 + **확인 시점**.
  - `## 미확인·한계` — 못 찾은 것, 시효가 짧은 것, Tier 3만 있는 것. **결론을 바꿀 수 있는 것만** 여기 두고 나머지는 부록으로.
  - `## 출처` — `[S1] 출처명(등급·갱신일) — URL` 형식. **1 라벨 = 1 URL.**
  - `## 부록` — **조사·검증 과정 기록**(종료 ledger, 이전 판 대비 정정, 남의 답변을 대조한 결과).
- **★ 조사 과정 서술은 본문에 넣지 않는다.** 무엇을 어떻게 확인했는지·이전 판의 오류를 어떻게 잡았는지는 **결론·비교보다 앞에 오면 안 되고** 문서 끝 `## 부록`으로 간다. 본문은 *조사 결과*만 담는다 — 리서치 자체에 대한 설명이 앞을 차지하면 독자는 정작 답을 못 찾는다.
- **본문 인용은 전부 클릭 가능한 링크**(맨 텍스트 `[S1]` 방치 금지).
- **종료 ledger 표**(간이 모드도 필수) — 핵심 사실별로 `사실 | 출처 | 등급 | 확인시점 | 판정(확인/미확인/시효주의)`.

## 자가 점검 (제시 전)
- [ ] **게이트** — 간이 모드면 ledger 표 + 이 점검으로 갈음 / 정식 모드면 `SG judge life-research publish …` → **GATE PASS**
- [ ] **스코프** — 일상·실무 주제인가(공시·시장규모·클라이언트 산출물이면 `work/consulting/`의 research-verified로)
- [ ] **조사 vs 검증** — 이미 있는 산출물 검증 요청이면 `fact-check`로 넘겼는가
- [ ] 모든 인용이 **원문 본문에 실제로 존재**(grep 확인). 검색요약·AI답변 그대로 인용 0 — 콘텐츠를 *링크 안 원문*에서 생성
- [ ] **출처 등급** — 시효성·공식이 존재하는 사실을 Tier 3(블로그·커뮤니티)로 확정 0
- [ ] **시효 확인** — 요금·운영시간·휴무·정책·자격요건에 **확인 시점** 부착, 출처의 갱신일 확인, 계절·요일 변동 반영
- [ ] **비교축이 독자의 결정 기준인가** — 출처 지표명을 그대로 행으로 옮기지 않았고, **한쪽만 값이 있는 항목은 축에서 내려** `## 근거`로 옮겼는가
- [ ] **비교는 같은 깊이** — 남긴 축은 대상마다 채움, 빈 칸은 '미확인' 명시('못 찾음 ≠ 없음')
- [ ] **조건·예외**를 요약이 아니라 약관·공고 본문에서 확인
- [ ] 사실 / **[내 판단]** 분리, 모든 [내 판단]에 근거 부착(무근거 추천 0)
- [ ] 결론이 **결정적**인가(모호한 회피 0), **양면 판정**(제약·리스크 동반), 한 사례 과잉일반화 0
- [ ] **조건이 갈리면 조건마다 택일**했는가('상황에 따라 다르다'로 끝낸 곳 0), 갈림이 서넛 넘으면 **"어떤 경우에 무엇" 표** 존재
- [ ] **결론 문단에 비교 수치 0** — 점수·가격·퍼센트는 비교/근거에만, 결론은 다음 행동으로 끝남
- [ ] **조사 과정 서술이 본문에 없음** — 검증 기록·이전 판 정정·ledger는 전부 문서 끝 `## 부록`
- [ ] 단위·통화·자릿수 검증, 환율 기준일 병기, **반올림은 원값에서 1회**
- [ ] 모든 링크 **접속 가능**(죽은 링크 0), 1 라벨 = 1 URL
- [ ] **종료 ledger 표** 작성 + `## 미확인·한계` 섹션 존재(빈 섹션이면 정말 없는지 재확인)
- [ ] fetch·임시 파일은 `_raw_sources/`에만, 루트 0
