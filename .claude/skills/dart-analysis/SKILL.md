# DART 재무분석 스킬 (단일 기업 딥다이브 + 경쟁사 비교)

DART Open API에서 **공시 원문 재무제표를 직접 가져와** 표준 재무비율·다년도 추이를 산출하고
컨설팅 관점으로 해석하는 스킬. 숫자는 추정하지 않고 **출처(접수번호)에서 직접** 가져오며,
산출물은 **채팅 요약 + Excel 데이터팩**. 분석 비율·관점은 `references/`의 선언적 정의로 분리해
**새 분석 방향을 코드 수정 없이 계속 추가**할 수 있도록 설계.

> **두 가지 모드**
> - **단일 기업 딥다이브**(§1–§11): 한 회사 × 정형 재무제표 API × 비율·추세 해석.
> - **경쟁사 비교**(§13): 동종 N사 × 5개년 × 비율/금액 교차 비교 — 순위·peer 통계 +
>   **산업(macro) vs 당사(개별) 요인 판별**. 단일 모듈을 회사별로 돌린 뒤 `compare.py`로 합침.
>
> 사업보고서 원문 정성 해석(경로 B: 판관비·세그먼트)은 단일 딥다이브의 심화. 챗(claude.ai)은
> 외부 네트워크 차단이라 **데이터 반입 모드**로 동작(§12) — 단일 기업 한정, 비교는 Code 권장.

## 0. 시작 규칙 — 언어 · 환경 · 입력 (스킬 발동 시 맨 먼저)

**① 언어 = 사용자 입력 언어 고정.** 한국어로 요청하면 **인사·진행멘트·질문·산출 전부 한국어로**(환경/UI 기본이 영어여도 영어로 시작하지 말 것). 티커·계정명·고유명사·인용은 원문 보존.

**② 환경(모드) 먼저 판별:**
- **Claude Code (네트워크 ○ · 컨텍스트 ~1M)** → DART API **자동 수집** + **경쟁사 비교**까지 풀 기능
- **claude.ai 챗 (네트워크 ✗ · 컨텍스트 ~200K)** → 자동 수집 불가 → **데이터 반입(붙여넣기)** + **단일 기업만**. 경쟁사 비교는 N개사 데이터로 **컨텍스트가 넘쳐 깨짐** → 챗에서 하지 말고 **Code로 안내**(§12·§13.5)

**③ 입력 게이팅 (챗):** 자동 수집이 안 되는 환경이면 **바로 생성·추정으로 넘어가지 말 것.** 먼저 **사업보고서 PDF 업로드**를 요청(가장 쉬움):
> "DART(dart.fss.or.kr)에서 **대상 기업 사업보고서**를 열고 **우측 상단 '다운로드' 버튼으로 PDF**를 받아 이 대화에 **업로드**해 주세요 (어느 회사·어느 연도인지만 함께 적어주시면 됩니다)"
업로드되면 Claude가 PDF에서 **재무제표(BS/IS/CF)·판매비와관리비 명세·부문 정보**를 읽어 분석(PDF가 크면 그 섹션 위주). PDF가 어려우면 표 **복사·붙여넣기**도 가능(보조).
업로드/붙여넣기 데이터 없이 숫자를 지어내지 않음(§4·§10).
> ★ **기업명만 묻지 말 것** — 챗에선 이름만으론 아무것도 못 함(네트워크 차단). *"우선 기업명을 알려달라"는 안내는 헛된 기대만 유발.* 기업명은 **데이터에 딸린 라벨**일 뿐 → 항상 **PDF 업로드(또는 붙여넣기)**를 요청.

## 1. 전제조건

- **OpenDART 인증키** — `opendart.fss.or.kr`에서 무료 발급(40자리). **Code 자동 수집에만 필요**(챗 반입 모드는 키 불필요). 미보유 시 발급 절차부터 안내.
- **키 로딩** — `.env`의 `DART_API_KEY`(또는 `--key`로 대화 input). **키는 코드·git·로그에 직접 넣지 않음.**
- **실행 환경(§0②)** — **Claude Code**: 네트워크 ○ → 자동 수집 + 경쟁사 비교 풀 기능. **claude.ai 챗**: 네트워크 ✗ → **데이터 반입·단일 기업**(자동 수집·비교 불가, §12·§13.5).
- **Python 의존성** — 네트워크는 표준 `urllib`만. 분석 `pyyaml`(미설치 시 `references/*.json` 자동 fallback), Excel `xlsxwriter`(챗에도 사전설치). `pip install pyyaml xlsxwriter`.

## 2. 입력 명세

### 2.1 필수
- **기업 식별자** — 다음 중 하나(§4에서 타입 분기):
  - 고유번호(corp_code, 8자리) / 종목코드(stock_code, 6자리) / **회사명**
- 미제공 시 사용자에게 질문. 추측 금지.

### 2.2 선택(디폴트 제공)
- **분석 기간** — 디폴트 **최근 3개 사업연도**(추세 최소 단위).
- **재무제표 구분** — 디폴트 **연결(CFS)**. 지주사·단독 법인 등 연결이 없으면 별도(OFS)로 폴백,
  둘 다 있으면 연결 기본 + 별도 병기 가능.
- **분석 관점(렌즈)** — 디폴트 기본 비율 셋(§6). `references/lenses/`에 정의된 관점 지정 가능.

## 3. 워크플로우

### Step 1. 환경 판별 + 기업 식별 (★ 1순위 가드레일 — §0·§4)
- **환경 먼저(§0②)** — Code면 자동 수집 / 챗이면 **사업보고서 붙여넣기 안내·단일 기업 한정**(비교는 Code로 안내). 붙여넣은 데이터 없이 진행 금지.
- **식별** — 잘못 식별하면 이후 **모든 숫자가 엉뚱한 회사 데이터**가 됨 → **추론-후-확인(§4)**. 확정 전 반드시 확인.

### Step 2. 데이터 수집 (§5)
정형 재무제표 API로 3개년 BS/IS/CF 계정 + 접수번호(출처) 확보. 단위·연결/별도 기록.

### Step 3. 비율·추이 계산 (§6)
`references/ratios.yaml`을 읽어 비율 계산, 연도별 추이(YoY)·방향 산출.

### Step 4. 분석 구조 초안 → 승인 (산출 전 필수)
아래 구조의 **초안을 먼저 채팅에 제시**하고 승인받은 뒤 산출:

```markdown
# 초안: <회사명> 재무분석 (연결 / YYYY–YYYY)
- 식별 확정: <회사명> (종목 ______ / 고유번호 ________) · 출처 사업보고서 N건
## 핵심 요약(예정) — 3개 내외
## 범주별 — 수익성 / 성장성 / 안정성 / 현금흐름
## ⚠️ 확인 필요 — 단위·연결별도·계정매칭 등
```
**묻기 (이 순서로 — ★ 정확성 먼저)**:
1. **정확성 확인** — 식별 확정 / 단위(원·백만원) / 연결·별도 / 계정 매칭(미매칭·오인식 의심)을 **먼저 확인**해 교정값 확보
2. **구조 승인** — "이 구조로 분석/산출할까요? 비율·관점 추가·삭제 알려주세요"

### Step 5. 산출 (§7)
- **채팅 요약** — 명사형 컨설팅체, 수치 + 해석(차트 이미지 없음, 파일 첨부만 안내)
- **Excel** — `scripts/build_excel.py`로 `Raw`/`Ratios`/`Summary` 3시트 + 네이티브 차트

## 4. 기업 식별 규칙 (★ 최우선)

입력을 **타입으로 분기**:

| 입력 형태 | 처리 |
|----------|------|
| 숫자 8자리 | 고유번호(corp_code)로 직행 → 확정 |
| 숫자 6자리 | 종목코드(stock_code)로 `corpCode.xml` 매칭 → 상장사 1건 확정 |
| 문자(회사명) | `corpCode.xml`에서 검색 → 후보 1건이면 확정, **2건↑이면 선택받음** |

- **기업 매핑 소스** — `corpCode.xml`(전체 기업 [고유번호·정식명칭·종목코드·최종변경일]). 1회
  내려받아 **로컬 캐시** 후 재사용(매 호출 다운로드 금지).
- **동명 처리 — 추론 먼저, 근거와 함께 확인 (★ 그냥 "어느 회사?"라고 묻지 말 것)** — 후보가 여럿이면
  각 후보에 업종·대표자(기업개황 `company.json` 1회씩) 보강 후, **가장 그럴듯한 후보를 근거와 함께 추천**하고
  확인받음. 단서: 상장 여부·이름 일치도·업종 적합성·요청 맥락:
  ```
  "○○전자"로 검색 → 3건. 추정: **1번 ○○전자(주)** — 상장(종목 0000XX)·이름 정확일치·업종 부합:
    1. ○○전자(주)    | 종목 0000XX(상장) | 고유 00XXXXXX | 업종 반도체 | 대표 …   ← 추천
    2. ○○전자홀딩스  | 비상장            | 고유 00XXXXXX | 업종 지주   | 대표 …
  → "1번 ○○전자(주)로 진행할까요? 다른 회사면 번호로 알려주세요"
  ```
  추천 **근거를 명시**하되 **확정은 사용자 확인 후**(추측 단독 진행 금지).
- **확정 확인(1줄)** — *"○○전자(종목 0000XX / 고유번호 00XXXXXX) 기준 2022–2024 분석 진행"*.
- **fs(연결/별도)·보고서종류·비교군도 같은 식** — 모호하면 합리적 기본값을 *근거와 함께 추천* 후 확인(예: "연결 기준 권장 — 자회사 포함 그룹 전체 보임").

## 5. 데이터 수집 (정형 재무제표 — 경로 A)

- **API** — 단일회사 전체 재무제표(`fnlttSinglAcntAll`). 전 계정과목을 받아 비율을 자유롭게 산출.
- **파라미터** — `corp_code`, `bsns_year`(연도별), `reprt_code`(사업보고서 `11011`),
  `fs_div`(연결 `CFS` / 별도 `OFS`).
- **기간** — 3개 사업연도 각각 조회.
- **반드시 기록** — **단위**(원/천원/백만원), **연결/별도(CFS/OFS)**, **접수번호(rcept_no, 출처)**,
  당기/전기 구분.
- **모듈 경계** — 네트워크 호출은 `scripts/collect.py`·`parse_notes.py`에 격리. 챗 반입 모드는 이 둘을 `from_input`/`notes_from_input`으로 교체.

> 주석 세부계정(예: 지급수수료)·"사업의 내용" 정성 설명은 정형 API에 없음 → **경로 B(원문 파싱, `parse_notes.py`·§13.6)** 로 확장(구현됨).

## 6. 분석 — 비율 레지스트리 + 추이

- **비율 정의는 `references/ratios.yaml`에서 읽음**(코드에 하드코딩 금지). 항목 스키마:
  ```yaml
  - id: operating_margin
    category: 수익성          # 수익성 | 성장성 | 안정성 | 현금흐름
    label: 영업이익률
    formula: 영업이익 / 매출액
    accounts: [영업이익, 매출액]   # account-aliases.yaml로 표기차 흡수
    unit: "%"
    interpret: 본업 수익성. 하락 추세 시 원가율·판가 점검.
  ```
- **기본 비율 셋:**
  - 수익성 — 영업이익률 · 순이익률 · ROE · ROA
  - 성장성 — 매출액증가율(YoY) · 영업이익증가율(YoY)
  - 안정성 — 부채비율 · 유동비율 · 이자보상배율
  - 현금흐름 — 영업활동현금흐름 1줄(순이익 대비 → 이익의 질)
- **추이 중심 해석** — 단일 기업 모드는 **자기 시계열 추이(3개년)**가 기준.
  (peer·업종 평균 비교는 **비교 모드(§13)**에서. 단일 모드에선 "업종 평균 대비" 단정 금지.)
- **해석 원칙** — 수치 → 방향(▲▼) → **데이터로 뒷받침되는** 원인(계정 분해)까지. 추측 보완 금지.

## 7. 산출물

### 7.1 채팅 요약 (★ 컨설팅 메시지 포맷 — 단일·비교 공통, §7.3)

**답부터, 헤드 메시지 → `[브래킷]` 범주 메시지(볼드) → `[근거]/[수치]` 백업 sub-bullet.** 핵심(so-what)과 디테일이 시각적으로 갈리게. teatime/interview-notes와 동일 하우스 스타일(§7.3).

```
📊 **<회사명> 재무분석** (연결 / YYYY–YYYY) · 종목 ______ · 출처 사업보고서(접수번호 …)

**핵심 진단**   ← answer-first 거버닝(1~2 불렛, so-what)
- **<한 문장 답: 재무상태의 본질 + 왜>**
  예) **매출 +31%로 사상 최대지만 영업이익은 정점 대비 −24% — "외형↑·수익성↓" 고착**
- **<2번째: 구조적 주의/맥락>**  예) 연결 지표는 금융자회사가 좌우 → 제조 단독(별도)으로 봐야

**[수익성] <범주 핵심 판단 — 볼드>**
 - [추세] 영업이익률 6.9→**9.3**(23)→8.1→**6.2%**(25) ▼
 - [드라이버] <why — drivers 있으면 비용/세그먼트로> 예) 원가율 **79.5→81.6%** + 판관비 +6%
 - [수치] 영업이익 15.1조→**11.5조(−24%)**, 순이익률 5.6%로 회귀
**[성장성] <핵심 판단>**
 - [역전] 매출 **+31%** ▲ vs 영업이익증가율 25년 **−19%** ▼ → "매출↑ 이익↓"
**[안정성] <핵심 판단>**
 - [수치] 부채비율 …% / 유동비율 …% / 이자보상 …배 → 단기 지급능력 이슈 없음
 - **[주의] <연결 왜곡 등 구조적 caveat>** 예) 자산 +45%는 금융 채권 — 제조 단독 부채비율 41%와 괴리
**[현금흐름] <핵심 판단>**
 - **[경보] 영업CF +10.6조→−6.0조 ▼▼, CF/순이익 133%→−58% 전환**
 - [원인] <운전자본·구조적 요인 — 본업 현금창출력과 구별>

⚠️ **해석 유의** — 단위(__)·연결/별도·계정매칭·미산출 사유
📎 출처: 접수번호 …(사업보고서 p.…)
```
- **answer-first**: 첫 블록 = `핵심 진단`(거버닝 1~2 불렛). 단순 비율 나열로 시작 금지.
- **범주 = 메시지**: `[수익성]` 옆에 *판단(주장)*을 달고 볼드. 주제어만 X.
- **백업 sub-bullet**: `[추세]/[드라이버]/[수치]/[주의]/[경보]/[역전]` 등 **꺽쇠 라벨**로 핵심 vs 디테일 분리.
- **볼드는 결정적 수치·메시지에만**(영익률·격차·CF 전환 등). 남발 금지.
- **why 연결**: `drivers`(판관비·부문) 있으면 "영업이익 변화의 *왜*"를 정성+정량으로(§11).
- 명사형·**끝 마침표 금지**·**한국어 고정**(§0①)·**References**(접수번호·페이지). 수치·기업명 원문 보존.

### 7.2 Excel 데이터팩 (`scripts/build_excel.py`)
- `Raw` — 원계정·연도별 값 + 단위 + 접수번호(출처)
- `Ratios` — 비율 시계열(범주별)
- `Summary` — 핵심 지표 + **네이티브 차트**(xlsxwriter): ①매출·이익 추이 ②수익성 비율 추이 ③안정성
- **파일명** — `<회사명>_재무분석_YYYY-YYYY.xlsx`

### 7.3 컨설팅 메시지 포맷 (★ 단일 요약·비교 요약 공통)

단일(§7.1)·비교(§13.3) 채팅 요약 **모두 동일 골격** — teatime/interview-notes 하우스 스타일과 일관:
1. **헤드 메시지(answer-first)** — 맨 위 1~2 불렛으로 "그래서 결론이 무엇"(so-what). 분석과정·정의로 시작 금지
2. **`[브래킷]` 섹션/주장 + 볼드** — 범주·주장 옆에 *판단*을 달고 핵심만 볼드(주제어만 ✗)
3. **`[근거]/[수치]/[추세]/[드라이버]/[주의]/[경보]` 백업 sub-bullet** — 핵심 메시지 ↔ 디테일 백업을 시각적으로 분리
4. **볼드는 결정적 수치·메시지에만**, **명사형**, **끝 마침표 금지**, **한국어 고정**, **References**(접수번호·페이지)
- 데이터 나열·주제어 헤더(✗) → **메시지 피라미드**(✓)

## 10. 절대 하지 말 것 (가드레일)

- **식별 추측 금지** — 동명·모호 시 임의 선택하지 않고 사용자 확인(§4).
- **숫자 환각 금지** — 공시 원문에 없는 값을 추정·생성하지 않음.
- **단위·연결/별도 누락 금지** — 원/천원/백만원, CFS/OFS를 항상 명시.
- **출처 누락 금지** — 접수번호(rcept_no)를 병기해 검증 가능하게.
- **합쇼체·해요체 금지** — 채팅 요약은 명사형 종결.
- **키 노출 금지** — `DART_API_KEY`를 코드·git·로그에 남기지 않음.
- **환경·입력 게이팅(§0)** — 챗(네트워크 ✗)이면 **사업보고서 붙여넣기 안내 후 진행**, 입력 없이 생성·추정 금지. **챗에서 기업명만 받고 분석되는 것처럼 안내 금지**(이름만으론 불가 → 붙여넣기 데이터 요청). **챗에서 경쟁사 비교 금지**(컨텍스트 초과) → Code 안내.
- **언어 = 한국어 고정** — 인사·질문·진행멘트·산출 전부 한국어(환경/UI가 영어여도). 영어로 시작/응답하지 않음. 티커·고유명사·인용은 원문.
- **끝 마침표 금지(컨설팅 펌 한국 오피스)** — 불렛·문단 맨 끝 문장에 `.` 안 찍음(중간 문장·말줄임 `…`은 허용).
- **금융업·지주사 안내 후 중단** — 핵심계정(매출액·영업이익) 부재 감지 시 "은행·증권·보험 등 금융업/지주사·특수구조 → 표준 재무분석 대상 아님(FI/INS PA 전문가 통해 별도 고도화)" 고지. 억지 분석 금지.
- **보고서 종류** — 연간(사업보고서) 기본. 반기·분기는 요청 시 `--reprt`(11012/11013/11014)로 제공.
- **적자·음수 처리** — 전기 적자(≤0) 시 증가율 'N/A(전기 적자)', 영업적자 시 이자보상배율 무의미 표기. 음수 비율을 추세로 단정 금지.

## 11. scripts 인터페이스 (단일 기업 — 구현 완료)

단일 기업 딥다이브 4단계. 네트워크는 `collect`·`parse_notes`에만 의존, 3·4단계는 오프라인.
경쟁사 비교(다중 기업) 원샷 CLI는 §13.1(`peer.py`).

```bash
# 1) 정형 재무제표 수집 (네트워크) — 식별(회사명/종목6자리/고유8자리) + 다년도 BS·IS·CF
python3 scripts/collect.py --ident "삼성전자" --years 3 --fs CFS --out /tmp/raw.json
#   옵션: --year 2024(종료연도, 기본=작년) · --years 5(수집 연수, 비교는 5 권장)
#         --reprt 11011|11012|11013|11014(연간/반기/1Q/3Q) · --pick N(동명 후보 선택)
#         --key <DART_KEY>(.env 대신 인증키 직접 전달 — 챗 input용)
# 2) 경로 B: 원문 드라이버(판관비 명세·부문 P&L) — rcept는 raw.json의 rcept_no 사용 (네트워크)
python3 scripts/parse_notes.py --rcept <rcept_no> --what all --out /tmp/notes.json
#   --what sga|revenue|all(기본 all) · --key <DART_KEY>
# 3) 비율 계산 + 경로 B 드라이버 병합 (네트워크 불필요)
python3 scripts/analyze.py --raw /tmp/raw.json --notes /tmp/notes.json --out /tmp/ratios.json
#   --notes 생략 가능(표준비율만) · --ratios/--aliases로 레지스트리 경로 직접 지정 가능
#   (pyyaml 미설치 시 references/*.json 자동 fallback)
# 4) Excel 산출 (네트워크 불필요) — Summary/Ratios/Raw 3시트 + 네이티브 차트 3종
python3 scripts/build_excel.py --ratios /tmp/ratios.json --raw /tmp/raw.json --out "<회사명>_재무분석_YYYY-YYYY.xlsx"
```
- **챗(claude.ai) 반입 모드(§12)**: 네트워크 1·2단계를 `from_input.py`(재무 CSV→raw.json)·`notes_from_input.py`(비용/부문 CSV→notes.json)로 교체, 3·4단계는 그대로 재사용.
- `analyze` 결과의 `drivers`(판관비 구조·부문 P&L)는 **채팅 요약의 "영업이익 why" 해석에 반영** — 비율 수치뿐 아니라 *매출/비용 드라이버*까지 서술.
- 단위 주의: 정형=원, 판관비=백만원, 부문=억원 → 해석·표기 시 통일.

## 12. claude.ai 챗에서 실행 — 데이터 반입 모드

⚠️ **확인된 제약(2026-06 실측)**: 컨설팅 펌 claude.ai는 외부 네트워크가 전면 차단(`host_not_allowed`)이라
**챗에서 DART 자동 수집은 불가**. 자동 수집이 필요하면 **Claude Code(로컬)** 로 실행.
챗에서는 **데이터를 반입**해 분석·산출만 수행(pandas·xlsxwriter 사전설치라 가능).

> ★ **챗 시작 시**(§0③): 바로 생성으로 직행하지 말고 먼저 **"DART 사업보고서 PDF를 다운로드(뷰어 우측 상단 버튼)해 업로드해 달라"**고 안내·대기(붙여넣기는 보조).
> ★ **챗 = 단일 기업만.** 경쟁사 비교는 N개사 데이터로 **컨텍스트(~200K)가 넘쳐 깨짐**(실측: 첫 경쟁사 분석 중 중단) → **Code 사용 권장**(§13.5).

워크플로우:
1. **사업보고서 PDF 업로드(권장)** — DART(dart.fss.or.kr) → 대상 기업 사업보고서 → **우측 상단 '다운로드'로 PDF** 받아 대화에 업로드. Claude가 PDF에서 **재무제표·판관비 명세·부문**을 직접 읽음(PDF가 크면 해당 섹션 위주).
2. **입력 정리** — Claude가 PDF(또는 붙여넣은 표)에서 수치를 뽑아 `references/chat-input-template.csv` 양식(표준계정 × 연도, 원 단위)으로 정리. PDF가 어려우면 표 복사·붙여넣기도 가능(보조).
3. **raw 변환** — `python3 scripts/from_input.py --csv input.csv --name "회사명" --out raw.json`
   (네트워크 불필요 — `collect.py`의 챗 대체).
4. **분석·산출** — `analyze.py --raw raw.json --out ratios.json`(json fallback) → `build_excel.py`. 기존과 동일.
5. **드라이버(선택)** — 판관비 명세·부문 P&L은 사업보고서 해당 표를 붙여넣으면
   Claude가 `drivers` 형식으로 정리해 "영업이익 why" 해석에 반영.

- **비율 정의**: pyyaml 미설치 → 동봉 `references/ratios.json`·`account-aliases.json` 자동 사용.
- **키 불필요**(자동 수집 안 하므로). **단위**: 원 권장. **연도 헤더**: 오래된→최신 순.
- 네트워크가 열린 환경이면 `collect.py`(+`--key`)로 자동 수집도 그대로 가능.

## 13. 경쟁사 비교 모드 (다중 기업)

동종 N사를 **같은 비율·같은 기간(기본 5개년)** 으로 교차 비교. 단일 기업 모듈
(`collect`→`analyze`)을 **회사별로 그대로 돌린 뒤** `compare.py`로 합치는 구조라
1단계 자산(비율 레지스트리·별칭·가드레일)을 100% 재사용.

> **언제**: "경쟁사 비교", "동종업계 N사", "○○ vs △△", "편의점 3사 5개년" 등.
> 1단계가 *자기 시계열*만 봤다면, 비교 모드는 **peer 통계(중앙값·최소·최대)·순위**를 비로소 산출.

### 13.1 비교 워크플로우

**식별 먼저(★ §4 동일).** N개 모두 확정 후 진행. 동명이면 `이름:순번`으로 선택.

원샷(권장, Claude Code):
```bash
python3 scripts/peer.py \
  --idents 코리아세븐 비지에프리테일 지에스리테일 \
  --years 5 --segment-focus 편의점 \
  --out-dir /tmp/cvs --xlsx "편의점3사_비교_2021-2025.xlsx"
# 동명 예: --idents "현대:2" 신세계 …  /  키: --key <DART_KEY>  /  비용·부문 생략: --no-notes
```
peer.py = 회사별 `collect(--years N)`+**`parse_notes`(경로 B 드라이버)**+`analyze` → `compare` → `build_compare_excel` 일괄.
기본으로 판관비 명세·부문 P&L까지 수집해 **비용구조·세그먼트 비교(§13.6)** 도 산출(`--no-notes`로 끄면 표준비율만, 빠름).
중간 산출(`raw_*.json`/`ratios_*.json`/`comparison.json`)도 out-dir에 남겨 검증·재가공 가능.

수동(모듈 단위 — 챗·부분재실행용):
```bash
# 회사별 (네트워크는 collect만)
python3 scripts/collect.py --ident 비지에프리테일 --years 5 --out /tmp/cu_raw.json
python3 scripts/analyze.py --raw /tmp/cu_raw.json --out /tmp/cu_ratios.json   # 3사 반복
# 합치기 + 산출
python3 scripts/compare.py --ratios /tmp/*_ratios.json --out /tmp/comparison.json
python3 scripts/build_compare_excel.py --comparison /tmp/comparison.json --out "비교.xlsx"
```

### 13.2 분석 관점 — 비교 모드 고유

- **순위(leader/laggard)** — `higher_is_better`로 방향 인식(부채비율은 낮을수록 1위).
- **peer 통계** — 연도별 중앙값·평균·최소·최대. "업종 평균 대비" 단정이 *비교 모드에선 허용*.
- **★ 산업(macro) vs 당사(개별) 판별** — 최신연도 YoY 방향을 회사별로 비교:
  - 전사 동조(▲ or ▼) → **산업·매크로 요인**(수요·원가·규제 등 공통 충격).
  - 한 회사만 역행 → **당사 고유 이슈**(`comove_latest.divergent`로 어느 회사인지 표면화).
  - → 비교 분석의 핵심 컨설팅 메시지. "○○만 마진 악화 = 산업이 아니라 당사 문제".
- **규모 차이 보정** — 규모가 다르면 절대값 대신 **비율·성장률·점유율**로 비교
  (`amounts`의 매출 `share`로 시장 포지션, 비율로 효율 비교).

### 13.3 비교 산출물 — 컨설팅 메시지 피라미드 (★ answer-first)

> **절대 원칙**: 채팅 요약은 **데이터 나열이 아니라 "답"부터.** 컨설팅 펌 피라미드 구조 —
> **한 줄 핵심 답(거버닝 메시지)** → 이를 떠받치는 **sub-message 3개(MECE, 각각 *완결된 주장*)**
> → 각 sub 아래 **근거 숫자 + 논리(why)**. 모든 주장은 수치로 뒷받침하고 "그래서?(so-what)"가 분명해야.
> **마이크로 포맷(`[브래킷]`·볼드·`[근거]/[why]` 백업 sub-bullet)은 단일 요약(§7.1)과 동일** — 공통 하우스 스타일 §7.3.

`comparison.json`의 **`synthesis`**(거버닝 후보 = `leader_overall`·`outlier`·`profit_gap`·`cost_drivers`·`signals`)를
출발점으로, **답 → 근거 → why** 순으로 작성:

```
📊 <업종> N사 재무비교 — <A> vs <B> vs <C> (연결/별도 · YYYY–YYYY)
출처: 각 사 사업보고서(접수번호 …)

【핵심 답】 **<한 문장 거버닝 — 누가/무엇이 우위이고 그 본질>**
  예) **<A>가 N사 중 수익성·성장 모두 선두 — 시장요인 아닌 비용구조 효율, 구조적·지속가능**

**① <sub-message 1 — 완결 주장(볼드, 주제어 ✗)>**
 - [근거] <수치·격차%p·추세·peer중앙값 — 핵심 볼드>
 - [why] <드라이버·논리 — cost_structure/segments로>
**② <sub-message 2>**
 - [근거] …   - [why] …
**③ <sub-message 3 — 산업 vs 당사 / 핵심 리스크>**
 - [근거] …   - [signal] 산업요인(전사 동반) vs 당사이슈(특정사 역행)

⚠️ **비교가능성**: 연결범위·사업믹스(지주·복합)·단위·연결/별도
📎 첨부: <파일명>.xlsx (요약/데이터/비용구조/세그먼트)
```

**작성 규칙(컨설팅 품질 — 이게 핵심):**
- **answer-first**: 첫 줄은 반드시 *결론*. 정의·분석과정·"먼저 ~을 보면" 류로 시작 금지.
- **sub-message = 주장**: "수익성" 같은 *주제어* 말고 "A의 영업이익률 우위는 비용구조에서 기인" 같은 *문장 주장*.
- **숫자로 백업**: 각 주장에 구체 수치 최소 1개(값·격차%p·추세·peer중앙값). 막연한 형용사("우수하다") 금지.
- **why까지 연결**: 수익성 격차면 *왜*를 `cost_structure`·`segments`로 → "영업이익률 A>C(3.3 vs −1.4%)는
  A 인건비 3.1% vs C 4.4%·지급수수료 효율 등 **비용구조 우위**에서". `synthesis.cost_drivers`가 이 연결을 제공.
- **산업 vs 당사 명시**: `signals`로 "전사 동반(산업요인)" vs "특정사 역행(당사이슈)" 구분 — 비교의 핵심 컨설팅 메시지.
- **MECE·중요도순 3개 내외**: 모든 비율 나열 금지. 겹치지 않게, 임팩트 큰 것만.
- 명사형 종결, 수치·기업명 원문 보존, 차트는 Excel만(첨부 안내).

**예시(편의점 3사 — 톤·구조 참고):**
```
【핵심 답】 **CU(BGF)가 편의점 3사 수익성 선두 — 격차의 본질은 비용구조 효율, 산업요인 아닌 구조적 우위**
**① CU 영업이익률 3.3%로 선두 — GS 2.6%·세븐 −1.4% 앞섬**
 - [근거] 5년 내내 1위(peer 중앙값 2.6%), 격차 GS **0.7%p**·세븐 **4.7%p**
 - [why] **인건비 3.1% vs GS 5.4%**, 지급수수료 5.5% vs 8.5% — 판관비 전반이 가벼움
**② 세븐 부진은 산업 아닌 당사 이슈 — 3사 중 유일 매출 역성장·영업적자**
 - [근거] CU·GS 매출 ▲ / 세븐만 ▼, 영익률도 세븐만 적자
 - [signal] comove=개별 분화(divergent: 세븐) → 당사요인
**③ '진짜 편의점'만 보면 격차 더 분명 — 부문 편의점 영익률 CU 2.5% vs GS 2.1%**
 - [근거] segment-focus 편의점(GS 연결엔 슈퍼·홈쇼핑 혼입) → 사업믹스 보정 후에도 CU 우위
⚠️ 비교가능성: 세븐=별도·비상장 커버리지 짧음, GS=연결에 슈퍼/홈쇼핑 포함
```

Excel(`build_compare_excel.py`): **요약**(최신연도 스냅샷=회사×지표 + 선두 + 산업/당사 신호) ·
**데이터**(지표·금액별 회사×연도 표 — 차트가 셀 참조) + 비교차트(매출·영업이익·영업이익률·
매출증가율·부채비율·ROE 추이 + 매출 점유율 stacked).

### 13.4 비교 모드 가드레일 (§10 + 추가)

- **비교가능성 점검 필수** — `compare.py`가 자동 표면화: 연결/별도 혼재, 연도범위 불일치,
  금융업·핵심계정 부재. 채팅 요약 ⚠️에 반드시 명시.
- **연결범위·사업구성 차이 고지** — 같은 업종이라도 연결 대상이 다르면(지주형·복합사업·
  합병 이력) 매출·이익 절대비교가 왜곡. 예: 한 회사가 비교 사업 외 부문을 연결에 포함하면
  "동일 잣대 아님" 명시 후 비율 위주 해석. **추측으로 사업부 분해 금지**(원문 세그먼트는 경로 B).
- **산업 vs 당사 단정 주의** — `comove`는 *방향*만 본 신호. 동조라도 강도 차이는 별도 서술,
  분화라도 일회성(소송·손상 등) 가능성 → 원문 확인 여지 표기. 데이터로 안 되는 인과 추정 금지.
- **N=2 이상** — 회사 1곳이면 비교 아님(단일 딥다이브로 회귀).

### 13.5 챗(claude.ai)에서 비교 — ★ 비권장(Code 사용 권장)

경쟁사 비교는 N개사 사업보고서를 한 세션에 다 넣어야 해 **챗 컨텍스트(~200K)가 넘쳐 중간에 깨짐**
(실측: 타겟사 분석 7분 + 첫 경쟁사 진행 중 컨텍스트 초과로 중단). **비교는 Claude Code(컨텍스트 ~1M·API 토큰 효율) 사용을 권장.**
챗에서 비교 요청을 받으면 정중히 안내: *"경쟁사 비교는 컨텍스트 한계로 Claude Code에서 돌리는 걸 권장합니다."*

정 챗에서 해야 하면(권장하지 않음): 회사당 **전체 사업보고서가 아니라 요약 수치(표준계정·핵심 비용항목)만** 반입해
부담을 줄이고 회사 수를 최소화. `compare.py`·`build_compare_excel.py`는 순수 모듈이라 동작은 함:
```bash
python3 scripts/from_input.py --csv cu.csv --name "BGF리테일" --out cu_raw.json
python3 scripts/analyze.py   --raw cu_raw.json --out cu_ratios.json   # 각 사 반복(요약 수치만)
python3 scripts/compare.py --ratios *_ratios.json --out comparison.json
python3 scripts/build_compare_excel.py --comparison comparison.json --out "비교.xlsx"
```
- 연결/별도·단위·연도 헤더를 사 간 통일(혼재 시 compare가 경고).

### 13.6 비용구조·세그먼트 deep-dive (경로 B 비교)

표준비율이 "누가 잘하나"라면, 경로 B는 **"왜"** — 사업보고서 원문의 **판관비 명세**와 **부문 P&L**을 회사 간 비교.
`peer.py` 기본 동작(`--no-notes`로 끔). 산출은 `comparison.json`의 `cost_structure`·`segments` + Excel **비용구조/세그먼트 시트**.

- **① 비용구조** — 판관비 항목을 `cost-aliases`로 표준범주(인건비·지급수수료·임차료·감가상각비·광고판촉…)로 묶어
  **매출 대비 비중(%)을 다년 추세**로 비교. 한 범주에 여러 항목이 걸리면 합산(예: 급여+퇴직급여+복리후생→인건비;
  **IFRS16 사용권자산상각비→임차료**). 미분류는 '기타'+표면화.
  → "GS 인건비 5.4% vs CU 3.1%, 지급수수료도 GS가 무거움" 식 효율 비교.
- **② 세그먼트** — 부문 매출/영업이익/영업이익률을 `segment-aliases`로 canonical 매칭해 비교.
  `--segment-focus 편의점`이면 **해당 부문만 격리** → **연결 사업믹스(GS리테일=편의점+슈퍼+홈쇼핑) 왜곡 제거**해
  "진짜 편의점만" 영업이익률 비교(영익률은 단위 무관 = 핵심 비교지표). 매출은 회사별 단위를 **억원으로 통일**.

챗(claude.ai): 자동 수집 불가 → `notes_from_input.py`로 반입.
```bash
# 회사별: DART 사업보고서의 '판매비와관리비의 내역'·부문표를 붙여넣기 → Claude가 아래 양식 CSV로 정리
python3 scripts/notes_from_input.py --cost cu_cost.csv --segments cu_seg.csv --out cu_notes.json
python3 scripts/analyze.py --raw cu_raw.json --notes cu_notes.json --out cu_ratios.json   # 3사 반복
python3 scripts/compare.py --ratios *_ratios.json --segment-focus 편의점 --out comparison.json
python3 scripts/build_compare_excel.py --comparison comparison.json --out "비교.xlsx"
```
- 양식: `references/cost-input-template.csv`(항목×연도, 백만원), `segment-input-template.csv`(부문×metric[sales/op]×연도, 억원).

**가드레일/한계(경로 B 고유):**
- **환각 차단** — SG&A 합계가 매출의 60% 초과면 표 오인식/단위 오류로 보고 **해당 사 비용비교 자동 제외**(경고). 비상장·비표준 보고서에서 발생.
- **단위 가정** — 판관비=백만원, 부문=억원 가정. 회사별 상이 시 비중 왜곡 가능(경고 표면화). 영업이익률은 단위 무관이라 항상 유효.
- **best-effort 추출** — 원문 표 구조는 회사·연도마다 편차. 표 미발견 시 해당 드라이버는 비우고 진행(억지 추출 금지). 별칭(`cost-aliases`/`segment-aliases`)은 seed라 산업별 보강 필요.
- **부문 정의 차이** — 같은 canonical이라도 회사별 부문 범위가 다를 수 있음(비교 시 caveat 명시).
