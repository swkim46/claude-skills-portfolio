## 단계

### 0. 사전 점검 — 기존 리서치 이력 + 지식지도 (★ 시작 전 필수)
새 리서치 시작 전 **`work/consulting/_지식지도_KNOWLEDGE_MAP.md`를 먼저 훑어** 같은(인접) 주제 리서치 이력을 확인하고, 있으면 그 폴더를 활용한다 — **중복 방지·리드 확보용이지 그 문서를 출처로 인용하기 위함이 아니다.**

**★ 산출물의 '집'(폴더·이름)은 리서치 착수 *전*에 지정한다 — 인접 폴더 발견 = '거기 넣기'가 아니다.** 인접 폴더가 있어도 그건 *출처·리드·`_raw_sources` 재사용*에만 쓰고, **새 과제(주제가 그 폴더와 다르면)는 착수 전 `/knowledge-map start`로 전용 폴더·이름을 먼저 지정**한다 — 즉흥으로 기존 폴더에 투입하면 산출물이 *엉뚱한 워크스트림*(예: 시장규모 전용 폴더) 아래 묻혀 지도·레터 배정이 어긋난다. **리트머스: *이 산출물이 어느 폴더에·무슨 파일명으로 앉을지 지금 한 줄로 답할 수 있는가* — 없으면 knowledge-map start 미실행이다.** cf. [[knowledge-map-skill]].

**지식지도 위치·생성** — *여러 프로젝트 횡단*이면 루트 맵, *한 폴더 내부 심화*면 폴더 로컬 맵. 없으면 부속 가이드 `references/지식지도_가이드.md`에 따라 만든 뒤 진행.

**★ 내부 문서(과거 자체 산출물)는 출처가 아니다 — 외부 1차 원본으로 거슬러 올라가라.** 과거 `.md`/`docx`/`xlsx`는 *2차 가공물*이라 WebSearch summary와 같은 지위 → 인용 출처로 쓰면 검증 사슬이 끊긴다. 그 문서의 〈출처〉·인용 태그에서 **외부 1차 원본 URL을 찾아** 직접 fetch·verbatim 재확인(2·3단계)한 뒤 활용한다(내부 문서 = 원본을 가리키는 인덱스일 뿐).
- **재사용 OK**: 검증된 외부 출처 목록, `_raw_sources/` 원자료, 방법론·구조·스코프.
- **베끼면 안 됨**: 내부 문서를 출처로 박은 수치·인용(외부 원본으로 재귀속 후 재확인).
- **인접 산출물(sibling xlsx/docx/pptx)의 검증된 출처 재활용 = 파일 인용이 아니라 임베드 링크 *타깃* 추출.** 파일을 출처로 박지 말고 `openpyxl cell.hyperlink.target`(xlsx)·docx rels·`run.hyperlink.address`(pptx)로 외부 원본 URL을 뽑아 그 원본을 직접 fetch·재확인 후 활용. cf. `research-source-check` §1.

### 1. 스코프 + Fan-out (deep-research)
- 질문을 5개 내외 검색 앵글로 분해(현황 1차지표 / 과거 전망 verbatim / Bear·구조적 함정 / Bull·정책 / 파격(비선형) 트리거 등).
- `/deep-research`(또는 동등한 병렬 WebSearch)로 후보 출처를 발견한다. **이 단계 결과는 발견 목록일 뿐 인용 출처가 아니다.**
- **★ 위임·백그라운드 리서치는 *수렴 조건 + 호출 상한*을 못박아라 — 무한 fan-out 금지.** 서브에이전트/백그라운드에 리서치를 맡길 땐 '무엇이 나오면 끝'(예: 핵심 질문을 N개 1차 출처로 답하면 *즉시 종료*)과 호출/시간 상한을 *프롬프트에 명시*하고, 에이전트가 *스스로 하위 에이전트를 늘리지 못하게* 하라(자율 escalate 금지). **핵심 사실은 값싼 고수율 1차 fetch부터 직접** 친다 — 공식 연혁·IR 페이지·시드 기사·최근 회차는 보통 *2~3회 fetch*로 답이 난다. 광범위 하베스트가 *정말* 필요할 때만 위임하고, 위임 후에도 수렴하면 곧장 거둬들여라. *실사례: 한 행사의 '시작·현재 존속' 확인은 공식 연혁 1 + 최근 회차 기사 1 + 시드 기사 1(=3 fetch)로 끝나는데, 상한 없는 백그라운드 에이전트에 맡겨 토큰·시간을 흘림.*
- **★ 초기 리서치는 *방향 잡기*용 — 딥다이브는 *본 리서치*에서 끝까지 하라.** 첫 패스(fan-out·빠른 검색)는 '어디를 팔지' 정하는 나침반이지 결론 근거가 아니다. 초기 발견을 그대로 결론·산출물에 옮기지 말고, 핵심 주장마다 본 리서치에서 1차 자료로 충분히 파고들어 확정하라. 특히 **다대상 비교·벤치는 *모든 대상을 같은 깊이로* 조사하라** — 초기엔 한 대상만 깊고 나머진 얕기 마련이라 그대로 두면 '자료 많은 A만 강하다'는 거짓 결론이 난다. **'못 찾음'은 '없음'이 아니다** — 못 찾았으면 UNVERIFIABLE·한계로 두고 부재로 단정 말 것. 비교 축(능력 체크리스트)을 먼저 정해 *대상마다 같은 칸을 같은 깊이로* 채운 뒤 비교하라. **'무엇을 하는 회사인가'(사업범위·역량)는 그 회사 *본인*의 1차 자료**(공식 사업·제품 페이지·거래소 상장/발행 문서·규제 라이선스 등록부·업계 전문지)를 2차 뉴스보다 먼저 본다. *(예: 다사 벤치 1패스가 재무공시·뉴스만 보고 한 곳만 'full'로 단정 → 나머지의 공식·거래소·업계지를 같은 깊이로 보자 결론이 뒤집힘.)*
- **★ 스코프를 {포함}/{제외} 명시 리스트로 *잠그고* 후보마다 통과시켜라.** 과제 정의(예: "S&T = OTC·MM/LP·Prime")를 포함/제외 박스로 고정한 뒤 모든 후보를 거른다. **인접·유사 활동의 경계를 미리 선언** — 안 그러면 유사하지만 범위 밖인 것이 계속 새어든다. 헷갈리는 쌍(구조화상품↔트레이딩·커스터디↔prime·거래소 venue↔OTC)은 *어느 쪽인지* 박스에 명시.
- **★ 분류·귀속은 표면 신호가 아니라 *범주를 가르는 결정적 속성*으로 — '사건이 일어났다' ≠ '그 범주다'.** 분류·귀속 시 *발생 사실·instrument·이름·라벨* 같은 여러 범주 공통의 표면 신호로 판정하면 오분류한다('활동 X가 있었다'는 X의 존재만 입증, 유형은 미입증). 혼동되는 범주쌍은 *무엇이 둘을 가르는지(결정 속성)*를 먼저 정의하고 그 속성을 출처에서 확인하라. *(예: BTC 옵션도 체결·청산 경로[중앙청산 거래소↔양자 OTC]가 결정 속성 — GFO-X 거래를 '거래 발생'만 보고 OTC로 오분류.)*
- **★ 등록·라이선스/약관의 *명시 라벨* ≠ 실제 *허용 스코프*(룰북·약관 본문) — '근거없음/UNVERIFIABLE'을 라벨만 보고 판정 말 것.** 어떤 활동이 등록부·면허의 *명시 활동 라벨*에 없어도 그 면허의 *본문(룰북·약관) 스코프*에 포함될 수 있고(라벨엔 없지만 허용 = false-negative), 반대로 라벨처럼 보여도 *별도 면허*로 분리돼 그 면허 보유만으론 불가일 수 있다. 기능 보유/부재 판정 전 **해당 면허·권한의 본문 스코프를 직접 확인**하라(위 '결정 속성' 분류를 규제·권한에 적용). *실사례: 시장조성이 등록 라벨엔 없으나 Broker-Dealer 면허 본문의 '자기계정 principal+인벤토리 보유' 스코프에 포함 / 발행은 BD와 분리된 별도 면허라 BD 보유만으론 불가.*

- **★ '없음·단일출처' 부재 단정은 *쿼리 변형 소진* 후에만 — 내 검색어로 안 나옴 ≠ 존재하지 않음.** load-bearing 부재 주장('비-X 매체엔 기록 없음'·'출처는 이거 하나뿐') 전에 *동의어·사건명·관계자·반대 프레임*으로 재검색하라(예: '인수 검토'만 치지 말고 '인수설·참여 시도·지분 타진·인수 부인'과 *사건 자체*를 친다). **요청자·사용자가 '그 자료가 있다'고 하면 강한 신호 — 내 1패스 부재를 들이대지 말고 사건을 다각도로 재탐색**(가용 시 1차·외신·아카이브). 그래도 없으면 '내 검색 범위에선 미확인'으로 *한정*해 적고 '존재하지 않음'으로 단정 금지. cf. [[exhaust-before-declaring-research-limits]]

### 1-bis. 정형 공시·구조화 데이터 추출 분기 (filings/structured-data)
과제가 웹 서술형이 아니라 **1차 공시(DART·SEC·감독기관 재무주석)에서 정형 수치 표를 추출**하는 것이면, 위 5개 검색앵글 fan-out은 무의미하다. 대신 4절차로 분기:
1. **권위 공시 위치 특정** — 회사·기간·문서종류(사업보고서/10-K/10-Q)와 주석 노드 확정.
2. **정확한 표 추출** — 본문 HTML/XBRL의 `<TR>/<TD>`를 결정적으로 파싱(에이전트 요약 아님).
3. **다년도 교차정합 검증(비용 0의 강력한 무결성 체크)** — *각 연도의 「당기」 = 익년의 「전기」* 일치 확인. 다년도 추출 시 항상 수행.
4. **단위·컬럼 구조 먼저 확정** — 회사마다 공시단위(천원/백만원)·자본 컬럼 유무 상이. 단위환산(천원→백만원→억원)은 최빈 오류원이라 별도 검증.

**★ 공시 리서치는 재무제표에서 멈추지 말고 *같은 발행처의 서술형·발표 자료*까지 소진하라.** 정형 재무제표(10-K/10-Q 재무·XBRL·DART 재무주석)엔 *수치*만 있다 — **고객 구성·세그먼트 KPI·사업 전략·정성 서술은 IR 발표자료(SEC 8-K exhibit EX-99.x investor presentation·earnings deck)·MD&A·DART '사업의 내용'·투자설명서**에 있다. 한 회사 공시를 다룰 땐 이 자료를 *반드시 함께* fetch한다 — **SEC=EDGAR filing list에서 8-K/EX-99 exhibit·investor deck을 훑고, DART=사업보고서 '사업의 내용'을 연다.** 리트머스: *'이 회사가 무엇을·누구에게·어떻게 파는가'를 재무제표만으로 답하려 하면 실패 — 답은 발표자료에 있다.* *실사례: 상장사를 10-K/8-K 재무만 보고 정리했다가 investor deck(고객 카운터파티 수·세그먼트 AUM 분해·신규 리테일 라인·성장전략)을 놓쳐 사용자가 짚은 뒤에야 반영.*

**DART 공통 접근 (식별 → fetch 2경로 → 기록)**:
- **① 기업 식별(선행 필수)**: corp_code(8자리)면 직행 / 종목코드·회사명이면 `corpCode.xml`에서 매칭(1회 받아 로컬 캐시). 동명 다수면 업종·상장여부로 추론-후-확인(오식별 시 이후 전 수치가 엉뚱한 회사).

### 2. 원문 fetch + claim 추출 (방법론 B-1·B-2)
- 후보 URL을 **WebFetch 또는 curl로 직접 fetch**. 403/타임아웃은 봇 차단일 수 있으니 브라우저 UA curl로 재시도(E-1). 죽은 링크는 404/완전 도달불가일 때만.
- **봇차단 우회 — Wayback Machine**: 브라우저-UA curl마저 타임아웃(curl exit 28)·403이면(컨설팅사 등), Wayback으로 우회 — ① `http://archive.org/wayback/available?url=<URL>`로 스냅샷 조회(`.archived_snapshots.closest.url`), ② 스냅샷 URL에 **`id_` 삽입**(`/web/<ts>id_/<url>`)해 배너 없는 원본 raw 수신, ③ HTML 태그 제거(또는 pypdf)로 본문 추출 후 grep. 스냅샷 본문은 verbatim 동일하므로 인용 가능(**스냅샷 날짜 병기**). 라이브 차단 ≠ 도달불가.
- **★ 차단 *종류*를 먼저 진단해 분기 — UA 차단 ≠ 등록/페이월**: **① 봇 UA 차단**(403·타임아웃·챌린지)이면 브라우저 UA·Wayback으로 뚫린다 — 일부 기관은 **이름·이메일 형식 UA 요구**(예: SEC.gov). **② 등록/페이월**(본문이 로그인·구독 뒤; 라이브 200이어도 수치 미노출·Wayback도 흔히 부재)이면 UA·Wayback 둘 다 무력 → *같은 발행기관의 개방 채널*(보도자료·서머리·블로그)이나 재인용 개방 미러에서 동등 수치를 verbatim 확보해 재귀속한다(등록벽 URL을 인용으로 남기지 말 것). '못 뚫음/보류' 선언 전에 *UA형인지 게이트형인지* 먼저 가르고, 게이트형이면 개방 동등 출처로 우회. **+ 봇차단 우회 사다리**: 브라우저UA → **크롤러UA(Googlebot/Bingbot — Cloudflare가 SEO용으로 허용하기도)** → Wayback `id_`/CDX → 개방 미러. 이 사다리로도 안 뚫리는 *하드 JS 챌린지*(Cloudflare 'Just a moment')는 브라우저(JS 실행)만 통과 — 이때도 **'유료/페이월'로 라벨 금지**(봇차단이지 게이트 아님): 링크는 *접근가능*으로 남기고 verbatim만 '자동 미수행', 필요하면 사용자에게 본문 요청. ②(등록/페이월) 판정은 *200 + 로그인·구독 게이트를 실제 확인*했을 때만 — 자동 fetch 실패만으로 '유료' 단정 금지.
- **PDF 추출**: curl로 PDF 다운로드(이름·이메일 또는 브라우저 UA) 후 아래 두 경로로 분기. 서브에이전트가 fetch 차단되면 **메인 세션에서 직접 수행**(메인은 PowerShell·curl 가용).
  - **텍스트 레이어 있음 → pypdf(설치됨)**: `from pypdf import PdfReader; txt="".join(p.extract_text() or "" for p in PdfReader(path).pages)` → grep로 verbatim 확인.
  - **★ 이미지 스캔 PDF(pypdf 0자 반환) → PyMuPDF(fitz, 설치됨)로 PNG 렌더링 → Claude Vision**: `import fitz; doc=fitz.open(path); doc[N].get_pixmap(matrix=fitz.Matrix(2,2)).save("_tmp_pN.png")` → Read 도구로 PNG 읽기. *실사례: Companies House(companieshouse.gov.uk)는 모든 공시 문서를 libtiff/tiff2pdf 이미지 스캔 PDF로 저장 — pypdf 항상 0자, format=xhtml 500 오류. 브라우저 UA curl로 302→S3 pre-signed URL(60초 유효) 경유해 PDF 다운로드 후 PyMuPDF 렌더링으로 Revolut 2025 재무제표 수치 추출 확인. 문서 URL 패턴: `/company/{번호}/filing-history/{트랜잭션ID}/document?format=pdf&download=0`, 연간 계정은 AA 유형.*
- **★ fetch 파일은 repo 루트에 쓰지 않는다 — 과제 `_raw_sources\`에만**: curl 다운로드·임시 PDF는 해당 과제 폴더의 `_raw_sources\`에 저장(cwd가 루트여도 거기 흘리지 말 것). 스크래치는 **단일 고정 경로 `_raw_sources\_tmp.<ext>` 재사용 + 종료 시 삭제**. 영구 raw는 의미있는 파일명으로 보존.
- **★ WebSearch summary를 그대로 인용 금지 (절대 게이트)** — 원문 본문에서 인용 표현·수치를 verbatim 추출하고 grep으로 존재 확인(B-2). **콘텐츠는 *링크 안 원문에서* 만든다 — 검색요약/LLM지식으로 초안을 쓰고 나중에 출처를 붙이는 *역순* 금지**(요약이 우연히 맞아도 불가). 초안부터 원문 verbatim에서 생성하고, 게재 전 모든 claim을 그 링크 원문에서 재대조한다.
- **★ WebFetch는 200을 줘도 *요약·번역*한다(silent paraphrase) — "WebFetch 성공 ≠ verbatim".** 작은 모델이 본문을 요약·영역해 어순·연결어·핵심 문장을 왜곡할 수 있다 → **verbatim 인용·정합성 대조는 curl raw 본문 + grep**으로(특히 비영어). load-bearing 인용은 curl 원문으로 확정.
- PDF 전용 수치는 접속 가능 미러로 교차확인(E-11).
- **★ 라이브 트래커(SPA) 인용 규율**: rwa.xyz·DefiLlama 등은 시점값이 계속 바뀜 → ① **토픽 서브페이지**로 링크(앱 홈/제네릭 URL 금지) + **기준일 병기**, ② 가능하면 수치가 static하게 적힌 리포트(PDF 등)를 병기, ③ 게재 전 인용 수치가 그 링크에 실제 보이는지 WebFetch로 현재값 확인. *(예: 앱 홈 URL에 과거 시점값을 걸면 현재 페이지값과 반복 불일치.)*

### 3. 의무 출처 재대조 — 모든 claim (방법론 E-3 ★핵심)
워크플로우가 "출처 X가 Y라 했다"고 합성해도 **X 원문을 직접 grep해 Y의 존재·귀속을 재확인**한다. 미확인 시: (a) 인용 삭제, (b) 정확한 출처로 재귀속, (c) "본 보고서 분석"으로 framing 전환(B-4).
- **★ '승계'한 인용도 그 URL 원문에 재grep — verbatim+URL을 검증된 쌍으로 신뢰 금지.** 이전 산출물·다른 노트에서 출처 코드와 verbatim을 통째로 가져올 때, 그 verbatim이 *바로 그 URL 원문*에 실제로 있는지 건건 재확인한다. 한 인용을 여러 출처가 받치면 어느 페이지에 *그 문구*가 있는지로 귀속. *(예: 승계 인용이 인수 보도자료엔 부재하고 다른 페이지에 있어 오귀속.)*
- superlative(최초·유일·최대)는 원문 한정자 verbatim 유지(docx 가이드 §"first").
- **★ 백단 서브에이전트 수치 = 메인 재검증**: 백그라운드 에이전트가 준 load-bearing 수치는 메인에서 ① 숫자뿐 아니라 ② 그 출처 URL이 그 값을 실제 보여주는지까지 재대조(서브에이전트는 fetch가 샌드박스라 신뢰도 낮음). *(예: 백단 "active $18.91B"이 실제 페이지엔 Distributed $5.66B / Represented $23.63B였음.)* **★ 카테고리(주체·역할·분류) 확인 ≠ 정량(규모·금액·일자·수치) 확인** — 한 행의 *범주 필드*를 1차로 맞췄어도 *수치 필드는 별도로 틀릴 수 있다* → 정량값은 따로 1차 원문에서 결정적 재산정(에이전트 요약 수치를 산출물에 직행 금지). *(실사례: 거래 신디케이트·역할은 1차 grep으로 확정했으나 규모(금액)는 발굴 에이전트값을 옮겨 다수 오류.)*

### 4. 적대적 검증 (deep-research) + Tier 라벨링 (방법론 A-2·A-3)
- 핵심 claim은 3표 적대적 검증(2/3 반박 시 폐기). 외부 검토 의견도 1차 자료와 재대조 후 선별 반영(B-8 / E-6).
- 출처를 Tier 0~1 우선으로 카테고리화(R/C/A/N + 분석 보강 O). 본문 인용 ↔ 출처 1:1 라벨 매핑.

### 5. 합성 — 사실/분석 분리 + 실적/전망 + 단위 (방법론 B-6·E-4·E-5)
- **사실(출처 derive)**과 **[분석](본 보고서 해석)**을 명확히 분리.
- **★ 모든 `[분석]`은 레퍼런스/백업 grounding 필수 — 없으면 삭제.** 각 [분석]은 (a) 이 리서치의 인용 출처/데이터에서 도출되거나 (b) comparable·proxy + 출처를 동반하거나, (c) 둘 다 못 하면 삭제/〈한계〉 강등. 순수 LLM 일반지식 분석(뇌피셜) 금지. 합성 framing("두 축"·"1:1 대응")도 *어느 출처의 어느 진술에서 도출됐는지* 명시. cf. [[analysis-must-be-reference-grounded]].
- **★ [분석]은 산식만이 아니라 「출처가 이렇게 보고 → 이건 이런 의미 → 그래서 이렇게 도출」 사슬로 풀어 쓴다.** 도출값 옆에 산식만 적지 말고, 각 입력이 *출처에 어떻게 나오는지(verbatim·측정)* → *그 사실의 의미* → *그래서 어떤 곱·배분·외삽·합산/제외로 결과가 나오는지*, 특히 *'왜 이 인자를 이렇게(합산/제외) 잡는가'의 판단 근거*를 적는다. *(예: 보유 AUM을 '두 ETF 순자산 합'으로 잡은 근거 = 그 시장 기관 채널이 규제 ETF뿐이라는 의미 사슬; 수탁액에 포함되므로 합산 시 이중계상→제외.)*
- **★ 스코프 완전성 — 양을 이루는 *주요 구성 층*을 임의 누락하지 말 것.** 어떤 양(거래량·시장규모·풀)을 사이징할 때 주요 층(현물 vs 파생·1차 vs 2차·발행 vs 유통) 중 하나를 *베이스가 그것을 못 잡는다는 이유로* 빠뜨리면 체계적 과소·왜곡이다. 베이스가 한 층만 포착하면 누락 층을 *별도 층으로 추가*(배수·proxy)하거나 최소한 *한계·방향(과소)·보강법을 명시*한다(스코프 박스의 '제외'와 다름 — 포함돼야 할 층의 누락). *(예: 거래 베이스가 현물만 잡아 파생을 누락 → 파생 층을 배수로 별도 가산.)*
- **★ 권위 *민간* 데이터 vs *공식 1차* 구분.** 업계 표준으로 인용되는 민간 지수·벤더 데이터도 *정부·규제·공시 1차가 아니다*(방법론에 추정 개입) → 본문에 *민간·방향성*임을 밝히고, load-bearing 수치는 *공식 1차*로 받쳐 단일 벤더 의존을 피한다(Tier: 공식 1차 > 권위 민간 > 상업). *(예: 채택지수는 권역 비교 방향성으로만, 시장 규모는 공식 통계로.)*
- **★ 인접 워크스트림의 실측치를 차용할 땐 그 *문서*가 아니라 *원 1차 출처 URL*로 인용** (§0 '내부문서≠출처'의 실측치 버전; 차용임은 밝히되 링크는 원 1차로). *(예: 밸류풀의 체결 4.9bp·수탁 6.4bp를 차용하되 출처는 그 원천 공시 URL로.)*
- **★ 성과/효과 귀속 = 분해·소거법.** 성과를 특정 단위·원인에 귀속하기 전 **분해**한다: (회계) 영업이익 vs OCI/FX 환산, (수익 성격) principal(자기자본 평가손익) vs fee/agency, (귀속 주체) *법인 장부 booking vs 본사 사업부 장부*. 그리고 **소거법** — 명백히 그 원인이 아닌 것(FX환산·자본 carry·시황 평가차익)부터 떼고 *남는 잔차*만 후보로. 정량 분리가 공개데이터로 안 되면 단정 말고 **구간(상한·하한)·질적 귀속 + 한계**로(반사실 부재 명시). negative 결과("공개자료에 없음")는 소진 검색 후의 유효한 결론 — 단일출처로 강등·한계로 남길 것(가짜 백업·삭제 금지).
- **★ 격차·우열을 '구조적'이라 단정하기 전 *정규화*로 구조 vs 일시를 가른다.** 두 대상의 *현 시점* 차이(수익·실적·점유 등)를 구조적 우위로 결론짓기 전, **일회성·시점 요인**(대규모 충당·일회성 손익·소송/사고·시황 변동)을 제거하거나 **그 충격이 없던 기준기간**(직전 정상 연도 등)으로 비교하라 — 한 컷만 보면 일시 충격을 구조로 오인한다. 정규화 후에도 차이가 남으면 구조적, 사라지거나 역전되면 일시적(회복 시 좁혀짐)으로 결론. *(실사례: A의 현 이익이 B의 2배여도 충격 전 기준기간엔 B가 더 컸다면, 그 격차는 B의 일회성 비용 충격發이지 A의 구조적 우위가 아님.)*
- **★ 관측된 *부재·공백*에서 원인을 단정 금지.** '트랙레코드 없음 / 안 함'을 관측했을 때 그 원인이 *역량 제약('못 함')*인지 *전략적 미진출('안 함')*인지 출처로 판별되지 않으면 **인과를 미정으로 둔다**(부재를 곧 무능 또는 무관심으로 비약 금지) — 둘 다 가능함을 명시하거나 한계로. *(실사례: '특정 업무 트랙레코드 부재'를 '라이선스가 없어서'로 단정 → '못 함/안 함 미판별'로 교정.)*
- **★ '관행·통상·일반적으로'도 출처가 필요하다.** 업계 관행·표준 수치를 출처 없이 단언 금지(내가 관행이라 부른다고 관행이 되는 게 아니다) — 외부 1차/공개 자료로 뒷받침하거나, 없으면 `[분석]`/`[가정]`으로 강등하고 프록시·도출 근거를 명시.
- 통화·대규모 수치는 영어식 B/T. 마크다운 본문 `$`는 `\$` escape, 인용은 HTML 앵커(E-4).
- 성장률 등 표는 실적/추정/전망 구분(E-5).
- **★ 수치 반올림은 원본 full-precision 값에서 목표 표시자리로 *단 한 번*만 — 이중 반올림 금지.** 출처 원값을 최대 정밀도(소수 2~3자리)로 받아 표시자리로 한 번에 반올림하라. 이미 중간 자리로 반올림된 2차 값(요약·재가공 표)을 다시 반올림하면 x.x5 류 경계값이 한 자리 위로 부풀려진다(raw 5.049 → 2자리 5.05 → 1자리 5.1, 정답 5.0). 임의로 잘린 소수 2자리 스냅샷을 재반올림 소스로 쓰지 말고, 반올림은 항상 원값 한 곳에서 최종 자리로 직행. *실사례: WDI 성장률 5셀이 raw→2자리→1자리 경로로 각 +0.1 과대(감리 셀단위 재대조로 포착).*
- **비약(비선형) 트리거**와 일반 Bull을 구분: 외생 충격으로 급격 확대 가능한 것만 '파격/비약', 점진적 동력은 Bull(E-10). 중복 금지.
- **★ 권고·결론은 '비자명한 인사이트'여야 한다.** 대상이 당연히 할 일을 권고로 내지 말 것(증권사에 "증권에 집중하라"는 무의미) — '그 안에서 *무엇을·어떻게*'까지 좁혀야 인사이트다.
- **★ 결론·권고는 *결정*한다 — 우산 용어로 회피 금지.** 분석이 한 선택지를 지지하면 *명확히 그것으로 결론*(A vs B 택일)하라. 실제 후보가 둘인데 모호한 상위 개념으로 판단을 비키면 권고가 아니다 — 단서·대안은 결론 *뒤에* 짧게. 일반론 권고는 *대상 주체의 1차 자료*(인터뷰·내부)로 ground하면 실행가능 권고로 격상.
- **★ 단일 사례로 집단 일반화 금지(=날조).** 한 데이터포인트("KB 6년 적자")를 집단 전체("은행은 부진")로 단정 말 것. 섹션 제목·결론이 데이터 범위를 넘으면 안 됨.
- **핵심 주장은 적대적 논리 점검 통과.** '왜 그런가'를 스스로 반박해 반례에 무너지면 수정.
- **★ 인과·강점연결 주장은 '메커니즘'과 '근거 적합성'을 점검.** *'A가 강점 X를 Y로 레버리지'* 식 주장은 **X가 무엇이고 *어떻게* Y가 되는지(메커니즘)가 출처로 설명**돼야 함 — 막연한 'A+B→C'는 grounding 미달이라 삭제/구체화. 각 인용이 **그 주장 유형(발행/유통·강점 A/B·현재/미래)을 실제로 뒷받침**하는지 확인(*verbatim 정확 ≠ 뒷받침* — 발행 인용을 유통 주장에 붙이지 말 것). *(예: 발행 플랫폼 인용을 유통 주장에 붙임 → 유통(거래) 인용으로 교체.)*
- **★ 비교(다대상) 시 각 대상의 *해당 영역 entity*를 동일 깊이로 1차 확인.** 한 대상의 **한 측면(예 발행 플랫폼)으로 다른 측면(유통)을 단정 금지** — 발행 ≠ 유통 entity일 수 있고 firm마다 별개. firm별로 '발행/유통/수탁을 *어느 entity*가 하나'를 따로 매핑하고, 한 곳만 얕게 보면 비대칭 오류. *(예: 한 곳은 entity별로 파고들고 다른 곳은 단일모델로 단정 → 후자의 유통 실체 누락.)* cf. §1 '같은 깊이로'.
- **★ 사이징/밸류풀 모델은 '산식 메커니즘'을 건건 점검.** 산식(베이스×요율×share)으로 산출할 때 숫자 채우기 전 각 산식이 *그 수익을 구조적으로 옳게 잡는지* 확인:
  - **(a 베이스)** 베이스가 그 수익 메커니즘 대상인가 — 발행=flow·거래=volume(시총×회전율)·잔액수수료(수탁·서비싱)=stock(AUM). flow에 stock요율 곱하는 베이스 불일치 금지.
  - **(b 전환율) 100%를 곱하지 말 것** — 수탁=외부수탁 전환율(AUC<시총)·대행=agency 체결비중(DMA 직접·principal 제외)·MM=monetized 비중. 자산군 간 **대칭 적용**. 베이스가 이질적이면 각 세그먼트가 그 지표를 실제 발생시키는지 확인(안 내는 세그먼트는 별도 처리), 카테고리·시장 간 이중계상 점검.
  - **(c 이중계상)** 같은 거래/잔액 위에서 서로 다른 주체가 각각 수취하는 층(venue·agency·spread)을 가산하면 한 주체 몫이 아님 — *번들 실측요율*에 별도 층을 또 더하면 이중계상 → 한 층 제외/순수요율 분해. *지불 주체가 다른 층*(예: 수탁 = 기초자산층[펀드 TER] + 토큰층[투자자])을 합산하면 단일 주체 매출이 아님 → 특정 주체 capture는 *그 주체의 층*만(층 합산은 TAM).
  - **(d TAM vs SAM)** 가산 합계는 보통 산업 전체(TAM)이지 대상 포착분(SAM)이 아님 — 분리 표기, SAM을 TAM 합계에 섞지 말 것.
  - **(e 인자 grounding)** 각 인자(가정·share·rate)는 comparable/proxy라도 **출처 연계 + `[분석]` 라벨**. 미래시점은 현재 실측을 성숙 가정으로 스케일하되 소규모·초기 프리미엄 요율은 압축. grounding을 **출처가 그 인자를 얼마나 직접 측정하는지로 등급화**(직접실측/부분 analogy/proxy/정성) — **정량 인자엔 정량 출처 필수**(정성 서술로 특정 수치 뒷받침 금지). proxy·analog는 대상의 *실제 구조*(기초자산/메커니즘)에 매칭.
  - **(f 시점기준 일관성)** 미래 사이징 시 인자마다 '현재 유지 vs 미래 튜닝'을 들쭉날쭉 말고 **하나의 기준**으로: 이미 대규모·경쟁적인 군(크립토)은 현재 실측 ≈ 성숙값으로, 신생·소규모 군(토큰화 RWA)은 현재 실측(초기 프리미엄)이 아니라 성숙 analog(규제증권=TradFi 요율). 시장규모·2차시장·기관화는 명시적 미래 가정. driver+grounded endpoint가 있을 때만 튜닝.
  - **(g 실측요율 도출 위생)** 요율 = 매출 ÷ 베이스로 역산할 때: ① 분자가 *organic·해당 활동* 매출인가 — 인수(M&A)·타 세그먼트·일회성 매출 혼입 점검. ② 분자·분모 **단위 일치** — 일회성(발행) 매출을 AUM(stock)으로 나눠 flow에 곱하지 말 것; recurring과 one-time을 분리해 각자 베이스에.
  - **(h 다중 산출물 정합성 · top-down)** 상호의존적 정량 결과가 여럿이면 개별 인자 검증과 별개로 **결과값들의 상대 규모를 서로·합계·실세계 벤치마크와 대조해 sanity**한 뒤 신뢰하고, **이상한 결과만 인자로 drill**(인자부터 뒤지면 전체 부정합을 놓침). 벤치마크는 맥락·국면 일치 확인(성장기 vs 성숙기 — 성장기/비유동 시장은 primary가 secondary보다 클 수 있음).

### 6. 산출물 — 작업 마스터 vs 클라이언트 (방법론 E-9·E-12)
- **작업 마스터(.md)**: Tier 라벨 유지, 목차/앵커/'목차로'/HTML 앵커 인용·출처 하이퍼링크(아래 〈.md 산출물 형식〉).
- **클라이언트 산출물(docx/xlsx)**: Tier 등 메타 라벨 제거, 표 출처도 클릭 하이퍼링크, 명사형·전문 워딩(docx 가이드 / research-organizer 스킬).
- 모든 인용 링크 접속 가능 검증. 산출물 새 버전 발행·`_raw_sources/` 분리.
- **지식지도 — 시작 시 *참조*만, 갱신은 `/knowledge-map` 호출 시에만**(자동·매 종료 갱신 금지). cf. [[claude-folder-knowledge-map]]·[[knowledge-map-skill]].

## .md 산출물 형식 (작업 마스터 리서치 노트 — 단독 정본)

**1) 파일·버전** — 덮어쓰기 금지(`_vN` 신규 발행), 같은 주제는 전용 폴더, 원자료·스크립트는 `_raw_sources/`로 분리, 폴더에 `CHANGELOG.md`.

**2) 문서 골격** — `<a id="top">` → 제목/부제 → 메타라인(기준일·버전·시계·출처원칙·단위) → `<a id="toc">` 목차 → `## 0. Executive Summary`(불릿, 각 줄 끝 출처 인용) → 본문(1.현황 2.전망 3.시사점/기회 4.미해결) → `## 〈출처〉`(Tier 라벨) → `### 검증 메모`(작업노트, 본문 비노출).

**3) 목차·앵커·'목차로'** — 자동 슬러그는 한글·기호에서 불안정 → **명시적 HTML 앵커**: 각 섹션 헤딩 위 `<a id="secN"></a>`, 목차는 `- [1. …](#sec1)`(2단계까지), 각 주요 섹션 끝 `<div align="right"><a href="#toc">⬆ 목차로</a></div>`.

**4) 출처 — 본문은 원문 직접 랜딩 · 〈출처〉는 원문·번역·내용·활용 다단**:
- **인덱스 1개 = URL(출처) 1개.** 한 `[R#]`에 여러 링크 매핑 금지 — 한 주장을 여러 출처가 받치면 `R3a·R3b`로 분할.
- **본문 인용 = 원문 페이지로 직접 링크**: `<a href="원문 URL">[R1]</a>` — 클릭 시 그 수치가 보이는 원문 페이지로 바로 랜딩(하단 앵커 점프 아님). **본문 모든 `[R#]`은 하이퍼링크(HTML 앵커 또는 마크다운 링크)여야 한다 — 맨 텍스트 `[R#]` 방치 금지.** 웹 URL이 없는 출처(인터뷰 전사·비공개 문서)만 예외로, 〈출처〉 항목 앵커(`#R#`)로 점프시키되 그 사유를 항목에 명시.
- **〈출처〉 각 항목 = 다단 — *구조화 하위불릿*(인라인 한 줄 압축 금지)**: 헤더 한 줄 아래 들여쓴 하위불릿으로 ⓐ원문(verbatim) ⓑ번역 ⓒ내용 ⓓ활용을 *각자 자기 줄*에 둔다(`·`로 한 문단에 욱여넣지 말 것). **번역**은 원문이 외국어일 때 필수(한국어 원문이면 생략 가능). 표준 정본 = `S&T_랜드스케이프_한판_v1.md`·`S&T_국가진출현황_v1_2.md`. 레이아웃:
  ```
  - **[R1]** [Reg] 출처명·문서종류 — 한 줄 설명.
    - **원문(verbatim)**: *"원문 그대로"*(어순·연결어·한정자 first/only/largest 보존) → 끝에 원문 URL `[표시텍스트](URL)`(백틱 금지)
    - **번역**: 위 원문의 한국어 번역(외국어 원문일 때 — 번역투 배제·자연스러운 국어)
    - **내용**: 그 출처가 *무엇을 말하는* 자료인가(분자/분모·정의·기준일 포함)
    - **활용**: 본문 *§위치 + 어느 주장을 어떻게* 뒷받침하는가 + **한계**(단일채널·시점성 등)
  ```
- **⚠️ MathJax 충돌 금지**: 마크다운 escape `[\[R1\]](#R1)`·본문 raw `$ … $`는 MathJax/KaTeX 뷰어가 LaTeX로 해석해 깨짐 → 인용은 **HTML 링크/앵커**, 본문 `$`는 **`\$`로 escape**(Rp·KRW 불요; 표/코드 span 안은 `$` 그대로).

**5) 단위 — 영어식 통일** — K/M/**B(십억)**/**T(조)**. 통화기호+숫자+접미사($13B·$1.40T·Rp600T·KRW 56.8B). 원문 "X billion/trillion"은 B/T로 직역(한글 억/조 변환 시 10배 자릿수 오류: "420 billion rupiah"→Rp420B, ❌"420억"). 통화 섞이면 각각 명시+USD 병기.

**6) 사실/분석 분리** — 사실=서술+인용태그; verbatim=*"원문 그대로"* 이탤릭+따옴표(한정자 보존); 해석=**`[분석]`** 표기; 검증 절차는 본문 비노출, 맨 끝 〈검증 메모〉에만.

**★ 6-bis) 해석·시사점·비교 동반 + 용어 인라인 + 프로페셔널 어투 (독자가 .md만 읽어도 이해)** — ① 팩트·표 나열로 끝내지 말고 각 항목의 *의미·시사점(so-what)*과 *항목 간 비교 해석*을 동반(비교는 '해석'열·비교표로; '왜 이 결론·순위·차이'가 글로 읽히게). ② 용어는 *그 문장·표 안에서* 풀이(별도 용어사전 떠넘기기 금지; 용어사전은 보조·문서 뒤쪽). ③ **직관적이되 비즈니스 프로페셔널** — 구어·비유·은어·외래 약어 금지(❌마중물·빡셈·조이다·서빙·굴리다·핏 → ✅초기 시장 조성·엄격·규제 강화·대상 영업·운용·적합성). 쉬운 말이되 어휘는 정식 용어. ④ **리드 앵커** — 각 문단·불릿을 '무엇에 관한 말인지' 밝히는 짧은 리드(괄호 태그·굵은 리드어)로 시작하고 *리드(결론)→근거→(그래서)시사점* 3단으로(맥락 없이 사실부터 던지지 말 것 — 이해 난독의 최대 원인). ⑤ **논리 명시 전개** — A→B→C 인과·근거 연결을 문장으로 드러내 독자가 점을 잇게 떠넘기지 말 것(결론만/사실만 나열 금지, '왜'까지). ⑥ **한 문장 = 한 주장 + 양면 판정** — 엠대시·쉼표 만연체로 여러 주장 뭉치지 말고 짧게 끊고; 판정·헤드라인 문장은 기회와 제약을 함께 담는다.

**7) 표·verbatim** — 표 우측 끝 열에 출처 인용(본문 라벨 1:1); 수치표 헤딩에 "(검증됨)" 라벨 불요; 출처 URL에 백틱 금지.

## 자가 점검 (게재 전)
- [ ] **단계 게이트 (2단계)** — ① 각 cp `SG judge research-verified <cp> … deliverable=<…> dir=<과제폴더>` → **GATE PASS**(absorb→fetch→publish 순서) + async cp는 백그라운드 gate-audit 발사. ② 게재 직전 `SG resolve research-verified deliverable=<master.md> dir=<과제폴더>` → **RESOLVE PASS**(3 cp 감사 전부 PASS) 붙여넣기. init·form·judge·resolve·clear 전부 **같은 `dir=`**(순서 토큰을 한 워크플로로 묶음 — 동시작업 격리). RESOLVE PASS 아니면 게재/‘done’ 금지 · 봉인 루브릭 직접 열람 금지.
- [ ] **★ 첫 게이트 전 1패스 일괄 스윕 (반응식 N차 감사 금지)** — 노출/게재 전에 아래 전 항목(인용 verbatim·[분석] grounding·귀속 재대조·단위·구조)을 *게이트에 걸기 전* 한 번에 훑어 통과 상태로 만든다. 감사가 잡아주길 기대하고 미완본을 노출 게이트에 걸어 *지적된 한 부류(lens)씩* 고치는 반복(버전·감사 N회 낭비) 금지 — 감사 지적은 '누락 스윕'의 신호이지 정상 루프가 아니다.
- [ ] **시작 전 지식지도 확인** — 기존 이력 점검. 내부(과거 자체) 문서를 출처로 인용 0(외부 1차로 재귀속).
- [ ] **산출물 폴더 위치·파일명 지정됨(신규면 착수 전 `/knowledge-map start`)** — 인접 폴더는 출처·리드 재사용만; 기존 폴더에 즉흥 투입 0. *어느 폴더에·무슨 파일명으로 앉을지 한 줄로 답 가능*해야 통과.
- [ ] 모든 인용이 **사용 출처 본문에 verbatim 존재**(grep). WebSearch summary·LLM 지식 차용 0 — 콘텐츠를 *링크 안 원문*에서 생성(요약→초안→출처부착 역순 금지).
- [ ] 워크플로우 합성 claim의 **출처 귀속 재대조** 완료(E-3). 승계 인용도 그 URL 원문 재grep.
- [ ] **초기≠본 리서치** — 다대상 비교는 모든 대상 같은 깊이, '못 찾음 ≠ 없음', 사업범위·역량은 대상 본인 1차 자료 우선.
- [ ] **라이브 SPA 트래커** 인용은 토픽 서브페이지+기준일·정적 리포트 병기, 인용값이 링크에 실제 노출. 백단 서브에이전트 load-bearing 수치는 메인에서 수치+URL 재대조.
- [ ] Tier 0~1 1차 우선, 라벨 1:1 매핑, 결번 0(E-8).
- [ ] 사실/[분석] 분리, 실적/전망 구분, 단위 영어식·자릿수 검증(E-4·E-5) · **수치 반올림은 원값 full-precision에서 1회**(이중 반올림 0).
- [ ] **모든 [분석]에 도출근거(출처/comparable/데이터) 부착 — 무근거 뇌피셜 0(없으면 삭제/한계).** 성과 귀속은 분해·소거 후 — 정량 분리 불가면 구간·질적 귀속 + 한계.
- [ ] 모든 링크 접속 가능(봇 차단은 Wayback `id_` 스냅샷/미러/브라우저; 게이트형이면 개방 동등 출처로 재귀속), 죽은 링크 0(E-1).
- [ ] 외부 검토·사용자 편집은 1차 자료/diff로 재검증 후 선별 반영(E-6·E-7).
- [ ] **데이터형 수치(GDP·환율·통계)는 발행 직전 권위 API(WDI/WGI/공식통계)로 일괄 재대조** — 목표 vs 실측·기간·기준연도 라벨 분리.
- [ ] **클라이언트 산출물(xlsx)을 research-organizer로 빌드할 때도** 위 검증 통과 수치만 사용(포매팅 스킬엔 검증 게이트 없음 — 본 스킬이 게이트).
- [ ] 권고·결론이 **비자명 인사이트**인가, 단일 사례 **과잉 일반화** 없는가, 핵심 주장이 **적대적 논리**를 통과하는가.
- [ ] **인과·강점연결 주장**은 *무엇을·어떻게(메커니즘)*가 출처로 설명되는가, 각 근거가 *그 주장 유형*을 뒷받침하는가(verbatim 정확 ≠ 뒷받침).
- [ ] **해석·시사점·비교·어투** — 팩트 나열로 끝내지 않고 의미·비교 동반, 용어 본문 내 풀이, 구어·비유·은어·외래약어 0.
- [ ] **문장·논리 전개 명료성** — 리드 앵커(주제 리드로 시작)·명시적 논리 전개(A→B→C, 결론만/사실만 나열 0)·한 문장 한 주장(만연체 0)·양면 판정(기회+제약 한 문장). 독자가 한 번에 이해되는가.
- [ ] **지식지도 자동 갱신 금지** — 시작 시 참조만; 갱신은 `/knowledge-map` 호출 시에만.
- [ ] **fetch·임시 파일 루트 금지 정리** — `_raw_sources\`(스크래치 `_tmp.<ext>`)에만, repo 루트 0; 종료 시 `_tmp*` 삭제.
