# Knowledge Map — 컨설팅 워크스트림 (start + update)

> ### ▶ 단계 게이트 (필수 — 합격은 네가 아니라 *심판*이 판정한다)
> hook 차단 환경의 강제 레버. 헬퍼 `SG` = `python3 <REPO>/.claude/skills/_stepgate/stepgate.py`.
> **이 스킬은 두 경로다 — 먼저 §A에서 경로를 판단하고, *그 경로의* 체크포인트를 통과한다**(합격 기준 비공개·**표현이 회차마다 뒤집히니 지난 답을 재사용하지 말고 이번 문구를 그대로 읽고 답할 것**):
> - **start**(과제 착수·폴더/이름 생성): ① `SG form knowledge-map start` → ② 정직히 답 → ③ `SG judge knowledge-map start <id>=<값> ...`. **GATE PASS가 아니면 생성 결과·핸드오프 제시 금지.**
> - **update**(지도 델타 갱신): ① `SG form knowledge-map update` → ② 지도·스캔 결과 확인 후 정직히 답 → ③ `SG judge knowledge-map update <id>=<값> ...`. **GATE PASS가 아니면 갱신 제시 금지**(말로 'done' 불가).
> 게이트 루브릭 파일은 직접 열람 금지(열람 시 무효 — Read는 감사됨). 상세 규약: `skill-maintainer` 〈단계 게이트 프로토콜〉.
> `<REPO>` = 이 저장소를 클론한 **절대경로**(문서상 표기). `dir=`·`deliverable=`은 절대경로여야 하므로 호출할 때 실제 경로로 치환한다.

**대상 리포 = `<REPO>/work/consulting/`**. 그 안의 `_지식지도_KNOWLEDGE_MAP.md` — "어떤 지식이 어느 폴더의 어느 파일에 있는지" 한눈에 보는 **포인터 인덱스**. 이 스킬은 ⓐ 새 과제의 *집(폴더·이름)*을 지도 구조에 맞게 **생성**하고(start), ⓑ 폴더 상태 변화를 지도에 **델타 반영**한다(update).

## A. 경로 판단 (먼저 — 어느 경로인가)

진입하면 **무엇을 하려는지 먼저 가른다**(둘 다 해당하면 start로 집을 먼저 만들고 → 책임 스킬이 작업 → 나중에 update):

| 신호 | 경로 |
|---|---|
| "새 과제/리서치 시작", "폴더 만들어줘", "작업공간 만들어줘", "어디에 둘지", "이름 정해줘" · 새 과제인데 **둘 곳·이름이 아직 없음** | **§B start** (폴더·이름 생성) |
| "지도 갱신/업데이트/최신화", "지도에 반영", "동기화", "마스터 인덱스 업데이트" · 새 산출물/버전이 생겨 **지도를 맞춰야 함** | **§C update** (델타 갱신) |
| 직전 대화가 **폴더·산출물 없이 끝난** 의미있는 단건 리서치이고 지도에 남길 가치 | **§C update → §C-bis** (§2-bis 요약 등재 — 한 줄 확인 후) |

- **★ 빈 호출(`/knowledge-map`만·설명 없음)이 기본 — 경로는 사용자 말이 아니라 *직전 대화 맥락*으로 가른다.** 새 폴더 만들 작업이면 start · 폴더/산출물·버전이 생겼으면 update · **폴더·산출물 없이 끝난 의미있는 리서치면 §C-bis(§2-bis 등재)** · 지도와 무관하면 그렇다고 답. §C-bis 후보가 감지되면 **"이 리서치를 §2-bis에 요약 등재할까요?" 한 줄만 확인**하고 진행(잡담·사소한 단발 조회는 제외 — 자동 등재 안 함).
- **start는 위치·이름만 *결정·생성*하고, 본 작업(리서치·빌드)은 그 작업을 맡은 스킬**(research-verified · research-organizer · research-docx · dart-analysis 등)이 한다 — 생성 후 그 스킬로 핸드오프한다. 이게 핵심 분리: *어디에·무슨 이름으로*는 지도(여기)가, *내용*은 책임 스킬이.
- 애매하면 사용자에게 한 줄로 확인("새 폴더를 만드는 건가요, 기존 지도를 갱신하는 건가요?").
- **스코프 밖이면 넘긴다** — 일상·개인 프로젝트(여행·가계·취미)면 `life/`의 `life-map`이 담당. 이 스킬은 컨설팅 과제 전용.

## B. 과제 착수 경로 (start — 새 과제의 집·이름 생성)

> 목적: 과제가 **제각각 다른 경로로 폴더를 만들어** 구조·이름이 흩어지던 것을 막는다 — 새 과제는 *항상 여기서* 지도 구조에 맞는 위치·이름을 받는다.

### B-1. 원칙
1. **지도가 위치·이름의 권위.** 새 폴더는 §0 전략질문 그룹 중 맞는 곳에 배치 + §1 **다음 레터** 부여. **임의 위치·프레임(렌즈1/2 등) 발명 금지.** cf. [[organize-by-user-taxonomy]]
2. **이름은 워크스트림 관례.** 폴더명 = 주제 식별 명사구(기존 폴더 톤·언더스코어 구분), 산출물 파일명 = `research_<task>_vN_M.{md,xlsx,docx}`(또는 그 워크스트림의 기존 관례). **스킬 framing 단어(consulting_·deliverable_ 등) 접두사 금지.** cf. [[filename-follow-workstream-convention]]
3. **생성은 골격까지만.** 폴더 + `CHANGELOG.md`(생성 기록 1줄: 생성일·목표·부여 레터) + 빈 `_raw_sources/`. **실제 산출물(마스터 .md·xlsx·docx)은 책임 스킬이 정해진 이름으로 만든다** — 여기서 만들지 않는다. cf. [[deliverable-versioning]] · [[fetch-files-never-repo-root]]
4. **중복 금지.** 같은 과제의 기존 폴더가 있으면 새로 만들지 말고 **그걸 쓴다**(스캔·지도로 먼저 확인). 하위 과제면 부모 폴더 아래 서브폴더로.
5. **배치는 표면 키워드가 아니라 '의의(어느 전략 질문에 답하나)'로 판정.** 폴더·주제의 표면어로 매칭하지 말고(예: '이름에 Web3사가 들어감 → 선도사'), **§0 전략질문·§2 카드 목표로 그 과제의 의의를 읽어** 배정한다. 판정 2층: ⓐ organic **시장/사업영역 *연구***('무엇으로/어디로 나가나')와 클라이언트 직결 **진출 *딜***('어떻게 나가나')를 가른다. ⓑ 딜은 다시 **성사단계**로 — 이미 **집행(executed)=본사 자산** vs **검토 중(prospective)=진출딜 검토**. *실사례: 크립토사 JV 실사를 이름만 보고 '선도사 벤치'에 넣었다가, 의의=검토 중 진출 딜로 재배치.* cf. [[causal-why-over-surface-verdict]] · [[organize-by-user-taxonomy]]

### B-2. 워크플로우
1. **현 지도 통독** — `work/consulting/_지식지도_KNOWLEDGE_MAP.md`를 읽어 §0 그룹·§1 레터(현재 마지막 레터)·기존 폴더 파악. (지도가 없으면 §형식 스펙대로 신설.)
2. **중복 확인** — 스캐너로 같은 과제의 기존 폴더가 없는지 확인(있으면 그 폴더 반환, 생성 안 함):
   ```
   python3 <REPO>/.claude/skills/_shared/scan_folders.py --root <REPO>/work/consulting
   ```
3. **위치·이름 결정** — ① §0 전략질문 그룹 배정 ② §1 **다음 레터**(현재 마지막 +1) ③ 폴더명(관례) ④ 산출물 파일명 스템(`research_<task>_v1_0`). **★ 배치 정확성(그동안 오배치가 잦았던 지점 — 반드시 검증): 과제의 의의(어느 전략 질문에 답하나)를 §0 전략질문·§2 인접 카드와 대조해 그룹을 확정**한다. 폴더명·표면어로 넣지 말고, 헷갈리면 *가장 가까운 기존 워크스트림*을 찾아 같은 그룹에 넣을지 판단(예: 은행 해외법인 개요 → 지역 벤치가 아니라 그룹 본사 역량). cf. 원칙5·[[classify-workstream-by-significance]]
4. **생성** — 폴더 + `CHANGELOG.md`(1줄: 생성일·목표·레터) + 빈 `_raw_sources/`. 임시·fetch 파일은 리포 루트가 아니라 이 폴더의 `_raw_sources/`에만. cf. [[fetch-files-never-repo-root]]
5. **지도 스텁 등록** — §1 스텁 행(`현행 산출물 = (착수 — 빌드 전)` · 🟢) + §2 스텁 카드(**목표만**; 핵심·이어받기 = `(빌드 후 갱신)`) + §0 전략질문 그룹 표에 레터 추가. 헤더 "최종 갱신: YYYY-MM-DD" + `_지식지도_CHANGELOG.md` 1줄. **목표 외 핵심·인사이트 추측 금지**(빌드 후 update가 폴더 실제 파일을 읽고 채운다). cf. [[analysis-must-be-reference-grounded]]
6. **핸드오프** — 결정된 *폴더경로·파일명·목표*를 **그 작업을 맡은 스킬**에 넘긴다(예: "`work/consulting/<폴더>/`에 `research_<task>_v1_0.xlsx`로 research-organizer 빌드"). 본 리서치/빌드·검증은 여기서 하지 않는다.
7. **게이트** — `SG form/judge knowledge-map start …` → **GATE PASS** 후에야 생성 결과·핸드오프 제시.

## C. 지도 수정 경로 (update — 델타 갱신)

### C-원칙 (먼저 읽기)

1. **지도는 포인터다.** 셀은 1~2줄로 얇게. **깊이(근거·버전수치·인사이트)는 폴더의 `CHANGELOG.md`·마스터 `.md`·`HANDOFF`에** 둔다 — 지도에 옮겨 적지 않는다.
2. **자동 재생성 금지 · 델타만 반영.** §0 전략질문 매핑, §2 카드의 "핵심(인사이트)"·"이어받기", 상태 이모지는 **사람이 큐레이션한 지식**이라 파일 목록으로 재생성하면 소실된다. 스캐너로 *바뀐 것만* 찾아 해당 셀/카드를 갱신하고 나머지는 그대로 둔다.
3. **사용자 택사노미 고정.** 워크스트림 레터링(A~AE…)이 골격이고, 그룹축은 **6 전략질문**(§0: 무엇으로/어떻게/무엇을 레버리지/어디로/전문가/독립). **임의 프레임(렌즈1/2 등) 발명 금지.** 새 폴더는 적절한 그룹에 배치하고 다음 레터 부여. cf. [[organize-by-user-taxonomy]]
4. **근거 있는 셀만.** "핵심"·"이어받기"·현행 산출물·상태는 **폴더의 실제 파일(CHANGELOG/핸드오프/마스터 .md)을 읽고** 채운다. 추측·LLM 일반지식 금지. cf. [[analysis-must-be-reference-grounded]]
5. **갱신 루틴 = 헤더 날짜 + CHANGELOG.** 변경점은 지도 본문이 아니라 `_지식지도_CHANGELOG.md`(날짜별 로그)에. 큰 개편 전엔 직전 전체본을 `_지식지도_KNOWLEDGE_MAP_v0_백업_YYMMDD.md`로 백업. cf. [[build-routine-changelog-only]] · [[deliverable-versioning]]
6. **갱신은 그 작업을 한 세션에서.** 지도 갱신은 가능하면 *그 변경을 만든 세션/터미널*에서 **맥락이 살아있을 때** 수행한다 — 핵심·이어받기·상태의 근거가 머릿속에 있는 그 자리가 유실이 가장 적다. 콜드 세션이 폴더 파일만 보고 핵심·이어받기를 추측해 채우는 것은 지양(불가피하면 폴더 CHANGELOG/핸드오프를 직접 읽고 근거를 확인한 부분만). 스캐너로 델타를 *식별*하는 것까지는 어느 세션에서나 OK.

### C-워크플로우

1. **현 지도 통독** — `work/consulting/_지식지도_KNOWLEDGE_MAP.md`를 읽어 §0~§3·카드·상태 파악.
2. **스캔** — 폴더별 *최신 산출물(버전키)·산출물 수·CHANGELOG 유무·핸드오프*가 나온다(스킬·아카이브·`_raw_sources` 제외). **카테고리 중첩(`N_…` 부모폴더) 자동 인식** — 그 안 워크스트림을 2단계로 열거하고 헤더에 `[카테고리]` 병기.
   ```
   python3 <REPO>/.claude/skills/_shared/scan_folders.py --root <REPO>/work/consulting
   ```
   (`--json`으로 기계 판독 출력.)
3. **대조(reconcile) → 델타 식별**:
   - **신규 폴더**: 지도 §1·§2에 없는 폴더 → 전략질문 그룹 배정 + 다음 레터 + 카드 신설. (start로 만든 폴더면 이미 스텁이 있으니 핵심·이어받기만 채운다.)
   - **버전 상승**: 스캐너 newest가 지도의 "현행 산출물"보다 높은 버전 → 셀 갱신.
   - **상태 변화**: 🟢↔✅↔⏸ (전달/완료·보류) — 폴더 CHANGELOG·전달본 유무로 판단.
   - **신규 핸드오프/마스터 .md**: 카드 "이어받기" 갱신.
4. **델타만 반영** — 해당 §1 행 + §2 카드만 수정. "핵심"·"이어받기"를 새로 쓰거나 바꿀 땐 **그 폴더의 CHANGELOG/핸드오프/마스터 .md를 직접 읽고** 1~2줄로 압축(자족적으로 — 단위·맥락 포함). 손대지 않은 카드·서술은 그대로 보존.
5. **헤더·CHANGELOG 갱신** — 헤더 "최종 갱신: YYYY-MM-DD" 갱신. `_지식지도_CHANGELOG.md`에 날짜별 변경 로그 1블록 추가(무엇을 왜 바꿨는지).
6. (선택) **백업** — 구조를 크게 바꿨으면 직전본을 `_지식지도_KNOWLEDGE_MAP_v0_백업_YYMMDD.md`로.

### C-bis. 산출물 없는 단건성 채팅 리서치 → §2-bis 등재 (update 하위 케이스)

> 폴더·산출물 파일 없이 *채팅에서만* 끝난 의미있는 리서치(일회성 시장/경쟁/팩트 조사 등)를 휘발 막아 지도에 **요약 포인터**로만 남길 때. 워크스트림(폴더 과제)이 아니므로 §1/§2 카드·레터를 만들지 않고 **§2-bis 요약 인덱스에 1항목**만 등재한다. 보통 `/knowledge-map`만(설명 없이) 호출되므로 *직전 대화 맥락*으로 후보를 인지한다.

1. **후보 판정(맥락)** — 직전 대화가 ① 산출물(.md/xlsx/docx)·폴더가 *생기지 않은* + ② 의미있는(결론·수치가 있는) 리서치인가? (단순 잡담·사소한 단발 조회는 제외.)
2. **한 줄 확인** — 후보면 **"이 리서치를 §2-bis에 요약 등재할까요?" 한 줄만 묻고** OK일 때만 진행(자동 등재 안 함).
3. **현 지도 통독 + 스캔** — C-워크플로우 1·2와 동일(미반영 폴더 델타가 따로 있는지도 확인 — 이 등재 자체는 폴더 델타가 아니라 *수동 큐레이션 추가*).
4. **§2-bis에 1항목 등재** — `## 2-bis` 섹션(없으면 §2와 §3 사이에 신설)에 `- **[권역/주제] 한 줄 제목** (YYYY-MM-DD 채팅·산출물 없음): 핵심 결론·수치 1~3문장 + **인사이트** + 인접 워크스트림 링크(A~…).` 자족적으로(단위·맥락 포함).
5. **레터 제외** — 워크스트림 아님 → **§0 그룹/§1/§2 레터 부여 안 함**.
6. **헤더·CHANGELOG·게이트** — 헤더 "최종 갱신" 날짜 + `_지식지도_CHANGELOG.md` 1줄 + update 게이트 그대로(`SG form/judge knowledge-map update …` → GATE PASS 후 제시).

## 형식 스펙 (지도 구조 — 두 경로 공통)

- **헤더**: 목적 1줄 · 최종 갱신일·CHANGELOG/백업 포인터 · 공통 규칙 · 상태 범례(🟢 진행 / ✅ 전달·완료 / ⏸ 보류 / 🔁 상시 누적).
- **§0 프로젝트 개요**: 고객사·목표 1줄 + **"전략질문(6) → 워크스트림"** 매핑 표.
- **§1 마스터 인덱스** 표: `# | 폴더 | 주제 | 현행 산출물 | 상태` (셀 1줄). 전달본(`_전달본`)=클라이언트 정본 표기. **start 스텁 행**: 현행 산출물=`(착수 — 빌드 전)`·상태 🟢.
- **§2 프로젝트 카드** (레터별): 고정 필드 **목표 / 꺼낼 파일 / 핵심 / 이어받기·인접**. 깊은 근거·수치는 폴더로. **start 스텁 카드**: 목표만 기입, 핵심·이어받기는 `(빌드 후 갱신)`.
- **§2-bis 단건성 채팅 리서치**(선택): 폴더·산출물 없는 ad-hoc 리서치 요약 인덱스 — §2와 §3 사이·항목당 1줄(`- **제목** (날짜·산출물 없음): 결론+인사이트+인접`)·레터 미부여.
- **§3 공통**: 방법론=스킬 매핑 · 설치/보호 스킬 · 공통 1차 소스 풀 · 컨벤션(버전 `vN_M`·`_raw_sources`·CHANGELOG·핸드오프·검증).
