# Source Consistency Check (출처 정합성 검증)

> ### ▶ 단계 게이트 (빠른 바닥은 인라인, 빡빡한 정합 심판은 비동기 gate-audit)
> hook 차단 환경의 강제 레버. 헬퍼 `SG` = `python3 <REPO>/.claude/skills/_stepgate/stepgate.py`.
> **★ 동시 작업 격리** — 이 워크플로의 *모든* SG 호출(init·form·judge·resolve·clear)에 **같은 `dir=<과제폴더 절대경로>`**를 붙인다(다른 과제=다른 폴더→자동 격리, 같은 폴더 다중 산출물은 `deliverable=`로 구분). 누락 시 form↔judge·init↔judge 키가 갈려 오작동.
> 워크플로 시작 시 `SG init research-source-check dir=<과제폴더>`. **① 산출 직후(바닥)**: `SG form research-source-check verdict dir=<과제폴더>` → 산출물 열고 **정직히** 답(합격 기준 비공개·**표현이 회차마다 뒤집히니 지난 답을 재사용하지 말고 이번 문구를 그대로 읽고 답할 것**) → `SG judge research-source-check verdict <id>=<값> … deliverable=<리포트.md 절대경로> dir=<과제폴더>`. **GATE PASS**면 바닥 통과 → FIRE 블록으로 **백그라운드 감사 에이전트(general-purpose) 발사·즉시 다음 작업**.
> **② 보고 직전(해소)**: `SG resolve research-source-check deliverable=<리포트.md> dir=<과제폴더>` → **RESOLVE PASS 아니면 종료/‘done’ 금지**(HOLD=동기 드레인·FAIL=수정·재감사). 종료 시 `SG clear research-source-check dir=<과제폴더>`.
> 체크포인트: **verdict**(접속성만 하고 내용 정합 3단계를 건너뛰는 최빈 누락 차단). 봉인 루브릭(rubrics/) 직접 열람 금지(감사됨). 상세: `skill-maintainer` 〈단계 게이트 프로토콜〉.
> `<REPO>` = 이 저장소를 클론한 **절대경로**(문서상 표기). `dir=`·`deliverable=`은 절대경로여야 하므로 호출할 때 실제 경로로 치환한다.

완성된 리서치 산출물의 **출처를 감리**하는 검토자 측 워크플로우. 두 가지를 분리해 검증한다: **① 링크 접속성**(살아있는가) **② 내용 일치**(인용 수치·verbatim이 출처 원문과 맞는가).

**입력 포맷은 무관.** `.md`뿐 아니라 `.docx`·`.xlsx`·`.pptx`·`PDF`·붙여넣은 텍스트·URL 목록 어떤 형태든 받는다. 검증 로직(2~5단계)은 동일하고, **포맷마다 다른 것은 1단계(URL·인용 추출)뿐**이다 — 1단계에서 포맷에 맞게 뽑아낸 뒤 같은 파이프라인으로 흘려보낸다.

**이 SKILL이 완결된 정본 절차다.** 핵심 원칙(아래)·단계(1~5)·출처 유형별 fetch 요령(3단계)·신규 실패 패턴(§10)을 모두 담아 **단독 실행**한다. (과거 별도 가이드 `출처정합성_검토_워크플로우_가이드.md`는 더 이상 사용하지 않음 — 필요한 내용은 본 스킬에 통합됨.)

**언제 쓰나:** 이미 작성된 산출물(타 터미널/과거 산출물, 어떤 포맷이든)의 링크·인용을 점검할 때. **쓰지 말 것:** 리서치를 새로 *작성*할 때 → `research-verified`(작성자 측 검증 게이트). 둘은 상보적(작성자 게이트 vs 검토자 감리).

## ★★ 종료 게이트 (STOP — 전 절차 완료·증빙 전 이 스킬 종료 금지) ★★

**이 스킬은 가장 중요한 감리 스킬이며, 어느 한 절차라도 누락되면 "검증했다"는 거짓 안심만 남고 오류가 그대로 통과한다.** 따라서 아래 전 단계를 *수행하고 증빙*하기 전에는 종료·"완료" 선언 금지(못 채우는 칸이 있으면 미완료 → 그 단계로 복귀). **★ 최빈 누락 = 2단계(접속성)만 하고 3단계(내용 정합)를 건너뛰는 것 — 접속성 점검은 검증의 절반도 아니다. 이 스킬의 핵심은 ② 내용 일치(3단계)다.**

**종료 시 반드시 아래 '완료 ledger'를 채워 제시한다:**

| 단계 | 수행 | 증빙(숫자/산출) |
|---|---|---|
| 1. 추출(URL+클레임, 포맷별) | ☐ | 고유 URL n건·클레임 m건 |
| 1-bis. 미인용(무출처) 주장 식별 | ☐ | 무출처 load-bearing 주장 N건 (🟡 출처필요 / [분석]·자체산출 라벨 / 자명 면제) |
| 2. 접속성(curl 배치·봇차단 재시도) | ☐ | 200/봇차단(사람가능)/죽은링크 분류 — 죽은링크 수 |
| **3. 내용 정합(병렬 에이전트 fan-out·verbatim 대조)** | ☐ | 그룹 수 + 클레임별 MATCH/MISMATCH/UNVERIFIABLE 집계 |
| 3-bis. 정형 수치 재대조(해당 시) | ☐ / N-A | 셀단위 PASS/FAIL·단위환산 |
| §10 실패패턴 점검 | ☐ | 문서번호 swap·SEC filer·보도자료≠본문·시점 drift·자체산출 수치·pertinence/coherence·범주 라벨 등 점검 결과 |
| 4. 심각도 분류 | ☐ | 🟡 수정권고 / 🔵 보류 / ⚪ 경미 건수 |
| 5. 산출물(교정 지시서·검증메모·판정표) | ☐ | 파일/표 + 임시 다운로드 정리 |
| 자가 점검(맨 아래 리스트) 통과 | ☐ | 전 항목 ✓ |

**+ 반드시 한 줄로 명시: "MISMATCH(틀린 수치) N건"** (0이면 "0건"이라고 — 과장·축소·생략 금지).

> ⚠️ 2단계(접속성)만 하고 멈췄다면 *이 스킬을 수행하지 않은 것*이다. 반드시 3단계(내용 정합)까지 완료하고 위 ledger로 증빙한다. cf. 메모리 [[source-check-must-complete-all]]·[[direct-invoke-trigger]].

## 핵심 원칙 (검증 내내 적용)

1. **2단계 분리.** 접속성부터 끝내고 내용 검증으로.
2. **HTTP 에러코드 ≠ 죽은 링크.** 403/500/000은 대개 봇 차단 → 브라우저 헤더로 재확인. **DNS 실패라야 진짜 사망.**
3. **3값 판정.** 클레임마다 `MATCH` / `MISMATCH` / `UNVERIFIABLE(이유)`. "확인 못 함"과 "틀림"을 절대 섞지 않는다.
4. **PDF는 추출해서 대조.** 이 PC엔 `pypdf` 설치됨 → PDF load-bearing 인용은 보류가 아니라 **verbatim 재대조 대상**(아래 2-3). 스캔 이미지 PDF만 UNVERIFIABLE.
5. **귀속·맥락도 검증.** 숫자가 맞아도 "그 출처가 그 사실을 말하는가", 인용 문구가 "그 주장의 맥락"에 있는가. verbatim은 **어순·연결어까지** 원문과 대조.
6. **검색 요약(WebSearch summary) ≠ 출처.** 수치도 1차 원문으로 추적. 목표 vs 실측·기간(3Q/연간)·기준연도 라벨 분리.
7. **단일 미수록을 즉시 MISMATCH로 올리지 말 것 — 판정은 가역적.** 출처 1개에 값이 없으면 1차 원자료를 1회 더 찾아 `MISMATCH(모순)`와 `귀속 보강(값은 맞고 출처만 교체)`을 가른다.
8. **페이월·구독자전용 필터링.** 200이어도 로그인 게이트면 독자 확인 불가 → 개방형 동등 출처 권장, 접속성 단계에서 함께 표시.

## 단계

### 1. 추출 (포맷별 — 유일하게 포맷에 의존하는 단계)
목표는 **(a) 모든 출처 URL**(중복 제거) **+ (b) 각 URL/인용에 매달린 본문 클레임**(수치·verbatim)을 뽑아 `id|url` + 클레임 목록으로 만드는 것. **하이퍼링크가 표시 텍스트 뒤에 숨어 있을 수 있으니**(docx/xlsx/pptx) 본문 텍스트만 보지 말고 **링크 타깃을 별도 추출**한다. 포맷별:

- **`.md` / `.txt` / 붙여넣은 텍스트 / 채팅:** Read 후 URL 정규식 추출 `https?://[^\s)\]"'<>]+`. 마크다운 `[표시](url)`·각주 모두 포함.
- **URL 목록만 준 경우:** 그대로 사용(클레임은 사용자에게 무엇을 대조할지 확인).
- **`.docx` (python-docx):** 본문 텍스트 + **하이퍼링크 rels 타깃**을 함께 추출.
  ```python
  from docx import Document
  d = Document(r"<path>")
  for p in d.paragraphs:           # 본문(인용/클레임)
      if p.text.strip(): print("T|", p.text)
  for rid, rel in d.part.rels.items():   # 하이퍼링크 URL
      if "hyperlink" in rel.reltype: print("U|", rel._target)
  # 표 안 링크도 누락 말 것: 각 table.rows→cells→paragraphs 동일 처리,
  # 표 셀 하이퍼링크는 그 셀이 속한 part.rels에 들어감
  ```
  (research-docx 산출물은 본문 `[R1]` + 표 안 라벨에 클릭 하이퍼링크가 박혀 있음.)
- **`.xlsx` (openpyxl):** 셀 값 + `cell.hyperlink.target`. research-organizer 산출물은 **오른쪽 출처 열**에 태그·링크가 모임.
  ```python
  import openpyxl
  wb = openpyxl.load_workbook(r"<path>")
  for ws in wb.worksheets:
      for row in ws.iter_rows():
          for c in row:
              if c.hyperlink: print("U|", ws.title, c.coordinate, c.hyperlink.target, "|", c.value)
  ```
- **`.pptx` (python-pptx):** run 텍스트 + `run.hyperlink.address`(슬라이드 번호와 함께).
  ```python
  from pptx import Presentation
  for i, s in enumerate(Presentation(r"<path>").slides, 1):
      for sh in s.shapes:
          if sh.has_text_frame:
              for para in sh.text_frame.paragraphs:
                  for r in para.runs:
                      if r.hyperlink and r.hyperlink.address: print("U|", i, r.text, r.hyperlink.address)
  # 표(sh.has_table)·노트(s.notes_slide) 안 링크도 점검
  ```
- **PDF (pypdf):** 본문은 `extract_text()`(아래 2-3), 링크는 annotation `/A`→`/URI`.
  ```python
  import pypdf
  r = pypdf.PdfReader(r"<path>")
  for pg in r.pages:
      for a in (pg.get("/Annots") or []):
          o = a.get_object();  uri = (o.get("/A") or {}).get("/URI")
          if uri: print("U|", uri)
  ```
- **추출 도구 부재/실패 시:** 해당 포맷을 직접 Read(가능하면) 하거나 사용자에게 텍스트/URL 목록 export 요청. python 패키지 없으면 `python -m pip install python-docx openpyxl python-pptx pypdf`.

> 산출물의 **위치 좌표를 함께 기록**(md=인용ID·라인, docx=문단/표, xlsx=시트!셀, pptx=슬라이드#) — 5단계 교정 지시서에서 "어디를 고쳐라"를 정확히 가리키기 위함.

### 1-bis. 미인용·미링크 load-bearing 주장 식별 ★ (출처가 마땅한데 *없거나*, 출처를 *지명했는데 링크가 빠진* 것)
단계 1이 *달린* 출처를 뽑았다면, 여기서는 **출처가 마땅한데 어떤 인용도 안 달린 load-bearing 주장**을 전수 식별한다. 이것은 '귀속'(틀린 출처)·'pertinence'(약한 뒷받침)와 다른 ***무출처* 누락**이며, 인용된 것만 검증하면 그대로 통과하는 사각지대다(사용자 지적: "출처 표시가 있어야 하는데 없는 부분 검토").
- **대상(load-bearing):** 수치·통계·날짜·법령명·"세계최초/최대/유일" 등 한정자·순위·비교 우열·평가/단정.
- **판정(4분류):** (a) **사실 주장인데 무출처 → 🟡 '출처 표시 필요'**(1차 찾아 부착, 못 대면 〈한계〉 강등) / **(a-bis) 출처를 프로즈로 *지명*했으나(예 "○○에 따르면"·"△△ 보도") 클릭 링크가 없음(named-source-without-link) → 🟡 *링크 부착 필수*** — 본문 미검증·봇차단·페이월이어도 *링크는 반드시 제공*하고, '미검증/한계'라는 이유로 링크를 생략하지 말 것(★ 이번 세션 실패: '한경비즈니스 보도'라 써놓고 URL 없이 통과). / (b) [분석]·자체산출이면 → **`[분석]`/`자체 산출` 라벨**로 명시(출처 대신 도출근거) / (c) 자명·정의성 진술 → 면제.
- **포맷별 식별:** xlsx = 수치·단정이 있는데 *그 행/섹션에 hyperlink 0* / md·docx = load-bearing 문장 끝에 `[R#]`(링크) 없음 / pptx = 같은 shape·슬라이드에 출처 run 없음.
- (선택·기계화) **xlsx 휴리스틱:** 수치/단정 정규식 매칭 셀인데 같은 행·근접 셀 hyperlink 0 → '미인용 후보' 출력 → 사람 판정(research-organizer grep 스윕과 짝).
- 산출: *미인용 주장 목록*(위치 좌표 + (a)/(b)/(c) 판정)을 4단계 심각도·5단계 교정 지시서에 합류.

### 2. 링크 접속성 (curl)

**2-1 기본 배치** — 상태코드만(`-o NUL`):
```powershell
$ua = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/123.0 Safari/537.36"
$urls = @("M1|https://...","M2|https://...")   # id|url
foreach ($e in $urls) { $p=$e.Split("|"); $id=$p[0]; $u=$p[1]
  $code = & curl.exe -s -o NUL -L --connect-timeout 15 --max-time 40 -A $ua -w "%{http_code}" $u
  Write-Output ("{0,-16} {1}  {2}" -f $id,$code,$u) }
```
- 툴 타임아웃 넉넉히(`600000`). 30~40개면 2덩이로 분할.

**2-2 봇차단 재시도 (403/500/000 전용)** — 전체 브라우저 헤더 세트. ⚠️ **`--http2` 절대 금지(이 PC libcurl exit 2)**:
```powershell
& curl.exe -s -o NUL -L --compressed --connect-timeout 20 --max-time 50 -A $ua `
  -H "Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,*/*;q=0.8" `
  -H "Accept-Language: en-US,en;q=0.9" `
  -H "Sec-Fetch-Dest: document" -H "Sec-Fetch-Mode: navigate" -H "Sec-Fetch-Site: none" `
  -H "Upgrade-Insecure-Requests: 1" -w "%{http_code}" $u
```
- **SEC.gov(`sec.gov/...`)는 이름·이메일 UA 필수**: `-A "Operator <email>"`.
- 그래도 403 지속이면 응답 헤더 확인(`-I`): `Cf-Mitigated: challenge`/`Server: cloudflare`면 **Cloudflare 봇챌린지 = 사람 접속 가능(✅, 비고: 자동요청 차단)**. DNS 실패라야 ❌.

**2-3 판정 기준**

| 코드 | 판정 |
|---|---|
| 200 / 30x→200 | ✅ 접속 가능 |
| 403/500/000 (브라우저헤더로 200) | ✅ (비고: 자동요청 차단) |
| 403 + `Cf-Mitigated: challenge` | ✅ 봇차단(사람 가능) |
| 200 (본문 구독자 전용) | ⚠️ 접속○ 내용✗ → 개방형 대체 권장 |
| 200 (라이브 SPA·인용값 미표시/시점 상이) | ⚠️ 토픽 서브페이지+기준일·정적 리포트 병기 권장 |
| DNS 실패 / 영구 404 | ❌ 링크 교체 |

⚠️ **200 ≠ 올바른 출처.** 그 페이지가 실제 그 데이터를 담는지는 3단계에서.

### 3. 내용 정합성 (병렬 에이전트 fan-out)

> **★ raw를 이미 로컬에 확보했으면 에이전트 fan-out 말고 메인에서 직접 grep.** 작성 단계에서 출처 원문을 이미 curl로 `_raw_sources\`에 받아둔 경우(예: `research-verified`로 갓 산출한 직후 감리), 에이전트로 *재fetch하지 말고* 메인이 그 raw를 직접 grep해 verbatim 대조한다 — 결정적이고 더 신뢰(에이전트 fetch는 샌드박스). 즉 **3-bis의 '로컬 결정적 재대조'를 정형 수치뿐 아니라 *웹 서술형 출처*에도 동일 적용**. 에이전트 fan-out은 *raw가 없어 새로 가져와야 할 때*의 병렬 fetch 수단이다.
>
> **★ grep '문자열 존재'는 *맥락 대조가 아니다*(내용정합의 최빈 반쪽 실패).** 같은 숫자·문구가 *다른 맥락*(SVG 좌표·이미지 치수·타 지표·타 종목수)에서 나올 수 있으니, 매 인용을 **surrounding context(앞뒤 1~2문장)·어순으로 대조**하고 *무엇의 값인지* 지표 맥락을 명시하라(숫자-only grep 오탐 = '473천'을 SVG좌표·'채권 473종목'으로 오판한 실사례). 나아가 ⓐ **자체산출/파생 수치**(비율·합계·통화환산·역산)는 원문 진술처럼 출처에 귀속하지 말고 `[자체산출]`/`[분석]` 라벨(원문엔 입력값만·그 파생값은 없음) ⓑ **pertinence** — 구체 사실(개별 품목명·세부 수치·점유율)을 *범주/개요만 있는 출처*에 귀속하지 말 것(예: overview 페이지엔 범주 라벨만 있는데 세부를 그 링크에 귀속). 이 셋은 `audit_rubrics`의 `context-not-just-grep`·`derived-value-labeled`·`pertinence-attribution` lens + 봉인 `context_matched`/`derived_unlabeled`/`pertinence_checked` observation으로 감사된다.

출처를 **성격별 5~7 그룹**으로 묶어 그룹당 `general-purpose` 에이전트 1개를 **single message로 동시 투입**(예: IOSCO PDF군 / 규제·법령 / 컨설팅(컨설팅 펌·McKinsey·OECD·PwC) / SEC EDGAR 공시 / 상업데이터·뉴스).

**에이전트 프롬프트에 반드시 포함:**
1. **검증할 클레임을 수치·verbatim 단위로 발췌**해 명시.
2. **fetch 방법:** WebFetch 먼저 → 실패 시 curl로 temp 저장 후 Read/Grep(위 2-2 패턴, SEC는 이름이메일 UA). **⚠️ WebFetch는 200을 줘도 본문을 *요약·번역*한다(silent paraphrase) — "WebFetch 성공 ≠ verbatim".** verbatim 대조(어순·연결어)는 **curl raw 본문 + grep**으로(특히 한국어 등 비영어). 실사례: WebFetch가 기사 핵심 문장을 paraphrase·영역해 "런던←뉴욕"·베트남 문구를 왜곡 → curl 원문으로 재확정.
3. **PDF 추출:** 임시 PDF는 **검토 대상 과제 폴더의 `_raw_sources\`** 에 받는다 — ★ **repo 루트 `<REPO>\`에 쓰지 말 것**(루트에 `_tmp*`·중복 raw 폴더가 쌓이던 정크 원인). `curl.exe -o <대상폴더>\_raw_sources\_tmp.pdf <URL>` → `python -c "import pypdf; print('\n'.join(p.extract_text() for p in pypdf.PdfReader(r'<대상폴더>\_raw_sources\_tmp.pdf').pages))"` (없으면 `python -m pip install pypdf`). **단일 `_tmp.<ext>` 경로 재사용 + 작업 후 삭제.** PDF 임베드 **문서번호·정식제목·날짜 메타데이터**까지 인용과 대조.
4. **판정 형식 강제:** 클레임별 `MATCH/MISMATCH/UNVERIFIABLE` + **원문에서 찾은 실제 값/문장 verbatim 인용**.
5. **추측 금지** — 못 본 건 UNVERIFIABLE. 못 읽었다고 MISMATCH로 올리지 말 것.
6. **인용 맥락 동반 확인:** verbatim마다 앞뒤 1~2문장 surrounding context 확보, 주장 핵심어와 동반 등장하는지 + **어순·연결어 원문 대조**.

**출처 유형별 요령:** World Bank 정량지표는 JSON API(`api.worldbank.org/v2/...`)가 최정확 / OJK·CEIC는 curl+Grep / 컨설팅 펌·OECD·SEC PDF는 pypdf 추출.

### 3-bis. 수치형 산출물 ↔ 1차 원문 결정적 재대조 (정형 데이터 경로) ★
산출물이 **정형 수치표(xlsx/표)**이고 출처가 **로컬 저장된 1차 원문**(DART·SEC 공시, 통계 원자료)이면, 에이전트 fan-out(서술 대조)이 아니라 **결정적(deterministic) 재파싱 스크립트로 셀단위 숫자 비교**가 정답이다(3단계와 상보적 — 웹 서술형은 3단계, 로컬 정형 수치는 3-bis).
- **절차:** ① 1차 원문 표 재파싱 → ② **단위환산까지 수행**(천원→백만원→억원 등) → ③ 산출물 셀과 **1:1 비교** → ④ 셀별 PASS/FAIL 전수 집계.
- **단위환산 검증 = 1급 항목 ★** — 원단위→표시단위 환산이 수치 산출물의 **최빈 오류원**. 환산 누락·배수(10×) 오류를 독립 항목으로 점검(사용자가 "백만원 환산 고려해 재검증" 명시 요구한 지점).
- **★ 반올림 경로 검증 — 이중 반올림 포착.** 표시값을 1차 원값과 대조할 때, 원값을 *full-precision(소수 2~3자리)에서 목표 표시자리로 1회 반올림*한 값과 비교하라 — 중간 반올림본(2차 표·요약값)과 비교하면 이중 반올림 오류를 못 잡는다. **x.x45~x.x5 경계 표시값**은 raw→2자리→1자리 경로로 +0.1 과대가 다발하니 원값 소수 2~3자리를 확인해 단일 반올림값과 일치하는지 재계산. *실사례: WDI 성장률 5셀이 이중 반올림으로 각 +0.1 과대 — 셀단위 재대조로 포착(문자열 grep으로는 못 잡음).*
- **★ 카테고리 ≠ 정량 (분리 검증).** 거래/정형 레지스트리에서 *주체·역할·분류(카테고리 필드)*가 1차로 검증돼도 *규모·금액·일자·건수(정량 필드)*는 별도로 틀릴 수 있다(특히 발굴 에이전트가 옮긴 수치) → **역할·존재 검증으로 수치 검증을 갈음하지 말 것**; 정량 필드는 반드시 1차 원문 셀단위 재대조. (리트머스: '역할 맞음' ≠ '규모 맞음'.)
- **엔티티 유형 구분(false-positive 방지) ★** — 종속기업 요약표 vs 관계기업 요약표는 컬럼 구조·등장 위치가 달라 단순 정규식이 **관계기업 행을 종속 요약으로 오판**(BIDV 사례, 검토로 정상 판정). 재대조 시 표 종류를 명시 구분.
- **프로토타입:** `<REPO>\과제_해외법인_실적\_raw_sources\verify_numbers.py`(4사×3국×5년=60포인트 전수 60/60). 작성 측 다년도 교차정합(당기=익년 전기)은 `research-verified` §1-bis와 짝.

## 신규 실패 패턴 점검 (규제·다보고서·공시 출처에서 다발)

- **봇차단 ≠ 페이월 ≠ 죽은링크 — 자동 fetch 실패를 '유료/미확인'으로 라벨 금지 ★:** curl/WebFetch가 403·타임아웃·Cloudflare 챌린지('Just a moment'·`cf-`)에 막히고 *크롤러 UA(Googlebot/Bingbot)로도* 안 뚫리면 **봇차단**(브라우저로는 정상 열람)이지 *유료(페이월)가 아니다*. '유료/페이월'은 **200 + 로그인·구독 게이트를 실제 확인**했을 때만. 봇차단 링크는 *접근가능*으로 표기하고(자동 verbatim만 '봇차단으로 미수행') *링크는 반드시 유지*. 우회 사다리: 브라우저UA → **크롤러UA(Googlebot)** → Wayback `id_`/CDX → 개방 미러 → 안 되면 사용자에 본문 요청. *실사례: Cloudflare 챌린지를 '유료 기사'로 오기→링크 누락·'미확인' 강등.*
- **출처를 *지목*했는데 링크가 없음(named-source-without-link) ★:** "○○(특정 매체·보고서)에 따르면 …"처럼 *출처를 지명*한 load-bearing 주장은 그 출처의 **클릭 링크가 반드시 동반**돼야 한다 — 본문 미검증·봇차단·페이월이어도 링크는 제공. 지명만 하고 URL이 없으면 🟡 *출처표기 누락*(1-bis '무출처'와 구분: 여기는 '출처는 댔는데 링크만 빠진' 경우).
- **URL 착지 실패 ≠ 사실 날조 — 절단·redirect부터 재도출, 교체본은 착지 재확인 ★:** 인용 URL이 404·오(誤)착지(엉뚱한 페이지·앱 홈)여도 그 *사실*이 날조라는 뜻은 아니다 — **슬러그 절단·경로 redirect·앵커 유실**로 링크만 깨진 경우가 흔하다(사실은 실재). '날조/삭제'로 판정하기 전 **정확 URL을 재도출**(슬러그 완성·redirect 추적·verbatim 문구로 재검색)해 *사실 실재 여부*와 *단순 링크 깨짐*을 가른다 → 전자만 삭제, 후자는 🟡 'URL 교정'. **+ 교체 URL은 반드시 verbatim 착지 재확인** — 깨진 링크를 *미검증* 링크로 바꾸면 문제를 옮긴 것뿐이니, 교체본에 그 수치·문구가 실제 보이는지 fetch·grep로 확인. (핵심원칙 7 '판정은 가역적'을 URL 무결성에 적용.) *실사례: grounding 감리에서 6개 인용이 슬러그 절단으로 404였으나 사실은 실재 → 정확 URL로 교정(날조 아님), 별개로 진짜 무근거 수치 1건만 삭제.*
- **부재·단일출처 단정 챌린지 ★:** 'X 없음'·'단일 출처뿐'이라는 *부재/희소* 판정은 **쿼리 변형 소진**(동의어·사건명: 예 인수'검토'↔'설'↔'참여시도'↔'타진')을 거쳤는지 확인 — 한 표현으로 안 나온 것을 '존재하지 않음'으로 적었으면 재검색 권고(특히 작성자/사용자가 *있다고 지목한* 자료).
- **JS 렌더·페이월 뉴스 — 사용자가 '열었을 때' 보이는가 ★:** curl/grep로 본문이 안 잡혀도 브라우저는 렌더되니 *죽은 링크 아님*(에러코드≠죽은링크의 연장 — CoinDesk·블룸버그 등 JS 렌더 뉴스). 단 **클라이언트 클릭 링크는 사용자가 열었을 때 인용 내용이 실제 보이는 정적/공식 페이지**가 이상적 — JS-only/페이월 뉴스는 WebFetch(렌더 모델)로 노출 1회 확인 + 가능하면 회사 공식·정적 원문 병기. **역도 성립: 'WebSearch 요약에서 본 verbatim' ≠ '그 URL 열면 보임'** → load-bearing은 정적 원문으로 확정. (주의: *curl 미표시*를 곧 "내용 없음"으로 단정 말 것 — 브라우저·WebFetch로 교차확인.)
- **문서번호 swap ★:** 한 기관이 번호만 다른 다수 문서를 낸 경우(IOSCO PD### 등), verbatim이 맞아도 인용이 **형제 문서**에 잘못 매달릴 수 있음. 각 인용을 **PDF 임베드 문서번호(FR/##/YYYY)·제목**으로 1:1 대조(핵심어로 판별: 예 PD649='CTP' vs PD747='CASP').
- **보도자료 URL ≠ 보고서 본문:** `.../news/...NEWS###.pdf`·press release를 보고서 인용에 쓰지 말 것 → 본문 FR/PD로 교체.
- **SEC EDGAR filer ≠ 인용 회사 ★:** 제3자가 상대방 계약서를 Exhibit으로 첨부하는 경우 흔함. CIK가 인용 주체인지 표지 'NAME OF FILER'로 확인(예: "Coinbase Prime BA"의 filer가 Coinbase 아님).
- **세그먼트 vs 연결 / 10-Q 누적기간 vs 10-K 연간:** 연결 총자산을 세그먼트로 귀속 금지. 10-Q는 3M/6M/9M 누적 공존(Q2=6M), 연간은 10-K. 필링종류+기간 라벨 명시.
- **상업 리서치 수치 drift:** Statista/Mordor/Fortune류는 재발행으로 수치·지평·CAGR이 바뀜 → 현재값과 다르면 'MISMATCH'가 아니라 **'출처 갱신(구버전)'**. 인용에 확인일자 + archive 스냅샷 권장.
- **라이브 트래커(SPA) 시점·landing 이슈 ★:** rwa.xyz·DefiLlama·온체인 대시보드류는 — **(a)** 시점값이 계속 바뀜 → 인용 과거값 ≠ 현재 페이지값은 MISMATCH가 아니라 **'시점 drift'**(위 drift와 동일 처리; 인용에 **기준일·트래커명** 필수). **(b)** 앱 홈/제네릭 URL은 특정 수치 미표시 → 200이어도 그 값이 그 페이지에 없으면 🟡(**토픽 서브페이지**로 교체, 예 `app.rwa.xyz/private-credit`). SPA라 curl 값추출 어려우니 **WebFetch로 현재값 확인**. **(c)** 동일 지표가 방법론별 **3~5배**(distributed/represented/단순합) → 인용값이 어느 방법론·기준일인지 페이지에서 확인. *(예: 앱 홈 인용값이 토픽 페이지의 distributed/represented 값과 3~5배 차이.)*
- **CAGR·성장률 endpoint 대조 + 기간/기준일 swap ★:** 성장률·CAGR 인용은 **base·target 값·연도로 역산해 출처 표기와 대조** — 불일치하면 endpoint 수치나 기간(base year)이 틀린 것(MISMATCH 전에 endpoint·기간 라벨부터 점검). *실사례: DataIntelo $62.7B(2024)→$193.5B(2033) 역산 시 ~13%인데 벤더 표기 16.9% → base/기간 불일치.* 또 **비-공시 정기 출처(분기 리서치·트래커)의 기간/기준일 swap**도 점검 — 인용 수치가 실제 어느 분기/시점인지, 라벨·링크된 버전과 일치하는지(위 SEC 10-Q/연간 패턴을 SEC 외 정기 출처로 확장). *실사례: '$92.3B'은 Q1'25 값인데 'Q3'25'로 라벨·Q3 리포트에 링크.*
- **자체 산출(파생) 수치를 출처 인용처럼 단 것 ★:** 비율·비중·합계 등 *계산으로 도출한 값*(예 588÷747=약 79%)을 원문이 진술한 것처럼 출처에 귀속하면 🟡 — 원문엔 입력값만 있고 그 파생값은 본문에 없음. → **'자체 산출(=입력출처 기반)'으로 명시**하고 입력값 출처만 링크. 귀속 검증 시 '이 수치가 원문에 그대로 있나 vs 작성자가 계산했나'를 구분. *(예: 비중 78.7%가 원문엔 없고 작성자가 계산한 값.)*
- **근거-주장 적합성(pertinence)·논증 coherence ≠ verbatim 정확성 ★:** source-check는 *fidelity(출처에 그렇게 써있나)* 외에 **근거가 그 주장을 실제로 뒷받침하는지**까지 봐야 함(이게 빠지면 verbatim 정확한 인용·느슨한 사실이 그대로 통과). 두 점검을 인용·주장마다 추가: **① Pertinence** — 인용이 verbatim 정확해도 *그 칸/문장의 바로 그 주장*(특히 **유형이 다른 것**: 발행 vs 유통, 강점 A vs 강점 B, 현재 vs 미래)을 뒷받침 안 하면 🟡. '이 근거가 *이 주장*을 뒷받침하나'를 건건 물을 것(주장 유형이 명확한 칸은 근거도 같은 유형). **② Coherence** — *'A가 강점 X를 Y로 레버리지'* 식 인과·강점연결 주장은 **X가 무엇이고 *어떻게* Y가 되는지(메커니즘)가 출처로 설명**돼야 하며, 각 토큰이 느슨하게 사실이어도 **막연한 'A+B→C'(메커니즘 공백)는 grounding 미달 🟡**('말이 되는가/무엇을·어떻게가 채워졌나'를 물을 것). *(예: 유통 칸에 발행 인용을 붙임→논점 불일치로 유통 인용 교체; 막연한 'A+B→C'를 '무엇을 어떻게'의 메커니즘으로 채움.)* **③ 비교표 일관성(다대상)** — 각 행(대상)의 *해당 칸(영역) entity*를 동일 깊이로 확인하고, **한 칸(예 발행 플랫폼)을 다른 칸(유통)에 전이해 단정 금지**(발행 ≠ 유통 entity·firm별 별개). firm별로 발행/유통/수탁을 *어느 entity*가 하나 매핑되는지 점검 — *한 대상만 얕게 보면 비대칭 오류(실사례: 해외 은행 D=Kinexys 단일모델로 유통 단정 vs SC=entity별 확인 → 해외 은행 D 유통 실체 누락).* (fidelity 아닌 *논증 적합성*이라 작성자 게이트 `research-verified`와 짝.)
- **분류·범주 라벨의 적합성 — '사건 존재' 확인이 '범주 귀속' 확인이 아니다 ★:** 인용이 *사건·사례의 존재*(거래·딜·라이선스 발생)를 verbatim 정확하게 입증해도 그것이 그 항목의 **범주 라벨**(스코프 내/외, 유형 A/B, 사업 종류)까지 입증하진 않는다 → 각 분류 라벨이 **그 범주를 가르는 결정적 속성**으로 출처에서 뒷받침되는지 별도 확인(위 ① Pertinence를 *범주 판정*에 적용 — '근거가 *이 분류*를 받치나'). 본 스킬을 돌렸는데도 통과시키면 안 되는 지점: *사건은 맞으나 범주 판정의 결정 속성을 안 봐* 오분류가 통과되는 것. *실사례: 해외 증권사 C GFO-X BTC 옵션을 'OTC'로 둔 분류가 source-check를 통과 — GFO-X는 중앙청산 거래소(venue)라 OTC 아님(체결·청산 경로로 판정해야 함).* (작성자 게이트 `research-verified` §1 '결정 속성으로 분류'와 짝.) **+ 라이선스·권한 검증 확장:** 등록부 *명시 라벨* ≠ 면허 *본문 스코프* — 어떤 기능이 라벨에 없어도 룰북/약관 스코프에 포함될 수 있고(false-negative), 라벨처럼 보여도 별도 면허로 분리돼 불가일 수 있으니, *기능 유무·'근거없음' 판정 전* 면허 본문 스코프를 직접 확인(라벨만 보고 누락/오통과 금지).
