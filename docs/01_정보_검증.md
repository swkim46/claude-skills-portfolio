# AI가 추가한 설명을 검증하는 방법

학습 노트의 오류는 용어의 정의나 배경 설명처럼 자연스럽게 읽히는 문장에서도 발견됐습니다. 문장만 읽어서는 원문에서 확인한 사실인지, AI가 새로 추가한 설명인지 구분하기 어려웠습니다.

검증할 내용을 구분하기 위해 원문에서 확인한 사실과 AI가 추가한 설명에 서로 다른 표시를 붙였습니다. 출처에 접근할 수 있는지부터 해당 주장을 뒷받침하는지까지 확인하고, 확인하지 못한 내용과 틀린 내용을 구별해 기록합니다.

## 오류 유형에 따른 검증 방법

외부 출처만 검증하는 절차로는 뉴스레터에서 잘못 옮겨 적은 숫자를 확인할 수 없었습니다. 매매 판단에 쓰이는 숫자 상당수가 이 검증 대상에서 빠졌습니다. 오류가 발생하는 경로를 셋으로 나누고, 각각에 맞는 확인 절차를 마련했습니다.

| 오류가 생기는 경로 | 확인 방법 |
|---|---|
| 자료에서 숫자를 옮겨 적는 과정의 오류 | 실행할 때마다 스크립트로 노트의 모든 숫자를 자료와 대조 |
| 자료(2차 출처) 자체의 오류 | 결론에 영향을 주는 소수의 숫자를 1차 출처에서 재확인 |
| 자료 밖에서 가져온 사실의 오류 | `[AI]` 표시가 붙은 모든 문장을 출처와 대조 |

## 학습 노트: 원문에 있는 내용과 덧붙인 설명의 구분

노트의 문장을 세 종류로 구분합니다. 원문에서 근거를 확인한 문장에는 표시를 붙이지 않습니다. 원문에 없는 외부 사실이나 제도 설명에는 `[AI]`, 원인이나 의도에 대한 해석에는 `[추정]`을 붙입니다. 출처로 확인할 수 있는 `[AI]` 문장은 검증하고, 출처만으로 확정하기 어려운 `[추정]` 문장은 해석임을 표시합니다. 사실 설명과 해석을 구분하지 않으면 출처로 확인할 수 없는 해석까지 검증 대상에 섞여 들어가 검증 절차가 진행되지 않습니다. 그래서 두 종류에 서로 다른 표시를 붙였습니다. 원문에 근거가 있는 문장은 해당 뉴스레터와 대조하고, 별도 출처 검증에서는 제외합니다.

설명을 추가하기 전에 뉴스레터의 각주와 용어 설명을 먼저 확인합니다. 선별한 항목에 연결된 링크도 모두 열어 원문을 읽습니다. 원문에서 설명을 찾지 못한 경우에 AI가 설명을 작성하고 `[AI]`를 붙입니다. 원문에 있는 설명을 놓친 채 AI가 새로 작성하는 일을 줄이기 위한 순서입니다.

선별한 항목의 링크는 모두 확인해야 하므로, 항목을 지나치게 많이 고르지 않도록 하는 역할도 합니다. 링크를 열지 못했다고 기록하기 전에 스크립트와 내장 브라우저로 순서대로 접근해야 합니다. 접근을 시도하지 않은 상태가 확인 불가로 처리되지 않도록 한 절차입니다. PDF는 브라우저의 저장 대화상자에서 사용자의 클릭을 기다리는 문제가 있어 별도의 처리 방식을 마련했습니다.

교정한 문장 중에는 용어의 정의처럼 읽히는 설명이 많았습니다. 원문을 옮긴 문장보다 AI가 추가한 설명에서 오류가 발견됐습니다. 그렇다고 설명을 생략하면 사건 간 관계와 데이터 해석이 빠지므로, 필요한 설명은 작성하되 표시를 붙여 검증하도록 했습니다.

## 출처 검증 기준과 판정 결과

출처는 네 가지 기준으로 확인합니다. 접근할 수 있는지, 수치와 문구가 원문에 있는지, 이용 시점에도 유효한지, 해당 사실을 확인하기에 적절한 출처인지 검토합니다. 내용이 일치하더라도 오래된 정보이거나 신뢰하기 어려운 출처일 수 있습니다. 실제 일상 정보 검증에서도 오래된 정보와 근거가 약한 출처로 인한 오류가 자주 발견됐습니다.

판정 결과는 일치, 불일치, 시효 지남, 확인 불가의 네 가지로 구분합니다. 불일치는 내용을 교정하고, 시효가 지난 정보는 재확인 목록에 올립니다. 확인할 수 없는 내용은 이유를 각주로 남깁니다. 결과에 따라 필요한 후속 조치가 달라지므로 판정을 구분해 기록합니다.

확인 과정에서 지키는 규칙은 다음과 같습니다.

- HTTP 오류 코드만으로 링크가 삭제됐다고 판단하지 않습니다. 접속 제한, 유료 이용 조건, 자료 삭제를 구분합니다. 정상 응답을 받은 경우에도 필요한 원문이 맞는지 확인합니다.
- 원문 파일을 받아 문구를 직접 대조하는 방식을 우선합니다. 요약 도구를 거치면 표현이나 조건이 달라질 수 있기 때문입니다.
- 맥락, 적용 조건, 계산으로 얻은 값, 주장을 뒷받침하는지 여부, 분류 표시를 확인합니다. 적용 조건을 누락한 인용은 불일치로 판정합니다.
- 1차 출처는 해당 사실을 직접 발표하거나 확정한 주체의 자료입니다. 동일한 문장을 재인용한 여러 자료는 독립된 근거로 세지 않습니다.
- 불일치로 판정하기 전에 1차 원문을 다시 찾아 내용이 실제로 모순되는지, 더 적절한 출처로 바꿔야 하는지 구분합니다. 추가 근거가 확인되면 판정을 수정합니다.
- 출처가 표시되지 않은 주장도 검증합니다. 제도와 지표의 정의에서도 오류가 자주 발견됐으므로 당연히 맞는 내용으로 간주하지 않습니다.
- 확인할 문장이 적어도 검증은 수행합니다. 검증 대상이 적은 날에도 오류가 잦은 정의와 개념 설명은 남아 있기 때문입니다.
- 문장이 많으면 여러 보조 작업에 나눠 검증합니다. 각 작업에 발췌 방법과 판정 형식을 모두 전달해, 누락된 지침으로 같은 오류가 반복되지 않도록 합니다.

## 모의투자: 숫자와 시점의 확인

분석 노트의 모든 숫자를 실행할 때마다 뉴스레터, 도구 출력, 직접 확인한 1차 출처와 대조합니다. 계산한 값은 식을 함께 적고 스크립트로 다시 계산합니다. 출처를 표시하는 것만으로는 검사를 통과할 수 없습니다. 다만 이 검사는 숫자가 자료에 있는지 확인하며, 문맥에 맞게 사용됐는지까지 판정하지는 못합니다.

자료 자체의 오류까지 모두 1차 출처로 검증하려면 비용이 많이 듭니다. 따라서 값이 틀렸을 때 당일 결론이 달라질 수 있는 숫자 두세 건을 골라 1차 출처에서 재확인합니다.

각 사실에는 성립 시점, 자료 조회 시점, 노트 기록 시점을 남깁니다. 성립 시점은 사람이 입력하고 나머지는 자동으로 기록합니다. 조회 시간을 나중에 입력하면서 실제 시점과 달라지는 일을 막기 위한 방식입니다. 판단에 영향을 주는 사실의 성립 시점을 확인하지 못하면 검사를 통과할 수 없습니다.

분석에 사용하는 숫자는 실행 시작 시점에 저장한 파일 하나를 기준으로 삼습니다. 장중에 여러 번 조회한 값을 섞어 쓰면서 노트 안의 숫자가 서로 달라졌기 때문입니다. 자료가 일부라도 누락되면 다음 단계로 진행하지 않습니다. 자료에서 찾지 못한 내용은 미확인으로 기록합니다. 예수금 조회에 실패한 경우에는 0원으로 처리하지 않고 매수만 보류합니다.

뉴스레터와 공시 본문에는 매매나 설정 변경을 유도하는 문장이 섞여 있을 수 있습니다. 내용은 분석 자료로 쓰되, 본문 속 권유나 지시는 따르지 않습니다. 매매 대상 목록의 편입·제외는 코드에 정의한 규칙으로 판단합니다. 수동 승인으로 목록 갱신이 지연되거나, AI가 본문의 권유에 따라 목록을 직접 바꾸는 일을 막기 위한 구조입니다. 주문 한도 파일의 해시값은 승인 기록에 저장해 전송 직전에 대조합니다. 주문 규칙 검사는 뉴스 본문을 읽지 않으며, AI는 잔고 숫자를 수정하지 못하도록 코드의 역할을 분리했습니다.

주문번호는 접수 결과이며 체결을 의미하지 않습니다. 지정가 주문이 체결되지 않았는데 매수한 것으로 보고한 일이 있어, 이후 주문 결과를 확인하는 검사를 추가했습니다. 종결 상태를 체결, 부분 체결, 취소, 만료, 거부, 알 수 없음의 여섯 가지로 나누고 각각의 후속 처리를 정했습니다. 미체결 주문은 종결된 것으로 보지 않으며, 남아 있는 주문을 처리해야 실행을 마칠 수 있습니다.

## 검증 범위와 한계

숫자 대조는 값이 자료에 있는지 확인하지만 문맥에 맞게 사용됐는지까지 판정하지는 못합니다. 출처와 주장의 일치 여부를 판단하는 주체도 AI이며, `[추정]` 문장은 별도로 검증하지 않습니다. 매매 대상 목록을 관리하는 규칙은 본문의 권유가 주문으로 이어질 가능성을 줄이지만 완전히 차단하지는 못합니다.
