# 컨설팅 조사 — 검증은 여기서 시작했다

2026년 6월부터 컨설팅 리서치 업무에 AI를 쓰면서, 이 저장소의 다른 업무가 같이 쓰는 출처 확인, 단계 검사, 감사, 스킬 수정 절차를 만들었습니다. 제가 본 문제와 정한 기준, 세 주의 시행착오, 지금 남아 있는 세 경로의 산출물을 적었습니다. 컨설팅 스킬은 재직 중에 썼던 것이고, 실제 과제와 고객 정보는 공개하지 않습니다.

## 제가 본 문제

조사 업무에는 시간, 정확성, 깊이, 범위, 판단이 한꺼번에 걸립니다. 마감에 맞추면 깊이와 범위가 얕아지고, 범위를 넓히면 출처를 하나하나 확인할 여력이 줄어듭니다. 저는 과제마다 무엇을 포기할지 고르고 있었습니다. 과제가 여러 개 들어오면 하나하나 이해하고, 조사하고, 결과를 다시 이해하고, 정리하고, 보고하는 식이었습니다.

AI를 보조 도구로 끼워 넣는 방식으로는 이 구조가 바뀌지 않았습니다. 대화창에서 질문하고 답을 옮기는 일은 산출물을 만들고 맥락을 쌓고 스스로 검수하는 몫을 그대로 사람에게 남겼습니다. 저는 AI가 제 몫의 일을 하게 일 자체를 나누기로 했습니다. 자료를 찾고 1차로 정리하고 출처를 대조하는 일과 1차 검수는 AI가, 목표와 기준과 최종 판단은 제가 맡습니다. 맡긴 일이라도 결과가 어떤 근거에서 나왔는지는 제가 확인합니다.

그렇게 하고 나니 조사하고 정리하는 인턴 여러 명에게 보고를 받는 사람처럼 일하게 됐습니다. 실무 대신 생각할 시간이 생겼고, 생각을 더 한 만큼 이해도 깊어져서 최종 발표의 스토리라인을 쓰는 데도 기여할 수 있었습니다.

## 제가 정한 기준

첫 산출물은 초안 수준이었고 출처를 추적할 수 없었습니다. 저는 세 가지를 정했습니다.

- 내부 자료 대신 외부의 확실한 출처만 인용합니다. 출처 표시가 없는 주장은 검토 대상입니다.
- 작업 중에 붙인 표식은 산출물에서 전부 뺍니다. 검토자가 보는 문서에는 결론과 근거만 남습니다.
- 어떤 품질이 왜 부족한지를 정의한 다음 그 기준으로 피드백합니다. 값 하나를 고치는 대신 그 값을 낳은 전제와 계산 구조를 바꾸는 피드백이어야 결과물이 실제로 나아집니다.

도구는 완성한 뒤에 쓰는 게 아니라 쓰면서 완성하기로 했습니다. 반복될 유형의 일만 스킬로 만들고, 실제 결과물이 드러내는 문제를 보고 거꾸로 절차를 고칩니다.

## 세 주의 시행착오

처음 세 주는 형식과 가독성을 고치는 데 썼습니다. Excel 정리 스킬의 첫 버전은 표 틀을 고정해 두었는데, 실제 자료를 넣자 열 너비가 내용과 맞지 않아서 읽히지 않았습니다. 내용 길이에 맞춰 열을 자동으로 맞추게 고쳤고, 넓은 재무 모델을 넣자 다시 틀어져서 그 경우의 전용 처리를 더했습니다. 조사 스킬도 같은 식으로 다듬었습니다.

AI의 1차 결론을 그대로 받거나 직접 다시 조사하는 대신, 저는 AI가 무엇을 어떤 각도로 볼지를 지시했습니다. 맞다 틀리다로 끝내지 말고 왜 그런지와 무엇이 갈랐는지를 밝히게 하고, 조사 대상의 범위를 좁혀 주고, 결론을 1차 규제 원문으로 검증하게 하는 식입니다. 이 방식이 가장 적은 개입으로 가장 나은 결과를 냈습니다.

과제가 끝나면 얻은 것을 남기는 일을 과제의 한 단계로 두었습니다. 개인 교정은 메모리에, 다른 과제에도 통하는 규칙은 스킬에, 이번 과제의 결정과 이유는 변경 기록에, 산출물의 위치는 지식지도에 남깁니다. 남기지 않으면 AI는 같은 실수를 되풀이하고 저는 제가 어떤 방향으로 판단했는지 잊습니다.

시스템은 이 기준을 다음 절차로 만들었습니다. 검색 결과의 요약을 인용하지 않고 원문을 받아 과제 폴더에 저장하고, 보고서의 모든 주장을 그 원문에서 다시 찾아 대조하고, 서로 반박하는 출처가 있으면 폐기하거나 등급을 낮추고, 출처마다 등급을 붙입니다. 작성자 측 검증과 검토자 측 감리를 다른 스킬로 나눴고, 자료 흡수, 원문 확보, 발행의 세 지점에 단계 검사를 두었습니다.

## 세 경로

| 요청 | 흐름 | 결과 |
|---|---|---|
| 새 조사 질문 | 지식지도에서 같은 과제 확인 → 포함과 제외 범위 고정 → 후보 자료 탐색 → 원문 확보 → 주장마다 원문 대조와 출처 등급 → 사실과 분석을 나눈 문서 | 조사 결과 문서, 주장별 출처 목록(원문 인용과 활용 방식), 검증 메모 |
| 준비된 내용의 문서화 | 검증을 통과한 내용만 받음 → Word(출처 링크, 인용 블록, 출처 절) 또는 Excel(개요, 피라미드 요약, 출처 모음 세 시트) → 링크 열림, 금지 표현, 수식 오류, 판 번호 검사 | 검토할 수 있는 보고서와 표 |
| 녹취 텍스트 정리 | 화자 표시가 끝난 녹취와 일시, 참석자 → 참석자 명단과 대조 → 구조 초안을 제게 제시 → 확인 뒤 문서 생성 | 요약, 번호 섹션, 시사점, 용어 풀이를 갖춘 인터뷰 기록 |

공시 재무 분석은 상장사 재무제표를 모아 비율과 추세를 계산합니다. 동명 회사가 여럿이면 근거를 달아 추천한 뒤 제 확인을 받고, 분석 구조 초안도 승인을 받습니다. 전문가 답변 정리는 사전 질문 응답 메일을 응답자 전원 기준으로 한 트래커에 쌓고, 답변과 경력과 가능 시간을 지어내지 않습니다. 지식지도는 과제 폴더의 위치와 이름을 정하고 변화를 반영하되, 분류 체계는 제가 쓰던 기준을 유지하고 AI가 임의의 틀을 만들지 않습니다.

## 제가 확인하는 자리

| 자리 | 확인 내용 |
|---|---|
| 인터뷰 기록의 구조 초안 | 요약, 섹션, 시사점, 용어의 구조를 확인하거나 고친 뒤 문서 생성 |
| 공시 분석의 기업 식별과 구조 초안 | 동명 회사 선택, 분석 구조 승인 |
| 문서화의 중간 판 | 검사와 감사를 거친 판을 보고 피드백. 내용이 확정된 뒤 정식 판으로 올림 |
| 조사 범위와 출처 | 접근할 수 없는 자료의 본문 제공, 무엇을 대조할지 확인 |

조사 경로에는 산출 전 승인 단계가 따로 없습니다. 발행 전 확인은 단계 검사와 감사의 통과이고, 제 검토 의견은 원문과 차이를 다시 확인한 뒤 골라서 반영합니다. 감사 결과의 최종 확인은 AI가 실행하는 엔진 명령이고 제 승인과는 별개입니다.

## 다른 업무로의 재사용

출처 확인 방법, 단계 검사 엔진, 감사, 스킬 수정 절차는 8월 말 학습 노트와 9월 투자에서 그대로 다시 썼습니다. 업무마다 다른 것은 검사 항목과 감사 결과를 기다리는 시점입니다. 학습 노트는 발행 뒤 감사 결과를 한 번 반영하고, 투자의 주문 근거는 주문 전 판정 뒤 주문 뒤 감사를 이어 가고, 컨설팅 산출물은 최종 발행 전에 활성 감사의 통과를 확인합니다. 이 스킬들은 다른 사람도 쓸 수 있는 형태로 표준화해서 사용 가이드와 함께 소속 조직에 배포했습니다.

## 범위와 한계

이 글은 스킬 파일에 적힌 절차와 프로그램의 동작, 그리고 제가 정한 기준을 설명합니다. 컨설팅 업무의 실제 결과나 고객 성과, 사용 인원과 절감 시간은 공개하지 않거나 잰 자료가 없습니다. 출처와 주장이 맞는지는 AI가 판단하고, 스캔 이미지로만 있는 자료는 확인 불가로 둡니다. 실제 회의록, 서식 가이드, 과제 자료는 공개본에 없습니다.
