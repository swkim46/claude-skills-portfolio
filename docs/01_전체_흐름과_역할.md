# 전체 설계 — 자료를 공유하고 결과를 검토하며 스킬을 고칩니다

[포트폴리오](../README.md) / 생태계 설계 · [검증과 개선](05_검증과_개선.md)

리서치·학습·투자 스킬은 출처 확인과 결과 검토에 필요한 도구를 함께 씁니다. 과제가 끝나면 자료와 판단을 기록해 두고, 반복되는 오류는 원인을 찾아 작업 지침을 고칩니다. 이 문서는 어떤 자료를 공유하고, 누가 검토하며, 스킬을 언제 수정하는지 설명합니다.

## 업무별 입력 자료와 결과

| 업무 | 입력 자료 | 결과와 활용 |
|---|---|---|
| 리서치·보고서 | 질문, 지식지도에서 찾은 관련 과제, 원자료 | 보고서의 근거를 검토·종합. 지도 갱신을 요청하면 현재 파일과 남은 질문을 기록 |
| 학습 | 직전 노트 이후의 뉴스레터, 기존 노트와 작성 기준 | 노트를 읽고 이해. 다음 노트는 이미 설명한 내용과 새로 달라진 내용을 구분 |
| 투자 실행 | 뉴스레터·공시·시세, 지난 시나리오와 거래 기록 | 판단·주문·체결을 저장. 다음 시장 실행과 주간 평가의 입력으로 사용 |
| 투자 주간 평가 | 한 주의 거래·보류 기록, 당시 근거와 이후 시세 | 타당한 판단은 유지하고 결함이 확인된 규칙의 변경을 제안 |

학습과 투자는 같은 뉴스레터를 각자 읽습니다. 학습 스킬은 원인과 개념을 설명하는 노트를 쓰고, 투자 스킬은 확인할 사건과 대응 조건을 정합니다. 학습 노트도 투자 자료로 참조할 수 있지만 노트의 완성이 투자 실행의 선행 조건은 아닙니다. 투자 스킬은 국내·미국 시장에서 남긴 기록도 함께 읽습니다.

평일에는 학습 노트와 시장별 투자 실행을 예약하고, 토요일에는 투자 주간 평가를 예약합니다. 국내 실행은 09:30, 미국 실행은 개장 5분 뒤 시작하며 실제 주문은 조사와 검사가 끝난 뒤 전송합니다. 리서치는 과거 업무에서 과제에 맞는 스킬을 골라 사용했습니다. 실행 주기와 자료 저장 방식은 업무마다 다릅니다.

## 스킬이 함께 작동하는 방식

| 연결 | 관계 | 전달하는 것과 사용하는 시점 |
|---|---|---|
| `knowledge-map` → 리서치·문서 작성 스킬 | 과제 착수 | 과제의 목적·위치·이름을 정한 뒤 필요한 작업으로 넘김 |
| `research-verified` → `research-docx`·`research-organizer` | 조사 후 문서화 | 검증한 내용을 Word 보고서나 Excel 비교표로 작성할 때 전달 |
| `research-source-check` → 완성 문서 | 별도 출처 감리 | 문장·링크·인용을 원문과 대조하고 교정 지시서를 작성 |
| `world-study`·`trade-run` → `fact-check` | 검증 요청 | 추가한 사실이나 주문 근거의 주장·출처를 넘겨 판정 |
| `trade-run` → `life-research` | 추가 조사 | 뉴스레터에 없는 산업·기업의 판단 재료를 조사 |
| 투자 실행 → 다음 실행·`trade-feedback` | 기록 전달 | 저장한 시나리오·거래·보류 이유를 다음 판단과 토요일 평가에서 읽음 |
| 업무별 단계 검사 → `gate-audit` | 별도 AI 검토 | 산출물과 검토 대상을 전달. 결과를 기다리는 시점은 업무마다 다름 |
| 감사 기록·사용자 피드백·주간 평가 → `skill-maintainer` | 변경 근거 | 반복 유형과 개선안을 검토해 어떤 스킬·도구를 고칠지 정함 |
| `skill-maintainer` → 관련 스킬·공통 도구 | 작업 방법 변경 | 지침·도구·검사 연결을 고치고 전후 내용과 참조 관계를 확인 |
| 과제 결과·결정 기록 → `knowledge-map`·`life-map` | 호출 시 지도 갱신 | 현재 파일과 핵심 판단, 남은 질문을 변경분만 반영 |

출처 확인 방법과 단계 검사 엔진은 함께 사용하되, 업무별 조건은 해당 스킬에 둡니다. 예를 들어 학습은 원인·개념 설명이 충분한지, 투자는 주문에 쓸 근거와 실행 조건이 있는지를 확인합니다. 단계 검사는 파일과 필수 항목을 대조하고, 별도 감사는 내용을 다시 읽습니다. 검토 결과가 스킬을 곧바로 자동 수정하지는 않습니다.

아래 구성은 2026년 10월 20일 기준입니다.

## 1. 지난 자료의 조사 목적부터 확인합니다

새 과제를 시작할 때 관련 자료를 찾습니다. 이를 위해 과제별 목적·자료 위치·핵심 판단·남은 질문을 모아 둔 안내문을 만들었고, 이를 **지식지도**라고 부릅니다. 지도에서 관련 과제를 찾으면 보고서뿐 아니라 당시 조사 목적과 아직 답하지 못한 질문도 확인할 수 있어야 합니다. 파일명에 같은 산업 이름이 있다는 이유만으로 자료를 한 과제에 모으면 서로 다른 질문이 뒤섞일 수 있습니다.

`knowledge-map`이 이 지도를 관리합니다. 새 과제를 시작할 때 조사 목적에 맞춰 폴더와 이름을 정하고, 사용할 자료와 경로를 조사 스킬에 알려줍니다. 관련 과제의 원자료를 참고하더라도 새 결과물은 해당 과제의 폴더에 저장합니다.

현재 지침은 지도에 다음 내용을 남기도록 합니다.

| 항목 | 다음 작업이 알아야 할 것 |
|---|---|
| 목적 | 어떤 질문에 답하기 위해 조사했는가 |
| 현재 자료 | 지금 사용할 결과물은 무엇이고 어디에 있는가 |
| 핵심 | 어디까지 판단했고 어떤 조건을 전제로 했는가 |
| 이어받기 | 무엇이 남았고 다음에 무엇부터 확인해야 하는가 |

지도에 모든 인용과 분석을 복사하면 원본이 바뀔 때마다 지도도 고쳐야 합니다. 지도에는 필요한 파일을 고를 만큼만 남기고, 세부 근거·계산·변경 이유는 원본과 과제별 기록에 둡니다. 다음 조사는 지난 보고서를 사실의 출처로 인용하지 않고, 보고서가 가리키는 외부 원문을 다시 확인합니다.

**지도 갱신은 `knowledge-map`을 호출했을 때 수행합니다.** 조사 종료 때마다 자동으로 갱신하지 않습니다. 탐색 도구가 바뀐 폴더와 파일을 찾으면, AI가 지도의 해당 항목을 확인해 수정합니다. 파일 목록으로 지도를 다시 만들면 사람이 정리한 판단과 남은 질문이 사라질 수 있어, 변경된 부분만 갱신합니다.

개인 프로젝트는 `life-map`이 담당합니다. 두 스킬은 같은 폴더 탐색 도구를 사용하지만 업무 과제의 분류 체계를 개인 프로젝트에 그대로 적용하지는 않습니다. 이 포트폴리오의 투자 기록은 별도의 데이터베이스, 학습 노트는 날짜별 파일로 관리합니다. 지도에는 이 기록들이 어디에 있는지 정리합니다.

## 2. 결론의 근거를 확인할 수 있게 작성합니다

업무 가이드북에는 AI가 조사와 1차 검수를 마치고, 사람이 결과를 판단하도록 적었습니다. 사람이 검토하려면 결론의 근거와 가정을 알 수 있어야 합니다. 보고서에는 주장·근거·분석을, 계산표에는 기초 값과 중간 계산을 남깁니다. [실제 가이드북 발췌](../examples/실제_기록_발췌.md#research)

조사할 때는 주장과 원문을 대조하고, 문서를 만든 뒤에는 본문과 출처를 다시 비교해 고칠 위치와 근거를 적습니다. 각각 조사 스킬 `research-verified`와 완성 문서의 출처 감리 스킬 `research-source-check`가 맡습니다. Word 보고서 작성은 `research-docx`, 비교·계산표 작성은 `research-organizer`의 역할입니다. 인터뷰 기록은 화자를 표시한 녹취에서 시작하고, 제가 구조 초안을 확인한 뒤 문서화합니다.

출처 대조 외에 작성한 AI와 다른 AI가 결과물을 다시 읽는 절차도 두었습니다. 이 별도 검토를 감사라고 부르며, `gate-audit`이 맡습니다. 주장을 원문이 뒷받침하는지뿐 아니라 요청한 내용과 작성 기준을 지켰는지도 살핍니다. 인용에서 한정어를 빠뜨리거나 확인한 사실과 해석을 구분하지 않으면 결과물을 고쳐야 합니다.

학습과 투자에서는 원문 대조와 판정을 맡긴 출처 검증 스킬 `fact-check`를 공통으로 사용합니다. 판정의 품질 기준은 검증 스킬에 두고, 학습은 설명의 충분함을, 투자는 판단과 주문 조건을 각자 확인합니다. 검토를 기다리는 시점도 다릅니다. [공통 기준과 업무별 감사 시점](05_검증과_개선.md#shared-criteria)

## 3. 오류가 반복되면 작업 지침을 고칩니다

학습 노트에서 원인과 개념의 설명이 빠지는 문제가 반복됐습니다. 저는 해당 문장만 고치지 말고 원인을 찾아 스킬을 고치도록 요구했습니다. AI는 검사 질문을 늘리는 데서 더 나아가, 글을 쓰기 전에 사실·원인·개념·예외를 준비하는 순서까지 바꿨습니다. [학습 노트의 작성 순서를 바꾼 과정](05_검증과_개선.md#writing-order)

현재 노트의 오류는 그 노트에서 고칩니다. 오류가 반복되면 작성 지침과 도구도 검토합니다.

`gate-audit`은 문제로 본 문장을 인용하고 유형을 기록합니다. 프로그램이 유형별 기록을 보존해 서로 다른 실행에서 반복됐는지 확인할 수 있게 합니다. 감사 AI가 스킬을 즉시 고치지는 않습니다. 작업 방법을 고치는 별도 절차에서 원인과 기존 지침을 읽고 수정할 위치를 정합니다. 이 역할을 맡긴 스킬이 `skill-maintainer`입니다.

여기서 이번 과제에만 해당하는 사실은 과제 기록에 남기고, 다른 과제에도 쓸 방법은 스킬에 반영합니다. 판정표를 잘못 쓰는 문제라면 호출한 업무마다 기준을 복제하기보다 판정표를 만드는 공통 스킬을 고칩니다. 설명 준비가 부족했다면 검사 질문을 추가하는 것만으로 충분한지 살피고 작성 순서도 바꿉니다.

스킬의 이름이나 경로를 바꾸면, 그 이름으로 스킬을 부르던 지침과 검사 파일도 확인해야 합니다. 실제로 개인 프로젝트용 스킬의 이름을 `life-map`으로 바꾸면서 검사 파일의 참조를 고치지 않아 검사가 작동하지 않았습니다. 이후 유지보수 절차에서 참조 관계도 확인하도록 했습니다. [반복 오류를 수정으로 연결한 실제 사례](05_검증과_개선.md#maintenance)

## 4. 기록의 용도에 따라 보관할 곳을 정합니다

| 남길 것 | 위치 | 다음에 쓰는 이유 |
|---|---|---|
| 조사한 사실과 근거, 완성 결과물 | 과제 폴더의 원자료·보고서 | 새 판단에 쓸 수 있는지 원문부터 확인 |
| 결정과 이유, 변경 결과 | 과제별 변경 기록 | 왜 현재 방식을 택했는지 이해 |
| 목적·현행 파일·핵심·남은 질문 | 지식지도 | 필요한 자료와 시작점을 찾음 |
| 일반화한 작업 기준 | 스킬과 관련 도구 | 같은 유형의 작업을 다른 방식으로 수행 |
| 개인 선호와 맥락 | 메모리 | 다음 요청의 뜻과 원하는 결과를 이해 |

지도에는 자료 위치와 요지를, 변경 기록에는 수정한 내용과 이유를 적습니다. 반복해서 수행할 절차는 스킬에 정리합니다.

## 사람의 판단과 변경 권한

저는 목표와 결과물의 기준을 정하고, 결과를 읽으며 전제와 해석을 검토합니다. AI는 조사·작성·개선안과 구현을 맡습니다. 프로그램은 파일과 조건, 판정 기록, 연결 상태를 대조합니다.

일반적인 스킬의 문안·구조 변경은 제 확인을 받습니다. 투자 주간 평가에는 되돌릴 수 있는 일부 변경을 사전 허용했지만, 안전장치나 수치 기준을 바꾸는 제안이 포함되면 승인을 우선합니다. 이 권한은 다른 업무에 그대로 적용하지 않습니다. [투자의 변경 정책](04_투자_판단과_평가.md#자동-변경과-승인)

단계별 검사와 별도 감사도 오류를 모두 막지는 못합니다. 기준 파일을 작업 AI가 읽지 않도록 하는 것은 운영 규칙이며 기술적으로 완전히 차단한 구조가 아닙니다. 각 작업의 자료와 수정 이유를 기록하므로, 이후에 완료나 변경을 판단한 근거를 확인할 수 있습니다.
