# 조사·검증·사용·평가를 연결하는 구조

[포트폴리오](../README.md)

한 번의 요청으로 좋은 결과를 받는 것에서 출발했지만, 업무를 반복하면서 필요한 것은 자료와 판단을 다음 작업에 이어 쓰는 구조였습니다. 조사한 사실을 다시 찾고, 어떤 근거로 결정했는지 확인하고, 잘못된 설명을 고쳤을 때 관련 결과도 함께 돌아볼 수 있도록 구성했습니다.

## 업무 목적에 따라 결과물을 나눕니다

리서치는 여러 자료를 종합해 사람이 결론을 내리는 데 쓰고, 학습은 설명을 읽고 이해하는 데 씁니다. 투자는 판단을 실행으로 옮기므로 근거 외에 가격·시간·주문 상태까지 확인해야 합니다. 같은 검토 절차를 모든 업무에 일률적으로 적용하지 않았습니다.

| 구성 | 받는 정보 | 다음 작업에 남기는 것 |
|---|---|---|
| 리서치·학습 작성 | 원문, 조사 목적, 설명 기준 | 출처를 가진 사실과 해석, 보고서·학습 노트 |
| 근거 검증 | 주장, 원문, 사용 문맥 | 일치 여부, 빠진 조건, 교정할 내용 |
| Compound | 노트의 항목·계층, 음성, 영어 원문 예문 | 읽기·듣기 상태, 문맥을 담은 질문, 학습 카드와 회화 교정 |
| 투자 판단·실행 | 조사한 사실, 이전 판단, 시세·계좌 상태 | 주문·보류 이유, 체결 결과, 이후 다시 볼 조건 |
| 평가·개선 | 결과물, 오류 기록, 실행 결과 | 현재 결과의 교정과 다음 작업의 기준 변경 |

각 구성은 필요한 자료를 넘겨주되 저장 방식을 억지로 통일하지 않습니다. 학습 노트는 문서로 작성하고 앱에서 읽기 좋은 단위로 변환합니다. 투자는 공통 사실 저장소에서 수치와 출처를 불러와 판단과 연결합니다.

## 재사용할 사실과 새로 내려야 할 판단을 구분합니다

이미 확인한 사실은 다음 조사에서도 활용할 수 있습니다. 그러나 같은 사실을 다른 결론에 쓰거나, 원문의 조건이 바뀌면 다시 확인해야 합니다. 저장한 사실의 번호·버전·출처와 그 사실을 쓴 문장을 연결하는 이유입니다.

문서에 값을 복사해 두는 방식에서는 원문을 정정해도 모든 문서에 반영됐는지 알기 어려웠습니다. 저는 사실을 한곳에 모으도록 요구했고, AI가 저장·참조·교정 도구를 구현했습니다. 이후에는 원문 대조와 사용처에 대한 판단을 구분해, 재사용할 수 있는 확인 결과의 범위도 명시하게 했습니다. [사실과 사용처의 검증](05_검증과_개선.md)

## AI의 제안과 프로그램의 실행을 나눕니다

AI는 자료를 해석하고 설명을 작성하며 투자안을 제안합니다. 프로그램은 필요한 기록이 있는지, 인용과 수치가 맞는지, 실행 조건을 충족하는지 확인하고 상태를 저장합니다.

예를 들어 주문은 AI가 결론을 썼다는 이유만으로 나가지 않습니다. 근거 판정과 실행 검사를 통과한 제안을 별도 전송 과정이 받아 처리하고, 접수 뒤에는 체결·취소·남은 수량을 확인합니다. 중단된 작업을 다시 실행할 때도 이미 처리한 주문의 상태부터 확인합니다.

Compound에서도 AI의 설명을 곧바로 새 사실로 저장하지 않습니다. 질문에는 읽고 있던 노트의 문맥을 붙이고, 회화 결과는 정해 둔 항목으로 받아 사용자가 고른 표현을 학습 카드에 넣습니다.

## 본인과 AI의 역할

제가 업무의 목적·결과 기준·변경 범위를 정합니다. 직접 써 보며 설명이 부족한 부분이나 사용 흐름이 끊기는 부분을 찾고, AI가 제안한 대안에서 무엇을 채택할지 결정합니다. AI는 세부 분석·코드 구현·검토와 수정 작업을 수행합니다.

반복되는 오류는 해당 결과물을 고치는 것과 작업 기준을 바꾸는 것으로 나눠 다룹니다. 검사에서 실패했다는 이유로 실행 중에 기준을 낮추지 않고, 변경 목적과 영향을 따로 검토합니다. 저장된 기록은 이런 판단을 다음 작업에서도 확인하기 위한 자료입니다.
