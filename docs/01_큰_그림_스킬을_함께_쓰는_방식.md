# 큰 그림 — 스킬을 함께 쓰는 방식

README 1절을 자세히 적은 글입니다. 무엇이 언제 도는지, 스킬이 스킬을 어떻게 부르는지, 세 업무가 무엇을 같이 쓰는지, 이 체계가 어떤 순서로 자랐는지를 다룹니다. 각 업무의 설계와 시행착오는 [학습 노트](02_학습_노트_요약이_아니라_이해.md), [투자](03_투자_예상해_두고_대응한다.md), [검사와 감사](04_검사와_감사_했다는_말을_믿지_않는다.md), [컨설팅 조사](05_컨설팅_조사_검증은_여기서_시작했다.md)에 있습니다.

## 일주일의 리듬

| 언제 | 스킬 | 하는 일 | 남는 것 |
|---|---|---|---|
| 평일 09:30 | trade-run(국내) | 수집, 지난 판단 확인, 시장 분석과 조사, 분석 노트, 결정, 주문과 체결과 마감의 여섯 단계 | 분석 노트, 주문 제안, 승인과 거부, 주문과 체결 기록, 자산 곡선 |
| 평일 11:00 | world-study → fact-check → 감사 | 직전 노트 이후 발행분 수집, 선별, 원인과 개념 설명, 덧붙인 사실의 출처 검증, 발행 | 그날의 노트, 검증 리포트, 감사 기록 |
| 평일 22:35 | trade-run(미국) | 국내와 같은 여섯 단계. 국내 실행의 회고가 입력으로 들어갑니다 | 국내와 같은 기록 |
| 금요일 실행 안 | 주간 리포트 | 한 주의 자산과 거래 집계 | 토요일 피드백의 입력 |
| 토요일 | trade-feedback → skill-maintainer | 놓친 상승, 매도 시점, 손실 거래, 사지 않은 판단을 당시 기록과 대조. 규칙 변경 제안. 되돌릴 수 있는 변경은 적용 | 피드백 보고서, 규칙 변경 기록, 검사 문항 반영 기록 |
| 필요할 때(컨설팅 재직 중) | knowledge-map → research-verified → research-docx 또는 research-organizer → research-source-check | 과제 폴더 만들기, 출처를 검증한 조사, Word와 Excel 문서, 완성 문서의 감리 | 조사 결과 문서, 보고서, 교정 지시서 |
| 필요할 때 | consulting-interview-note, expert-vq-compiler, dart-analysis, life-research, life-map | 인터뷰 기록, 전문가 답변 정리, 공시 재무 분석, 일상 주제 조사, 개인 프로젝트 지식지도 | 각 산출물 |

평일 실행과 토요일 피드백은 예약 작업이 부릅니다. 사람이 시작하거나 중간에 승인하는 단계는 없습니다. 승인이 필요한 변경만 피드백 보고서에 올라와 제 결정을 기다립니다.

## 스킬이 스킬을 부르는 관계

| 부르는 쪽 | 불리는 쪽 | 언제 |
|---|---|---|
| 학습 노트(world-study) | 출처 확인(fact-check) | 원문에 없는 사실을 덧붙인 문장마다, 묻지 않고 |
| 학습 노트 | 감사(gate-audit) | 발행 뒤 백그라운드에서 노트와 검증 리포트를 다시 읽습니다 |
| 학습 노트 | 투자 실행(trade-run) | 그날 노트가 투자 실행의 재료 파일에 들어갑니다(호출이 아니라 자료 전달) |
| 투자 실행 | 출처 확인 | 두 종류. 주문 근거는 주문 전에 판정하고 주문 뒤 최대 5회 감사, 배경 설명은 주문 뒤에 감사 |
| 투자 실행 | 일상 조사(life-research) | 공통 주제의 업황을 조사할 때 |
| 투자 실행 | 스킬 수정 절차(skill-maintainer) | 실행 중 코드를 고쳐야 할 때 |
| 투자 실행 | 주간 피드백(trade-feedback) | 주간 리포트와 실행 기록을 토요일의 입력으로 |
| 주간 피드백 | 스킬 수정 절차 | 규칙이나 스킬을 고치기 전에 반드시 |
| 주간 피드백 | 검사 엔진 | 감사에서 반복된 지적을 검사 문항으로 올립니다 |
| 주간 피드백 | 투자 실행 | 근거가 틀린 규칙만 유형 단위로 고쳐 다음 실행에 반영 |
| 과제 폴더(knowledge-map) | 조사(research-verified), Excel(research-organizer), Word(research-docx), 공시 분석(dart-analysis) | 새 과제의 위치와 이름을 정한 뒤 넘깁니다 |
| 조사(research-verified) | Word와 Excel 스킬 | 검증을 통과한 내용만 문서로 |
| 조사 ↔ 감리(research-source-check) | 서로 참조 | 작성자 측 검증과 검토자 측 감리가 짝입니다 |
| 컨설팅 산출 스킬 전부 | 감사 | 발행 지점에서 단계 검사를 통과하면 백그라운드 감사. 완료 전에 감사 결과를 반영 |
| 감사 | 지적 기록 | 지적을 항목별로 기록. 두 실행 이상 반복되면 검사 문항 후보 |
| 스킬 수정 절차 | 정합성 검사, 코드 편집 검사 | 고친 뒤 이름, 경로, 검사 기준표, 사라진 줄을 확인 |

## 세 업무가 같이 쓰는 것

- **출처 확인 방법.** 출처에 접근할 수 있는지, 주장을 뒷받침하는지, 이용 시점에도 유효한지, 적절한 출처인지를 보고 일치, 불일치, 시효 지남, 확인 불가로 판정합니다. 컨설팅 조사 스킬에 든 검증 방법론 문서가 정본입니다. 일상과 투자용 fact-check와 컨설팅용 research-source-check가 같은 기준을 각자의 산출물에 씁니다.
- **단계 검사 엔진.** 작업 단계가 끝날 때 AI가 검사 질문에 답하고 프로그램이 산출 파일을 대조하는 공통 엔진입니다. 스킬 16개가 검사 지점 28개에서 이 엔진을 씁니다. 보고하는 AI와 판정하는 프로그램을 나누고, 판정 기준은 질문과 다른 파일에 둡니다.
- **감사와 검사 문항 반영.** 통과한 산출물을 다른 AI가 정해진 항목으로 다시 읽습니다. 지적은 항목별로 기록되고, 서로 다른 실행 두 번 이상에서 반복되면 검사 문항으로 올립니다. 2026년 9월 28일부터 10월 20일까지 지적 123건 중 74건이 검사 문항이 됐습니다.
- **스킬 수정 절차.** 스킬 문서나 코드를 고칠 때 고치기 전 상태를 보존하고, 고치기 전후를 대조해 사라진 줄이 없는지 보고, 코드면 더는 쓰이지 않는 변수와 호출을 검사하고, 관련 테스트와 스킬 간 참조를 다시 확인합니다. 문안과 구조를 바꾸는 편집은 제 확인을 거칩니다.

같이 쓰지 않는 것도 있습니다. 투자 시스템의 데이터베이스와 예약 실행은 투자에만 있습니다. 학습 노트가 완성돼야 투자가 시작되는 구조가 아니라, 같은 뉴스레터를 두 스킬이 각자 읽습니다. 컨설팅 작업은 요청마다 필요한 경로만 씁니다.

## 역할

| 역할 | 맡는 일 | 예 |
|---|---|---|
| 저 | 업무의 목표와 결과물의 기준을 정합니다. 결과를 읽고 문제를 지적합니다. 승인 대상으로 정한 변경을 결정합니다. | 노트의 설명 기준 보완 요구, 주문 전 판정과 주문 후 감사의 분리 결정, 매매 대상 기준 변경 승인, 인터뷰 기록의 구조 초안 확인 |
| AI 세션 | 자료를 읽고 고르고 해석해 판단안을 씁니다. 조사한 사실을 등록합니다. 단계마다 검사 질문에 근거 파일을 인용해 답합니다. | 학습 노트 초안, 투자 시나리오와 주문 제안, 조사 결과 문서 |
| 프로그램 | 자료를 모으고 상태를 저장합니다. 파일과 수치와 형식을 검사합니다. 주문 규칙으로 승인과 거부를 정하고 주문을 보내 확인합니다. | 뉴스레터 수집기, 노트 검사기, 데이터베이스, 주문 규칙 검사, 체결 확인 |

AI가 했다고 답한 내용은 프로그램이 파일에서 다시 확인합니다. 거꾸로 프로그램이 확인하는 것은 파일과 인용문과 필수 항목이 있는지까지이고, 내용이 맞는지는 AI의 검토와 제 읽기에 달려 있습니다. 맡긴 일이라도 결과가 어떤 근거에서 나왔는지는 제가 확인합니다.

## 지금 확인된 범위

학습 노트는 8월 28일부터 평일마다, 모의투자 실행은 9월 9일부터 국내와 미국에서, 주간 피드백은 10월 3일부터 세 번 돌았습니다. 2026년 10월 20일 기준으로 노트 36편, 실행 52회, 거래 기록 45일이 있습니다. 투자 코드는 테스트 14개 파일을 가짜 증권사와 임시 데이터베이스로 돌려 확인합니다. 수익성과 규칙 변경의 효과는 평가 중입니다.

## 용어

- **스킬:** Claude Code가 읽는 작업 절차와 판단 기준 파일입니다. 불리면 그 절차대로 일합니다.
- **단계 검사:** 작업 단계가 끝날 때 산출 파일과 기록을 확인하고, 조건을 채워야 다음 단계로 가는 절차입니다. 스킬 문서에서는 '게이트'라고 부릅니다.
- **검사 기준표:** 단계 검사의 질문과 판정 기준입니다. 스킬 문서에서는 '루브릭'이라고 부릅니다. 작업하는 AI에게는 질문만 주고, 기준 파일을 직접 여는 것은 운영 규칙으로 금지합니다.
- **감사:** 단계 검사를 통과한 산출물을 다른 AI가 정해진 항목으로 다시 읽는 절차입니다.
- **주문 규칙 검사:** 미리 정한 조건으로 주문의 승인과 거부를 정하는 프로그램입니다.
- **주문 제안:** AI 세션이 매수, 매도, 보유, 보류 판단과 근거를 적어 주문 규칙 검사에 넘기는 파일입니다. 스킬과 코드에서는 '시그널'이라고 부릅니다.
- **사실:** 조사에서 확인해 데이터베이스에 등록한 한 건의 정보입니다. 출처와 인용문과 등급을 갖고 번호로 참조됩니다.
- **매수 근거:** 종목을 사거나 보유하는 이유와, 그 판단을 유지하거나 철회할 조건입니다. 스킬과 코드에서는 '논지'라고 부릅니다.
- **매매 대상 목록:** 주문이 허용된 종목의 목록입니다. 변경은 별도 규칙으로 관리합니다.
