# 사실·조건·사용처를 연결하는 검증 구조

[포트폴리오](../README.md)

AI의 결과를 검토하려면 문장이 그럴듯한지보다 무엇을 근거로 썼고 어디에 사용하는지 확인할 수 있어야 합니다. 현재는 자료의 열람 범위, 사실의 값과 조건, 그 사실을 사용하는 판단을 연결해 관리합니다. 검토에서 찾은 오류는 현재 결과의 교정과 다음 작성 방식의 개선으로 나눠 반영합니다.

## 확인한 사실을 한곳에 저장합니다

같은 사실을 보고서와 판단 문서에 복사하자 원문을 고쳐도 다른 문서에 이전 값이 남았습니다. 검사 질문과 문서 대조를 추가한 뒤에도 누락이 이어졌습니다. 저는 사실과 데이터를 한곳에서 관리하고 이미 조사한 내용을 다시 활용하도록 요구했습니다.

저장소에는 사실의 종류에 필요한 항목과 출처·기준일을 둡니다. 값이 바뀌면 이전 버전을 남기고, 그 값을 사용한 판단을 다시 확인할 수 있게 참조를 연결합니다. 기업 실적, 정책, 일정처럼 조사 종류마다 필요한 정보가 다르므로 문장 하나와 숫자 하나로 모두 저장하지 않습니다.

저장 구조를 처음 설계할 때도 어떤 항목을 조사하고 어느 판단에 쓸지가 드러나도록 보완을 요구했습니다. 이 판단을 바탕으로 AI가 데이터베이스와 등록·교정·참조 도구를 구현했습니다.

## 원문과 일치하는 사실도 사용처에 맞게 확인합니다

원문에 수치가 있어도 대상이나 기간이 다르면 현재 문장의 근거가 될 수 없습니다. ‘예상’, ‘잠정’ 같은 표현을 빼면 원문보다 강한 주장이 됩니다.

| 확인 대상 | 확인하는 내용 | 결과에 반영하는 방법 |
|---|---|---|
| 자료 | 본문·자막을 읽었는지, 설명·검색 결과·접근 안내만 받았는지 | 확보한 범위를 넘겨 출처를 사용하지 않도록 구분합니다. |
| 사실 | 값·단위·기간·기준일·주체·한정 조건 | 하위 항목으로 나눠 원문 인용과 대조합니다. |
| 사용처 | 이 사실이 해당 판단 문장을 뒷받침하는지 | 원문 일치 판정과 별도로 사용 문장에 연결합니다. |
| 변경 | 사실·단서·문장·출처가 이전 확인 때와 같은지 | 바뀐 부분에 이전 판정을 그대로 적용하지 않도록 확인합니다. |

예를 들어 목표 가격을 판단에 사용할 때는 그 가격이 어느 기간을 대상으로 하는지도 함께 다룹니다. 저는 목표 가격의 기간과 판단의 기한을 맞춰 생각하도록 요구했습니다. 기간이 불명확한 수치를 같은 의미의 목표 가격처럼 쓰지 않도록 저장 항목과 검사에 반영했습니다.

자료를 재사용할 때는 원래 판정이 확인한 사실·출처·본문 버전도 함께 확인합니다. 같은 문장이 남아 있다는 이유만으로 새로운 사용 문맥까지 확인됐다고 보지 않는 구조입니다. [사실 항목과 사용처의 구현](reference/현재_구조_구현근거.md#fact-structure)

## 반복 오류를 작성할 때 줄입니다

별도 검토에서 같은 종류의 오류가 반복되면 재검토 횟수만 늘리기보다, 작성자가 처음부터 필요한 정보를 갖추게 해야 한다고 판단했습니다. 저는 감사 기준을 낮추지 않고 작성 구조를 바꾸도록 요구했습니다.

현재는 원문의 조건을 확인 목록에 포함하고, 인용이 주장한 수치를 담고 있는지와 필요한 판정이 빠졌는지를 작성 중에 검사합니다. 기계적으로 확인할 항목은 프로그램이 대조하고, 의미나 적합성은 AI의 판단으로 남깁니다. 검사 규칙을 추가할 때는 실제 기록에 적용해 정상 문장을 잘못 막는지도 확인했습니다.

학습에서는 사건의 원인·개념·예외를 먼저 조사한 뒤 초안을 쓰고, 투자에서는 사실과 사용처별 판정을 준비한 뒤 판단에 연결합니다. 현재 산출물을 고치는 일과 반복되는 작업 기준을 바꾸는 일은 별도로 관리합니다.

## 확인 시점은 결과를 사용하는 방식에 맞춥니다

투자에서는 모든 배경 설명의 감사를 기다리는 동안 실행 시점을 놓친 경험이 있었습니다. 저는 주문에 필요한 근거 확인을 먼저 끝내고, 후속 검토 결과도 실행 판단에 반영하도록 범위를 나눴습니다.

AI는 근거와 제안을 만들고 프로그램은 실행 조건을 검사합니다. 주문 뒤에는 접수와 체결을 구분하고, 근거가 뒤집혔을 때의 후속 조치까지 기록합니다. 이 구조는 검토를 없애기 위한 것이 아니라, 확인할 내용과 그 결과를 반영할 시점을 맞추기 위한 것입니다.

## 기여와 평가 기준

목적·변경 범위·결과 기준은 제가 정하고, 원인 분석과 도구 구현에는 AI를 활용했습니다. 검증 절차의 존재와 실제 판단의 정확도를 같은 성과로 보지 않습니다. 저장·추적·재검토가 가능한 구조를 갖춘 결과와, 계속 평가해야 할 내용의 타당성을 구분합니다.
