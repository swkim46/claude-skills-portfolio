# 학습 — 설명이 충분한 공부 노트를 만들고 싶었습니다

[포트폴리오](../README.md) / 학습 · [생태계 설계](01_전체_흐름과_역할.md)

직접 뉴스레터로 공부할 때는 내용을 고른 뒤 모르는 부분을 AI에 물었습니다. 원하는 답을 얻으려면 무엇을 어떻게 물을지도 생각해야 했습니다. 뉴스레터 한두 개를 읽는 데도 시간이 많이 들었습니다. 지금은 AI가 여러 뉴스레터에서 내용을 골라 노트로 정리하고 설명을 붙입니다. 저는 노트를 읽으며 공부하고, 설명이 부족한 부분을 짚습니다. 이전보다 공부하는 양이 크게 늘었다고 느낍니다.

## 실제 노트: 실적과 주가는 왜 다를까

10월 16일 노트는 TSMC의 최대 실적 소식을 다루며, 좋은 실적과 주가 반응이 다를 수 있는 이유를 함께 설명합니다. 다음은 실제 노트의 부분 발췌입니다.

> 주가에는 미래 기대가 먼저 반영돼 있어 이미 더 좋은 결과를 예상한 투자자에게는 새 호재가 아님 → 숫자 자체보다 시장 예상과의 차이와 다음 분기 전망 확인 필요(UPPITY).

이 항목에서는 앞서 읽은 마이크론·ASML 사례도 함께 설명합니다. TSMC의 실적 발표 뒤 주가 반응은 자료에서 확인하지 못했다고 적었습니다. [해당 항목의 원문과 해설](../examples/실제_기록_발췌.md#study)

제가 원했던 것은 읽다가 생길 질문까지 설명해 주는 노트였습니다. 제가 매번 질문하고 답을 정리해야 한다면 공부량을 늘리기 어렵습니다. AI가 어디까지 설명해야 하는지 정하려고, 직접 공부한 기록부터 살폈습니다.

## 직접 쓴 노트에서 작성 기준을 찾았습니다

AI에 2026년 1~3월에 제가 쓴 노트 177개 항목과 뉴스레터 57통을 대조하도록 했습니다. 어떤 내용을 골랐고 얼마나 자세히 알아봤는지 찾는 작업이었습니다. 분석과 도구 구현은 AI가 맡았고, 저는 읽었던 자료와 원하는 설명 수준을 확인하며 기준을 고쳤습니다.

처음에 AI는 당일과 전날 뉴스레터만 비교했습니다. 출처를 찾지 못한 항목은 제가 다른 곳에서 읽은 뉴스로 추정했습니다. 제가 읽던 매체를 알려주고 이전 발행분까지 대조하니, 노트를 쓰지 않은 날에 받은 뉴스레터에서 해당 내용을 찾았습니다. 이후에는 직전 노트에 사용한 자료의 수집 시각부터 새 노트를 준비하는 시각까지 도착한 발행분 전체를 모으도록 바꿨습니다.

노트를 평문으로 추출하면서 들여쓰기가 사라진 문제도 있었습니다. 원래 노트에서는 사건 아래에 원인과 개념 설명을 달아 두었습니다. AI가 이 구조를 복원한 뒤에야, 한 사건에서 무엇을 더 알아봤는지 구분할 수 있었습니다.

## 노트의 분량을 목표로 삼지 않습니다

직접 쓴 노트에는 뉴스를 많이 받은 날에도 한 항목만 남긴 경우가 있었습니다. 그런데 과거 노트의 항목 수와 주제별 비중을 참고로 넣자 AI는 그 숫자에 맞춰 내용을 채웠습니다. 저는 선별 건수 자체에 의미를 두지 말라고 했습니다. 숫자를 채우느라 공부할 필요가 적은 내용까지 넣을 수 있기 때문입니다.

현재는 중요성과 배울 내용을 기준으로 항목을 고릅니다. 최근 노트에서 이미 설명했다면 새로 달라진 점이 있는지 확인합니다.

## 설명이 빠지는 문제는 작성 순서부터 고쳤습니다

초기 결과물에는 하위 항목이 있어도 관련 사실만 늘어놓거나, 용어의 뜻은 적었지만 그 제도가 왜 필요한지는 빠진 경우가 있었습니다. 저는 용어의 의미와 함께 제도·규칙이 생긴 이유, 해당 사건에서 중요한 이유까지 설명하도록 요구했습니다.

문장을 고쳐도 다음 노트에서 비슷한 설명이 빠졌습니다. 검사 질문을 추가해도 해결되지 않아 AI가 작성 순서를 바꿨습니다. 지금은 사실·원인·개념·예외·사건일을 먼저 정리한 뒤 글을 씁니다. 작성한 AI가 초안을 다시 읽으며, 원자료를 보지 않은 독자도 이해할 수 있는지 확인합니다. [검사 추가에서 작성 순서 변경으로 이어진 과정](05_검증과_개선.md#writing-order)

노트 작성과 출처 검증은 역할을 나눴습니다. `world-study`는 노트에 넣을 내용을 고르고 설명을 쓰며, `fact-check`는 추가한 사실을 원문과 대조합니다. 검증 스킬은 판정표가 기준에 맞는지 확인합니다. 노트 작성 스킬은 설명이 충분한지, 지적한 내용이 고쳐졌는지 확인합니다. 투자에서도 같은 출처 검증 스킬을 사용합니다. [공통 기준의 위치를 옮긴 이유](05_검증과_개선.md#shared-criteria)

별도 AI가 결과물을 검토하는 `gate-audit`의 지적은 유형별로 기록합니다. 같은 오류가 반복되면 `skill-maintainer`를 통해 원인과 작성 지침을 검토합니다. 노트의 사실 오류는 해당 노트에서 고치되, 작성 중인 AI가 스스로 작업 규칙까지 바꾸지는 않습니다.

## 작업용 약칭이 노트에 섞여 나오기도 했습니다

스킬 문서에서 쓰던 약칭과 점검용 표현이 노트에도 등장했습니다. 작업 방식을 모르는 독자에게는 뜻을 알기 어려운 말이었습니다.

저는 이해하기 어려운 어투를 지적했고, AI는 스킬의 작업 지침과 노트에 쓸 문장을 구분하도록 고쳤습니다. 지침에는 주어와 대상을 분명히 쓰고, 수치가 무엇을 기준으로 한 값인지 밝히도록 적었습니다. 제목에서도 본문보다 넓거나 확실한 주장으로 쓰지 않도록 했습니다. 프로그램도 내부 표현을 찾지만, 표현을 바꾼 뒤에는 문장 전체가 이해되는지 다시 읽어야 합니다.

## 노트 작성과 검증 절차

`world-study`가 수집한 뉴스레터를 읽고 내용을 선별해 설명을 작성합니다. 직전 노트의 머리말에 적힌 자료 수집 시각 이후의 발행분이 대상입니다. 프로그램으로 그 이후 도착한 발행분을 모으고, 연결된 원문과 각주를 확인한 뒤 부족한 설명을 보완합니다.

| 순서 | 만드는 자료 | 용도 |
|---|---|---|
| 수집·선별 | 밀린 발행분, 고른 항목과 원문 링크 | 각 항목이 왜 학습할 가치가 있는지 판단 |
| 원문 읽기 | 사실·원인·개념·예외·사건일을 적은 항목별 메모 | 설명이 빈 곳을 보완한 뒤 노트 작성 |
| 초안·다시 읽기 | 주어·수치의 기준·인과 관계를 풀어 쓴 노트 | 원자료 없이도 이해되는지 확인 |
| 출처 검증·사전 검토 | 보탠 사실의 판정과 교정 사항 | 해당 줄과 같은 유형의 오류를 함께 수정 |
| 발행 | 날짜별 노트와 검증 리포트 | 읽기와 복습, 이후 노트의 중복 확인에 사용 |

원문에 없는 사실·제도 설명에는 `[AI]`, 해석에는 `[추정]`을 붙입니다. `fact-check`가 `[AI]` 문장을 출처와 대조하고, 교정 결과를 노트에 반영합니다. 프로그램은 형식·중복·누락 후보를 확인합니다. 발행 뒤 감사에서 사실 오류를 발견하면 아래 정책에 따라 고칩니다.

발행 전 사전 검토와 발행 후 감사는 다릅니다. 발행 뒤에는 판정 변경과 사실 오류를 한 차례 반영하고, 형식·문체 지적은 반복 유형 기록으로 남깁니다. 추가 감사를 기다리느라 노트 전달을 계속 늦추지 않도록 정한 정책입니다.

노트는 날짜별로 보관하고 수정 전 판도 남깁니다. 쌓인 노트를 주제별 복습 자료로 정리해 읽는 데에도 활용합니다. 복습본 작성은 필요할 때 요청하는 작업이며, 매일 노트를 만드는 자동 절차와는 구분합니다.

## 확인한 범위

2026년 8월부터 학습 노트를 작성해 사용하고 있습니다. 10월 20일 기준으로 36일치가 남아 있습니다. 파일명의 날짜별로 하나씩 세고, 같은 날짜의 수정본·감사본·복습본은 제외했습니다. 이는 노트의 축적량이며 학습 효과를 나타내는 지표는 아닙니다. 여러 뉴스레터를 바탕으로 만든 노트를 읽으며 학습량이 늘었다는 설명은 제 경험입니다. 이해도나 기억의 유지 정도를 별도로 측정한 것은 아닙니다.

작성 기준은 제가 공부하던 방식에서 정했습니다. 설명이 충분한지는 노트를 실제로 읽으며 검토하고, 프로그램 검사는 형식과 누락 후보를 찾는 데 사용합니다. 개인 노트는 선택한 항목을 발췌해 공개했습니다. 노트 전체와 구독 뉴스레터 원문은 포함하지 않습니다. 코드 사용법을 설명하는 가상 예제는 실제 발췌와 별도로 표시했습니다.
