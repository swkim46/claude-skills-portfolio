# 작업 완료를 산출물과 실행 기록으로 확인하는 방법

분석 결과를 검토하다 보면 자료를 끝까지 읽지 않았거나, 필요한 확인 절차를 생략한 경우가 있었습니다. 완성된 결과물만 검사해서는 어느 단계에서 문제가 발생했는지 찾기 어려웠습니다.

작업 단계마다 필요한 파일과 기록을 확인하고, 조건을 충족해야 다음 단계로 진행하도록 했습니다. AI의 내용 검토와 코드의 파일 검사를 함께 사용하며, 각 방식의 검사 범위를 구분했습니다.

## 최종 결과물만 검사했을 때의 문제

초기 모의투자 절차에서는 분석 노트 작성 후에 한 번만 검사했습니다. 그러나 수집 자료가 일부 덮어써지거나, 뉴스레터를 끝까지 읽지 않거나, 이전 실행의 결론을 이어받지 않는 문제는 그 전에 발생했습니다. 검사에서 찾지 못한 문제는 사람이 결과를 읽으며 발견했습니다. 반면 주문·체결 단계의 검사에서는 잘못된 주문이 세 차례 차단됐습니다.

이후에는 작업 단계마다 검사하도록 변경했습니다. 학습 노트에서도 확인할 문장이 많다는 이유로 출처 검증을 건너뛰고 진행 여부를 묻는 일이 있어, 출처 검증의 수행 여부를 검사 항목에 추가했습니다.

## 여섯 단계 사이의 검사

모의투자 절차는 여섯 단계로 구성되며, 각 단계의 검사를 통과해야 다음 단계로 진행합니다.

| 검사 시점 | 확인하는 내용 |
|---|---|
| 자료 수집과 시장 측정 직후 | 자료와 업종별 등락 표의 누락 여부. 이후 판단에 필요한 숫자가 준비됐는지 확인합니다. |
| 이전 실행 이어받기 직후 | 이전 실행의 회고와 대기 중인 매매 조건의 점검 여부. 기존 판단을 이어받았는지 확인합니다. |
| 시장 지도와 조사 직후 | 미확인 영향 관계의 처리 여부와 조사 결과의 분석 반영 여부. |
| 분석 노트 확정 직후 | 설명의 충분성, 종목별 투자 근거와 상위 시나리오의 연결, 숫자 오류. |
| 주문 전송 직전 | 필수 절차와 매도 조건의 누락, 결정 보류의 타당성. 제안이 없는 날에도 판단 근거를 확인합니다. |
| 주문 확정 직후 | 접수와 체결의 구분, 미체결 주문의 처리 여부. |

주문 전송 명령은 다섯 번째 검사의 통과 기록이 있을 때만 실행됩니다. 이전에는 파일 안의 문자열만 확인해 첫 번째 검사만 통과해도 주문을 전송할 수 있는 결함이 있었습니다. 이를 수정하면서 어느 검사를 통과했는지 구분하도록 했습니다.

매매를 하지 않기로 한 날도 판단 근거를 검사합니다. 반복적으로 발생한 판단 보류의 타당성을 확인하려면, 주문이 없는 경우에도 같은 검토 절차가 필요했기 때문입니다.

## 검사가 진행되는 방식

1. 작업을 마친 AI가 검사 엔진에 질문지를 요청합니다. 엔진은 해당 단계의 모든 질문을 제시하되 합격 기준은 공개하지 않습니다.
2. 같은 질문을 "예가 정답인 표현"과 "아니오가 정답인 표현"으로 바꿔 제시합니다. 이전 회차의 답변을 그대로 재사용하지 못하도록 한 방식입니다. 의미를 혼동하기 쉬운 이중부정은 사용하지 않습니다.
3. AI는 예·아니오로 답하고, 근거 파일의 경로와 해당 문장을 그대로 인용합니다.
4. 엔진은 직전 단계의 통과 기록을 확인한 뒤, 산출 파일을 직접 검사하고 인용한 문장이 실제로 있는지 대조합니다.
5. 실패하면 다음 단계로 진행할 수 없으며 해당 회차의 질문지는 폐기됩니다. 통과하면 서명이 포함된 통과 기록을 남깁니다.

합격 기준을 공개하지 않는 이유는 AI가 수행 내용을 확인하기보다 통과할 답을 작성하는 일을 줄이기 위해서입니다. 다만 기준을 숨기는 것만으로 검사 결과를 보장할 수는 없으므로, 파일에서 확인할 수 있는 항목은 코드가 직접 다시 검사합니다.

## 검사 엔진 자체를 고친 사례

- 검사 코드가 파일을 읽지 못해 오류가 발생했는데도 통과한 것으로 보이는 문제가 있었습니다. 이후 검사 실행 오류도 실패로 처리해 기준을 충족한 경우와 구분했습니다.
- 통과 기록이 수정 가능한 텍스트였고 유효 기간도 없었습니다. 9월 3일의 기록이 9월 10일에도 유효한 것을 확인한 뒤, 서명을 추가하고 12시간 후 만료되도록 했습니다.
- 실패 기록을 삭제하는 명령이 인증 없이 실행됐습니다. 삭제 작업 자체가 기록에 남도록 수정했습니다.
- 실패한 항목에 대한 정보가 전혀 없어, 한 실행에서 표기 형식을 200개 넘게 시도하고도 원인을 찾지 못했습니다. 이후 합격 기준은 공개하지 않되 실패한 항목의 번호는 알려 주도록 했습니다.
- 작업 AI가 인자를 통해 검사 강도를 낮출 수 있는 경로를 제거했습니다. 검사를 받는 쪽에서 검사 범위를 변경하지 못하도록 한 수정입니다.

## 채점표의 규모

2026년 9월 기준 모의투자 채점표는 검사 단계 7개, 질문 158개, 파일을 직접 확인하는 항목 117개로 구성돼 있습니다. 다섯 번째 작업 단계는 제안 유무에 따라 검사를 두 갈래로 나눴습니다. 학습 노트 채점표에는 질문 18개와 파일 확인 항목 2개가 있습니다. 채점표는 [.claude/skills/_stepgate/rubrics/](../.claude/skills/_stepgate/rubrics/)에서 확인할 수 있습니다.

대표적인 질문은 다음과 같습니다.

- 뉴스레터를 앞쪽 몇 통만 읽고 나머지를 넘긴 것이 있는가.
- 하위 항목이 원인 설명이 아니라 추가 사실로만 채워진 상위 항목이 있는가.
- 작성을 시작하기 전에 목표 줄 수를 정해 두고 거기에 맞췄는가.
- 상위 시나리오 없이 종목 뉴스만으로 세운 논지가 있는가.
- 주문번호가 나온 것만 보고 체결됐다고 판단했는가.
- 회고에서 결과가 아니라 판단 근거를 채점했는가.

## 사후 감사

실행 후에는 별도의 감사 절차로 대화 기록을 검토합니다. 감사 AI는 정해진 규칙에 따라 위반 가능성을 확인하고, 최종 위반 여부와 오탐은 사람이 판정합니다. 감사 AI가 위반을 뒷받침하는 문장을 그대로 인용하지 못하면 통과로 처리합니다. 판정에 직접 확인할 수 있는 근거를 요구하는 방식입니다.

## 검사 방식의 한계

검사는 이미 작성된 산출물을 대상으로 하므로 오류 발생 자체를 예방하지는 못합니다. 파일 검사 외 항목은 AI의 판단에 의존하며, 검사 절차를 호출하지 않은 실행은 검사 기록이 없어 사후 확인도 어렵습니다. 서명 키가 작업 AI와 같은 파일 시스템에 있어 지침을 따르는 모델을 전제로 합니다. 채점표는 공개돼 있으므로 합격 기준을 숨기는 방식은 운영 환경 안에서만 적용됩니다.
