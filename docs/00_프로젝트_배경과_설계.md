# 전체 구성과 역할 분담

이 글은 세 업무(학습 노트, 투자 분석·판단·주문 관리, 컨설팅 리서치·문서 작업)가 어떻게 나뉘고 무엇을 공유하는지, 운영자·AI·프로그램이 각각 무엇을 맡는지 설명합니다. 개발 배경과 용어는 뒤에 두었습니다. 업무별 작동 방식은 [학습 노트](02_학습노트_설명_기준.md), [투자](03_투자_시나리오_설계.md), [컨설팅 리서치](07_컨설팅_리서치_시스템.md)에 있습니다.

## 세 업무와 공통 방법

| 구분 | 학습 노트 | 투자 분석·판단·주문 관리 | 컨설팅 리서치·문서 작업 |
|---|---|---|---|
| 실행 방식 | 평일 아침 실행 | 국내·미국 장 전 예약 실행, 토요일 주간 피드백 | 요청이 있을 때 호출 |
| 담당 스킬 | world-study, fact-check | trade-run, trade-feedback, fact-check | research-verified, research-source-check, research-docx, research-organizer, consulting-interview-note, expert-vq-compiler, dart-analysis, dart-analysis-code, knowledge-map |
| 프로그램 | 뉴스레터 수집·원문 확인·노트 검사 도구 | 자료 수집, 데이터베이스, 주문 규칙 검사, 주문·체결, 평가 도구 | 문서 조판, 엑셀 작성, 공시 수집·비율 계산, 폴더 구조 읽기 도구 |
| 상태 저장 | 날짜별 노트 파일과 검증 기록 | SQLite 데이터베이스 한 파일(사실, 판단, 주문, 운영 기록) | 과제 폴더, 변경 기록, 지식지도 |

세 업무가 공유하는 것은 네 가지입니다.

- **출처 검증 방법.** 출처에 접근할 수 있는지, 주장을 뒷받침하는지, 이용 시점에도 유효한지, 적절한 출처인지 확인하고 결과를 일치·불일치·시효 지남·확인 불가로 나눕니다. 컨설팅 리서치의 검증 방법론 문서가 정본이며, 일상·투자용 fact-check 스킬과 컨설팅용 research-source-check 스킬이 같은 기준을 각자의 산출물에 적용합니다.
- **단계별 검사 엔진.** 작업 단계가 끝날 때 AI가 검사 질문에 답하고 프로그램이 산출 파일을 대조하는 공통 엔진입니다. 검사 항목과 통과 조건은 업무마다 다릅니다.
- **감사.** 단계 검사를 통과한 산출물을 별도의 AI 에이전트가 백그라운드에서 다시 읽습니다. 결과를 언제 기다리고 반영하는지는 업무별로 정했습니다.
- **스킬 수정 절차.** 스킬 문서나 코드를 고칠 때 편집 전 상태를 보존하고 편집 전후를 대조하며 관련 테스트를 다시 실행하는 절차를 모든 스킬에 적용합니다.

공유하지 않는 것도 분명히 해 둡니다. 학습 노트와 투자는 같은 뉴스레터를 읽지만 서로 다른 실행이며, 학습 노트가 완성돼야 투자 실행이 시작되는 구조가 아닙니다. 투자 시스템의 데이터베이스와 예약 실행은 투자에만 있습니다. 컨설팅 작업은 요청에 따라 필요한 경로만 사용합니다.

## 운영자·AI·프로그램의 역할

| 역할 | 맡는 일 | 예 |
|---|---|---|
| 운영자(저) | 업무의 목적과 결과물의 기준을 정한다. 결과를 읽고 문제를 지적한다. 승인 대상으로 정한 변경을 결정한다. | 노트의 설명 기준 보완 요구, 주문 전 판정과 주문 후 감사의 분리 요청, 매매 대상 기준 변경 승인, 인터뷰 기록의 구조 초안 확인 |
| AI 세션 | 자료를 읽고 선별·해석·판단안을 쓴다. 조사한 사실을 등록한다. 단계마다 검사 질문에 근거 파일을 인용해 답한다. | 학습 노트 초안, 투자 시나리오와 주문 제안, 조사 결과 문서 |
| 프로그램 | 자료를 수집하고 상태를 저장한다. 파일·수치·형식을 검사한다. 주문 규칙으로 승인·거부를 정하고 주문을 전송·확인한다. | 뉴스레터 수집기, 노트 검사기, 데이터베이스, 주문 규칙 검사, 체결 확인 |

AI가 수행했다고 답한 내용은 프로그램이 파일에서 다시 확인합니다. 반대로 프로그램이 확인하는 것은 파일·인용문·필수 항목의 존재이며, 내용의 타당성은 AI의 검토와 제 읽기에 의존합니다.

업무별로 자동 처리의 범위가 다릅니다. 투자 실행은 수집부터 체결 확인까지 사람의 개입 없이 진행하고, 주간 피드백은 되돌릴 수 있는 변경만 자동 적용합니다. 학습 노트는 발행 뒤 감사 결과를 한 차례 반영합니다. 컨설팅에서는 인터뷰 기록과 공시 분석이 산출 전에 제 확인을 받고, 조사·보고서는 최종 발행 전에 감사 통과 여부를 확인합니다. 자세한 기준은 [스킬 운영 원칙](06_스킬_운영_원칙.md)에 있습니다.

## 개발 배경

2026년 1월부터 3월까지 금융·경제 뉴스레터 세 종을 읽으며 학습 노트를 작성했습니다. 기록할 뉴스를 고른 뒤 사건의 배경과 관련 개념을 찾아 덧붙이는 방식이었습니다. 일정이 바빠지면서 노트 작성을 중단했고, 이 작업을 AI로 이어갈 방법을 찾기 시작했습니다.

컨설팅 업무에서는 2026년 6월부터 출처 검증을 갖춘 조사 스킬과 문서 작성 스킬을 사용하고 있었습니다. 8월 말 학습 노트 스킬을 만들 때 그 검증 방법과 단계별 검사 엔진을 재사용했고, 9월에 같은 뉴스레터를 투자에 활용하는 trade-run을 개발하면서 다시 재사용했습니다.

학습 노트의 작성 기준은 직접 쓴 노트 177개 항목과 뉴스레터 원문 57통을 대조해 정리했습니다. 어떤 내용을 선택했고, 설명을 어디까지 덧붙였으며, 원문에서 어떤 근거를 확인할 수 있는지 분석했습니다.

| 기존 노트에서 확인한 내용 | 작성 규칙에 반영한 내용 |
|---|---|
| 하루에 작성한 항목은 0개부터 24개까지였으며, 뉴스가 많은 날에도 한 항목만 남긴 경우가 있었습니다. | 매일 채워야 할 분량을 정하지 않고, 선별 기준에 맞는 내용을 작성하도록 했습니다. |
| 전체 항목 중 62개, 약 35%가 하위 항목이었고 깊이는 최대 3단계였습니다. 주로 사건의 원인과 관련 개념을 설명했습니다. | 주요 사실 아래에 배경과 개념 설명을 덧붙이도록 노트 구조를 정했습니다. |
| 주제별 비중은 개별 기업 34%, 부동산 14%, 지정학 9%, 거시 지표 1%였습니다. | 기존 노트에서 자주 선택한 주제를 선별 기준의 우선순위에 반영했습니다. |

운영 초기에는 문서에 적어 둔 지침이 실제 작업에 반영되지 않는 경우가 있었습니다. 특정 뉴스레터가 수집에서 빠져도 알아차리기 어려워 수집기가 미등록 발신자와 스팸함 발행분을 경고하도록 고쳤고, 과거 노트의 통계를 참고 자료로 넣자 AI가 그 숫자에 맞춰 항목을 채워 분량으로 읽힐 수 있는 숫자를 작성 규칙에서 제거했습니다. 출처 검증에 비용 안내를 넣자 AI가 작업을 멈추고 진행 여부를 물어, 필수 검증은 그대로 수행하고 비용은 실행 후 보고하도록 바꿨습니다.

## 문서에서 사용하는 용어

- **단계별 검사:** 각 작업이 끝날 때 산출 파일과 기록을 확인하고, 필요한 조건을 충족해야 다음 단계로 진행하도록 하는 절차입니다. 스킬 문서에서는 '게이트'라고 부릅니다.
- **검사 기준표:** 단계별 검사에 사용하는 질문과 판정 기준입니다. 스킬 문서에서는 '루브릭'이라고 부릅니다. 작업하는 AI에게는 질문만 제공하고, 판정 기준 파일을 직접 여는 것은 운영 규칙으로 금지합니다.
- **감사:** 단계 검사를 통과한 산출물을 별도의 AI 에이전트가 정해진 항목으로 다시 읽는 절차입니다. 반복해서 지적되는 유형은 단계별 검사 항목으로 올립니다.
- **주문 규칙 검사:** 사전에 정한 조건에 따라 주문의 승인·거부를 결정하는 절차입니다. `risk_guard.py`가 이 역할을 담당합니다.
- **주문 제안 파일:** AI 세션이 매수·매도·보유·보류 판단과 근거를 적어 주문 규칙 검사에 넘기는 파일입니다. 스킬과 코드에서는 '시그널'이라고 부릅니다.
- **사실:** 조사에서 확인해 데이터베이스에 등록한 한 건의 정보입니다. 출처, 인용문, 등급을 갖고 번호로 참조됩니다.
- **1차 출처:** 해당 사실을 직접 발표하거나 기록한 주체의 원자료입니다. 정부 공고, 기업 공시, 통계기관의 발표 자료 등이 해당합니다.
- **투자 근거:** 종목을 매수·보유하는 이유와 그 판단을 유지하거나 철회할 조건을 정리한 기록입니다. 스킬과 코드에서는 '논지(thesis)'로 표기하며, 공개 설명에서는 '투자 근거'를 우선 사용합니다.
- **매매 대상 목록:** 주문이 허용된 종목의 목록입니다. 목록의 변경은 별도의 규칙에 따라 관리합니다.

## 검증 범위와 공개 자료

학습 노트 규칙의 근거는 한 사람이 16일 동안 작성한 기록입니다. 개인의 선별 기준과 설명 방식을 재현하기 위한 것으로, 다른 사람에게도 같은 기준이 적합한지는 확인하지 않았습니다.

구독 뉴스레터 원문과 개인 노트는 공개하지 않았습니다. 이 저장소에서는 이를 바탕으로 정리한 작업 규칙과 구현 코드를 확인할 수 있습니다.
