# 단계별 검사 — 작업 완료를 산출물과 실행 기록으로 확인하는 방법

AI가 작업을 마쳤다고 보고한 뒤에도 원문을 일부만 읽거나 필요한 확인을 빠뜨린 경우가 있었습니다. 완성된 결과물만 살펴서는 문제가 어느 단계에서 발생했는지 찾기 어려웠습니다. 이 글은 작업 단계마다 산출 파일과 기록을 확인하는 현재의 검사 방식, 중단·재개와 완료 확인의 기준, 그리고 이 방식을 택한 경위를 설명합니다.

## 검사가 진행되는 방식

1. 작업을 마친 AI가 해당 단계의 검사 질문에 예·아니오로 답하고, 근거가 되는 파일의 경로와 해당 문장을 그대로 인용합니다. 질문의 표현은 실행마다 바뀌므로 지난 답을 재사용할 수 없습니다.
2. 검사 프로그램은 직전 단계의 통과 기록을 확인한 뒤, AI의 답변과 별도로 산출 파일을 직접 검사하고 인용한 문장이 실제로 파일에 있는지 대조합니다.
3. 실패하면 다음 단계로 진행할 수 없습니다. 통과하면 통과 기록을 남기고, 다음 단계는 이 기록이 있어야 시작됩니다.

AI에게 제공하는 지침과 판정 기준은 파일을 나눠 두고, 작업하는 AI에게는 질문만 제공합니다. 기준표를 직접 여는 것은 운영 규칙으로 금지하고 열람을 감사 대상으로 두지만, 같은 파일 시스템에 있어 접근이 기술적으로 차단된 것은 아닙니다. 코드가 확인하는 것은 파일, 인용문, 필수 항목의 존재이고 내용의 타당성 판단은 AI의 검토와 제 읽기에 의존합니다. AI가 수행했다고 답한 내용을 파일에서 확인하는 것이 이 절차의 요점입니다. 검사 질문과 판정 기준은 [.claude/skills/_stepgate/rubrics/](../.claude/skills/_stepgate/rubrics/)에 있습니다.

## 투자 실행의 여섯 단계

| 검사 시점 | 확인하는 내용 |
|---|---|
| 자료 수집과 시장 측정 후 | 계좌·시세·공시·뉴스레터 등 필요한 자료의 누락 여부, 마감된 세션의 일봉 확정 |
| 이전 실행 확인 후 | 이전 판단, 대기 중인 매매 조건, 재검토할 항목을 이어받았는지 |
| 시장 분석과 추가 조사 후 | 산업·기업 간 영향 관계를 확인하고 조사한 사실을 등록·반영했는지 |
| 분석 노트 작성 후 | 매매 판단에 필요한 근거·조건·출처를 기록했는지 |
| 주문 전송 전 또는 매매 보류 결정 후 | 주문 규칙 검사를 거쳤는지, 매수마다 매도 조건이 먼저 정해졌는지, 주문하지 않는 판단에도 근거가 있는지 |
| 주문 결과 확인 후 | 접수와 체결을 구분하고 남은 주문을 처리했는지, 매도 대금을 재투자했거나 미룬 이유가 있는지 |

주문 전송 프로그램은 다섯 번째 검사의 통과 기록을 스스로 확인한 뒤에만 승인 파일을 보냅니다. 매매를 하지 않기로 한 날도 판단 근거를 검사합니다. 반복적으로 발생한 판단 보류의 타당성을 확인하려면 주문이 없는 경우에도 같은 검토 절차가 필요했기 때문입니다.

## 중단과 재개

투자 실행은 단계마다 시도 기록(성공·축소·실패)을 데이터베이스에 남깁니다. 수집 단계의 필수 자료가 실패하면 실행이 멈추고, 선택 자료의 실패는 분석 노트에 제한 사항으로 적습니다. 주문 제안은 생성 뒤 180분, 승인 파일은 30분이 지나면 무효가 됩니다. 전송 중에 중단되면 재실행이 그날의 주문 기록을 읽어 이미 접수된 주문을 다시 보내지 않습니다. 응답을 잃은 주문은 당일 주문 목록으로 상태를 확정하고, 확정되지 않은 주문은 미확정으로 남깁니다.

## 완료의 기준

지정가 주문이 접수됐지만 체결되지 않은 상태를 매수 완료로 보고한 일이 있었습니다. 이후에는 주문번호만으로 완료를 판단하지 않고, 체결 여부와 남은 주문의 취소·만료 등 처리 결과까지 확인하도록 했습니다. 실행은 모든 주문이 체결·부분체결·취소·만료·거부 중 하나로 확정될 때까지 닫히지 않습니다. 무엇을 완료로 볼지 정한 뒤, 그 상태를 확인할 기록을 검사에 포함한 사례입니다.

## 업무별 검사 항목과 감사 시점

학습 노트와 컨설팅 리서치도 같은 검사 엔진을 사용합니다. 학습 노트는 검증 리포트와 노트에 대해 발행 전 두 번 검사하고, 감사는 발행 뒤 백그라운드로 진행합니다. 컨설팅 조사는 자료 흡수, 원문 확보, 발행의 세 지점에서 검사하고 최종 발행 전에 활성 감사의 통과 여부를 확인합니다. 검사 항목과 감사 결과를 기다리는 시점은 업무별로 다르며 [스킬 운영 원칙](06_스킬_운영_원칙.md)에 정리했습니다.

학습 노트는 독자가 이해할 수 있는 설명을 갖추는 것이 중요합니다. 투자의 분석 노트는 매매 판단에 쓰인 요소와 근거를 빠짐없이 기록하는 데 초점을 맞췄습니다. 10월 13일부터 투자 검사는 설명의 분량과 형식보다 매매에 필요한 요소와 출처를 중심으로 확인하도록 조정했습니다.

## 최종 결과물만 검사했을 때의 문제

초기 투자 절차에서는 분석 노트 작성 후에 한 번만 검사했습니다. 그러나 수집 자료가 일부 덮어써지거나, 뉴스레터를 끝까지 읽지 않거나, 이전 실행의 결론을 이어받지 않는 문제는 그 전에 발생했습니다. 검사에서 찾지 못한 문제는 제가 결과를 읽으며 발견했습니다. 반면 주문·체결 단계의 검사에서는 잘못된 주문이 세 차례 차단됐습니다. 이후 작업 단계마다 검사하도록 바꿨습니다.

학습 노트에서도 확인할 문장이 많다는 이유로 출처 검증을 건너뛰고 진행 여부를 묻는 일이 있어, 출처 검증의 수행 여부를 검사 항목에 추가했습니다.

## 검사 방식의 한계

검사는 누락이나 오류가 있는 상태로 다음 단계에 진행하는 것을 막기 위한 절차입니다. 기록이 존재한다는 사실만으로 판단의 정확성까지 보장하지는 못하므로, 운영 결과를 읽고 검토하는 과정도 필요합니다. 파일 검사 외 항목은 AI의 판단에 의존하며, 검사 절차를 호출하지 않은 실행은 검사 기록이 없어 사후 확인도 어렵습니다. 판정 기준표도 같은 파일 시스템에 있어 접근이 완전히 차단된 것은 아닙니다.
