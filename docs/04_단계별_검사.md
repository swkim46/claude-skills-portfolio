# 작업 완료를 산출물과 실행 기록으로 확인하는 방법

AI가 작업을 마쳤다고 보고한 뒤에도 원문을 일부만 읽거나 필요한 확인을 빠뜨린 경우가 있었습니다. 완성된 결과물만 살펴서는 문제가 어느 단계에서 발생했는지 찾기 어려웠습니다.

이에 작업 단계마다 필요한 파일과 기록을 확인하도록 바꾸고, 완료 여부를 판단할 근거를 남기게 했습니다. 내용에 대한 AI의 검토와 코드로 확인할 수 있는 항목을 구분해 함께 검사합니다.

## 최종 결과물만 검사했을 때의 문제

초기 모의투자 절차에서는 분석 노트 작성 후에 한 번만 검사했습니다. 그러나 수집 자료가 일부 덮어써지거나, 뉴스레터를 끝까지 읽지 않거나, 이전 실행의 결론을 이어받지 않는 문제는 그 전에 발생했습니다. 검사에서 찾지 못한 문제는 사람이 결과를 읽으며 발견했습니다. 반면 주문·체결 단계의 검사에서는 잘못된 주문이 세 차례 차단됐습니다.

이후에는 작업 단계마다 검사하도록 변경했습니다. 학습 노트에서도 확인할 문장이 많다는 이유로 출처 검증을 건너뛰고 진행 여부를 묻는 일이 있어, 출처 검증의 수행 여부를 검사 항목에 추가했습니다.

완료의 기준 자체를 보완한 일도 있었습니다. 지정가 주문이 접수됐지만 체결되지 않은 상태를 매수 완료로 보고한 일이 있었습니다. 이후에는 주문번호만으로 완료를 판단하지 않고, 체결 여부와 남은 주문의 취소·만료 등 처리 결과까지 확인하도록 했습니다. 무엇을 완료로 볼지 정한 뒤, 그 상태를 확인할 기록을 검사에 포함한 사례입니다.

## 여섯 단계 사이의 검사

모의투자 절차는 여섯 단계로 구성되며, 각 단계의 검사를 통과해야 다음 단계로 진행합니다.

| 검사 시점 | 확인하는 내용 |
|---|---|
| 자료 수집과 시장 측정 후 | 계좌·시세·공시·뉴스레터 등 필요한 자료의 누락 여부 |
| 이전 실행 확인 후 | 이전 판단, 대기 중인 매매 조건, 재검토할 항목을 이어받았는지 |
| 시장 분석과 추가 조사 후 | 산업·기업 간 영향 관계를 확인하고 조사 결과를 분석에 반영했는지 |
| 분석 노트 작성 후 | 매매 판단에 필요한 근거·조건·출처를 기록했는지 |
| 주문 전송 전 또는 매매 보류 결정 후 | 필수 절차와 주문 조건을 충족했는지, 주문하지 않는 판단에도 근거가 있는지 |
| 주문 결과 확인 후 | 접수와 체결을 구분하고 남은 주문을 처리했는지 |

주문 전송 명령은 다섯 번째 검사의 통과 기록이 있을 때만 실행됩니다. 매매를 하지 않기로 한 날도 판단 근거를 검사합니다. 반복적으로 발생한 판단 보류의 타당성을 확인하려면, 주문이 없는 경우에도 같은 검토 절차가 필요했기 때문입니다.

학습 노트는 독자가 이해할 수 있는 설명을 갖추는 것이 중요합니다. 모의투자의 분석 노트는 매매 판단에 쓰인 요소와 근거를 빠짐없이 기록하는 데 초점을 맞췄습니다. 10월 13일부터 모의투자 검사는 설명의 분량과 형식보다 매매에 필요한 요소와 출처를 중심으로 확인하도록 조정했습니다.

## 검사가 진행되는 방식

1. 작업을 마친 AI가 해당 단계의 검사 질문에 예·아니오로 답하고, 근거가 되는 파일의 경로와 해당 문장을 그대로 인용합니다.
2. 검사 코드는 직전 단계의 통과 기록을 확인한 뒤, AI의 답변과 별도로 산출 파일을 직접 검사하고 인용한 문장이 실제로 파일에 있는지 대조합니다.
3. 실패하면 다음 단계로 진행할 수 없습니다. 통과하면 통과 기록을 남기고, 다음 단계는 이 기록이 있어야 시작됩니다.

코드가 확인하는 것은 파일, 인용문, 필수 항목의 존재이며, 내용의 타당성 판단에는 AI의 검토가 포함됩니다. AI가 수행했다고 답한 내용을 파일에서 확인하는 것이 이 절차의 요점입니다. 검사 질문과 판정 기준은 [.claude/skills/_stepgate/rubrics/](../.claude/skills/_stepgate/rubrics/)에 있습니다.

## 검사 방식의 한계

검사는 누락이나 오류가 있는 상태로 다음 단계에 진행하는 것을 막기 위한 절차입니다. 다만 기록이 존재한다는 사실만으로 판단의 정확성까지 보장하지는 못하므로, 운영 결과를 읽고 검토하는 과정도 필요합니다. 파일 검사 외 항목은 AI의 판단에 의존하며, 검사 절차를 호출하지 않은 실행은 검사 기록이 없어 사후 확인도 어렵습니다.
