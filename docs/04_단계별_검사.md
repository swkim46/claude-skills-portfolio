# 작업 완료를 산출물과 실행 기록으로 확인하는 방법

분석 결과를 검토하다 보면 자료를 끝까지 읽지 않았거나, 필요한 확인 절차를 생략한 경우가 있었습니다. 완성된 결과물만 검사해서는 어느 단계에서 문제가 발생했는지 찾기 어려웠습니다.

작업 단계마다 필요한 파일과 기록을 확인하고, 조건을 충족해야 다음 단계로 진행하도록 했습니다. AI의 내용 검토와 코드의 파일 검사를 함께 사용하며, 각 방식의 검사 범위를 구분했습니다.

## 최종 결과물만 검사했을 때의 문제

초기 모의투자 절차에서는 분석 노트 작성 후에 한 번만 검사했습니다. 그러나 수집 자료가 일부 덮어써지거나, 뉴스레터를 끝까지 읽지 않거나, 이전 실행의 결론을 이어받지 않는 문제는 그 전에 발생했습니다. 검사에서 찾지 못한 문제는 사람이 결과를 읽으며 발견했습니다. 반면 주문·체결 단계의 검사에서는 잘못된 주문이 세 차례 차단됐습니다.

이후에는 작업 단계마다 검사하도록 변경했습니다. 학습 노트에서도 확인할 문장이 많다는 이유로 출처 검증을 건너뛰고 진행 여부를 묻는 일이 있어, 출처 검증의 수행 여부를 검사 항목에 추가했습니다.

## 여섯 단계 사이의 검사

모의투자 절차는 여섯 단계로 구성되며, 각 단계의 검사를 통과해야 다음 단계로 진행합니다.

| 검사 시점 | 확인하는 내용 |
|---|---|
| 자료 수집과 시장 측정 직후 | 자료와 업종별 등락 표의 누락 여부. 이후 판단에 필요한 숫자가 준비됐는지 확인합니다. |
| 이전 실행 이어받기 직후 | 이전 실행의 회고와 대기 중인 매매 조건의 점검 여부. 기존 판단을 이어받았는지 확인합니다. |
| 시장 지도와 조사 직후 | 미확인 영향 관계의 처리 여부와 조사 결과의 분석 반영 여부. |
| 분석 노트 확정 직후 | 설명의 충분성, 종목별 투자 근거와 상위 시나리오의 연결, 숫자 오류. |
| 주문 전송 직전 | 필수 절차와 매도 조건의 누락, 결정 보류의 타당성. 제안이 없는 날에도 판단 근거를 확인합니다. |
| 주문 확정 직후 | 접수와 체결의 구분, 미체결 주문의 처리 여부. |

주문 전송 명령은 다섯 번째 검사의 통과 기록이 있을 때만 실행됩니다. 매매를 하지 않기로 한 날도 판단 근거를 검사합니다. 반복적으로 발생한 판단 보류의 타당성을 확인하려면, 주문이 없는 경우에도 같은 검토 절차가 필요했기 때문입니다.

## 검사가 진행되는 방식

1. 작업을 마친 AI가 해당 단계의 검사 질문에 예·아니오로 답하고, 근거가 되는 파일의 경로와 해당 문장을 그대로 인용합니다.
2. 검사 코드는 직전 단계의 통과 기록을 확인한 뒤, AI의 답변과 별도로 산출 파일을 직접 검사하고 인용한 문장이 실제로 파일에 있는지 대조합니다.
3. 실패하면 다음 단계로 진행할 수 없습니다. 통과하면 통과 기록을 남기고, 다음 단계는 이 기록이 있어야 시작됩니다.

AI가 수행했다고 답하는 것을 그대로 믿지 않고 파일에서 확인하는 것이 이 절차의 요점입니다. 검사 질문과 판정 기준은 [.claude/skills/_stepgate/rubrics/](../.claude/skills/_stepgate/rubrics/)에 있습니다.

## 검사 방식의 한계

검사는 이미 작성된 산출물을 대상으로 하므로 오류 발생 자체를 예방하지는 못합니다. 파일 검사 외 항목은 AI의 판단에 의존하며, 검사 절차를 호출하지 않은 실행은 검사 기록이 없어 사후 확인도 어렵습니다.
