# 투자 코드: 실행·설정·테스트

[포트폴리오](../README.md) / 구현 참고 · [투자 방식의 설계와 실행](../docs/04_투자_판단과_평가.md)

뉴스와 시장 데이터를 분석하고 주문을 처리하는 코드입니다. AI가 쓴 주문 제안은 단계별 검사와 주문 규칙을 통과해야 전송됩니다. 접수와 체결은 따로 기록하며, 조사한 사실부터 판단·주문·운영 기록까지 SQLite 데이터베이스에 저장합니다.

작업 지침은 [trade-run](../.claude/skills/trade-run/SKILL.md)에, 설계 이유는 [투자 판단과 평가](../docs/04_투자_판단과_평가.md)에 있습니다. 이 코드는 2026년 10월 20일 운영본을 공개용으로 정리한 사본입니다.

Python 3.9 이상과 표준 라이브러리를 사용합니다. 자료 수집과 주문에는 한국투자증권 API 키가 필요합니다. 주문 규칙 검사와 테스트는 키 없이 실행할 수 있습니다. 공개 설정은 모의계좌 모드이며 실계좌 주문은 꺼져 있습니다.

## 실행 중지와 재개

```bash
touch config/KILL   # 전면 중지. 주문 제안을 읽기 전에 판정하므로 어떤 주문도 나가지 않는다
rm config/KILL      # 재개
```

자동 실행이 연속 3회 실패하면 KILL 파일을 생성해 중지합니다. 원인을 확인하고 해당 파일을 삭제해야 재개할 수 있습니다.

## 실행 방식

정해진 시각에 예약 작업이 실행을 시작합니다. 개별 주문은 사람의 승인 없이 단계별 검사와 주문 규칙으로 전송 여부를 결정합니다. 아래 명령으로 직접 시작할 수도 있습니다.

```bash
python3 run_auto.py --self-test             # 환경 점검. 주문·LLM 호출 없음
python3 run_auto.py --market kr --no-send   # 전 과정을 돌리되 주문만 보내지 않음
python3 run_auto.py --market kr             # 주문 전송까지
```

Claude Code 세션에서는 `/trade-run kr` 또는 `/trade-run us`로 같은 절차를 실행하며, 예약 작업도 이 명령을 호출합니다. AI 세션은 분석과 제안을 담당하고, 주문 규칙 검사·전송·기록 프로그램은 세션 밖에서 실행됩니다.

## 실행 단계

여섯 단계로 구성되며, 각 단계가 끝나면 검사 엔진(`../.claude/skills/_stepgate/stepgate.py`)의 통과 기록이 있어야 다음 단계로 진행합니다.

| 단계 | 작업 내용 | 주요 스크립트 |
|---|---|---|
| 1 수집·측정 | 잔고·시세·공시·뉴스레터 수집, 전 업종 등락 측정, 마감된 세션의 일봉 확정, 요인 상태 측정 | `ingest.py`, `market_map.py board/exposure`, `db.py bars-finalize` |
| 2 이전 실행 확인 | 직전 실행 회고, 대기 중인 매매 조건·시나리오 점검, 지지 구간 이탈 재판정, 자산 배분 판단 인계 | `stage.py`, `scenarios.py`, `theses.py`, `support_break.py`, `allocation.py` |
| 3 시장 분석·조사 | 거시 사건과 개별 종목의 영향 관계 분석, 일정 점검, 추가 조사와 사실 등록 | `market_map.py chains/gaps`, `facts.py add`, `corpus.py`, `crosscheck.py` |
| 4 분석 노트 | 분석 노트 작성, 사실 번호로 수치 채우기, 숫자 대조, 배경 설명 검증 대기열, 매매 필수 요소 검사 | `stage.py render-note`, `verify_numbers.py`, `facts.py queue/verdict/lint`, `note_lint.py`, `base_rates.py`, `price_levels.py` |
| 5 결정 | 주문 제안 작성, 주문 근거 판정과 주문 전 결정 반영, 주문 규칙 검사, 전송 전 모의 실행 | `db.py import`, `facts.py decide --mode pre`, `risk_guard.py`, `execute.py`(dry-run), `req_audit.py` |
| 6 주문·체결 확인 | 주문 전송, 체결 확인, 매도 뒤 재투자, 실전 점검표, 기록, 마감 | `execute.py --send`, `fill.py`, `refill.py`, `real_check.py`, `journal.py`, `stage.py close` |

`stops.py`는 장중 매도 가격 조건을 확인해 실행하는 도구이며, 이 과정에는 AI의 판단이 개입하지 않습니다. 2026년 10월 20일 구성에서는 이 도구의 20분 간격 예약 실행을 꺼 둔 상태입니다. 주문 후 감사에서 매수 근거가 무너지면 `facts.py decide --mode post`가 해당 매수분의 매도를 기록하고, 장이 열려 있으면 같은 실행이, 닫혔으면 다음 실행이 처리합니다.

## 주문 검사와 중지 조건

주문 제안에 다음 검사를 적용합니다.

| 검사 | 내용 |
|---|---|
| 중지 파일 | `config/KILL`이 있으면 주문 제안을 읽기 전에 중지 |
| 계좌 모드 | `account_mode`가 모의, 실계좌 조회 전용, 실계좌 주문 중 하나를 정하며, 실계좌 주문은 `real_trading_enabled`까지 사람이 함께 켜야 열림. 실행의 계좌 계열은 시작 때 고정되고, 전송 프로그램은 기록의 계열이 현재와 다르면 보내지 않음 |
| 주문 제안 형식 | 스키마 버전, 필수 항목, 자산 배분 판단 블록이 없으면 전체 거부. 근거는 문장이 아니라 등록된 사실의 번호여야 함 |
| 유효 시간 | 생성 후 180분이 지난 주문 제안과 승인 후 30분이 지난 승인 파일은 무효 |
| 매매 대상 목록 | 목록에 없고 보유하지 않은 종목은 주문 거부. 편입·제외는 `universe_apply.py`가 `config/universe_rules.json`에 따라 판정 |
| 주문 근거 판정 | 매수 제안에 주문 전 판정 기록이 없거나, 판정표에서 1차·2차 출처로 확인된 근거가 하나도 없거나, 불일치로 판정된 근거를 쓰면 거부. 판정 뒤 값이 바뀐 사실은 재판정 요구 |
| 목표 기준 | 매수마다 목표 가격을 계산할 때 기준으로 삼은 가격 수준을 기록. 상승 여력이 하한(10%)에 못 미치면 거부. 판단자의 재량이 적게 들어가는 수준 대신 다른 수준을 골랐으면 선택 이유가 있어야 함 |
| 규모와 집중 | 새 종목의 첫 매수가 보유 평균보다 작으면 이유가 필요. 한 종목 20%, 한 거시 사건 40%를 넘기는 제안은 사유가 있어야 승인 |
| 요인 판정 | 여러 보유 종목에 영향을 주는 요인이 약해졌는데 대응 판단이 없으면 관련 종목의 매수 거부 |
| 자산 배분 판단의 연속성 | 직전 판단을 이어받지 않거나 근거 없이 변경한 제안은 거부. 투자 비중이 목표보다 낮으면 국내 2건, 미국 3건 이상의 제안을 요구 |
| 한도 파일 대조 | `config/limits.json`의 해시를 승인 파일에 기록하고 전송 직전에 다시 대조. 실행 중간에 한도를 바꾸면 거부 |
| 전송 직전 검사 | 전송 프로그램이 다섯 번째 단계 검사의 통과 기록을 확인하고, 시세를 다시 조회해 손절선 아래·진입 구간 밖·목표 여유 부족이면 보내지 않음 |
| 접수와 체결 | 접수 뒤 체결되지 않으면 승인 금액 안에서 정정, 시간 초과 시 잔량 취소, 취소 확정 뒤에만 재발주. 응답을 잃은 주문은 당일 목록으로 확정 |
| 주문당 상한 | 실계좌에서는 한 종목 한 번의 매수 금액에 상한을 두고, 1주 가격이 상한을 넘는 종목은 주수로 제한. 매도 주문은 줄이지 않음 |
| 매도 뒤 재투자 | 손절·추적 매도로 생긴 대금은 같은 실행에서 재투자 후보를 다시 심사 |

2026년 10월 20일 기준 설정은 `config/limits.json`에 있습니다. 모든 종목에 공통으로 적용하는 고정 비율 손절·추적 손절은 사용하지 않고, 종목별 투자 근거에 등록한 매도 조건을 적용합니다. 목표 가격 도달 시 매도하는 물량은 보유의 3분의 1까지만 허용하고 나머지는 추적 매도로 가져갑니다. 레버리지 ETF의 예상 투자 기간은 10일로 제한합니다. 일부 형식 요구(시나리오의 구조화 조건, 목표 기준)는 설정 파일의 적용일 전에는 경고, 적용일부터 거부로 바뀝니다.

## 데이터베이스

투자 근거·시나리오·시장 지도·일정·자산 배분과 조사 자료·시장 관측을 `journal/trading.db`에 저장합니다. 테이블 정의는 `db_schema.sql`에 있고, 데이터베이스 접근은 `db.py`가 맡습니다. 테이블 이름의 접두사는 기준 정보, 자료, 거시, 시장 상태, 세부시장, 종목, 일정, 출처·검증, 판단, 집행, 운영을 구분합니다.

- **사실.** 사실 한 건은 공통 항목을 저장하는 행과 종류별 상세 행으로 구성합니다. 종류나 필수 항목이 없으면 `facts.py add`가 거부합니다. 같은 식별 키의 사실은 한 번만 등록합니다. 교정할 때 버전을 올리고 이전 값도 보관하며, 기존 판정을 재검증 대상으로 바꿉니다.
- **판단과 집행.** 투자 근거는 사실을, 주문 제안은 투자 근거와 사실을, 승인·주문·체결 기록은 주문 제안의 버전을 번호로 참조합니다. 주문 제안을 바꿀 때마다 버전을 남기고, 승인 기록에는 입력 파일과 코드의 해시를 저장합니다.
- **읽기용 파일.** 읽기 전용 파일 7개(`journal/equity_curve.jsonl`, `feedback.jsonl`, `universe_coverage.json`, `market_map.json`, `theses.json`, `sources.json`, `config/watchlist.json`)는 검사 엔진과 공개용 동기화에서 사용합니다. `db.py`가 데이터를 쓸 때마다 다시 생성합니다. 손으로 고치지 않습니다. 공개본의 `journal/` 세 파일과 `config/watchlist.json`은 가상 견본입니다.
- **검사와 조회.** `python3 db.py doctor`(무결성·외래키·읽기용 파일 일치·스키마 버전), `python3 db.py show <표>`, `python3 db.py sql "SELECT …"`.
- **버전과 이전.** 데이터베이스의 스키마 버전이 코드와 다르면 열지 않습니다. `python3 db.py migrate`로 버전을 순서대로 올리며, 각 버전의 변경은 한 트랜잭션으로 처리합니다. 수집 단계마다 백업을 남깁니다. 기존 파일 원장에서 처음 옮길 때는 `migrate.py`를 사용합니다.
- **환경 변수.** `AITB_DB`가 저장소 경로를 가리킵니다. 테스트는 파일마다 임시 경로를 받고, 테스트 프로세스가 이 변수 없이 실제 저장소를 열면 막힙니다.

## 테스트

```bash
python3 run_tests.py          # 테스트 파일 14개를 끝까지 돌리고 전체 실행 완료 여부와 건수를 기록
python3 test_risk_guard.py    # 주문 규칙 검사만
```

2026년 10월 20일 공개 사본 기준 테스트는 14개 파일 453건이며, 주문 규칙, 주문 전송 경로, 주문 근거 판정, 저장소 저장·이전, 판단 원장, 노트 생성, 보고 계산, 가격 기준, 세션 날짜, 매도 뒤 재투자, 계좌 전환, 놓친 기회 집계의 동작을 확인합니다. 가짜 증권사 연결과 임시 저장소를 쓰며 네트워크와 API 키가 필요 없습니다. 테스트 러너는 끝까지 실행되지 못한 파일과 건수가 줄어든 파일을 실패로 기록하고, 주문 전송 경로의 코드가 마지막 완전 실행 뒤 바뀌었으면 표시합니다. 분석 정확도와 투자 수익성을 평가하는 테스트는 아닙니다.

두 건(장중 터치 매도의 일봉 저장, 가격 수준의 기준일)은 오늘의 국내 세션이 마감된 뒤를 가정하므로, 한국 시간 장중에 실행하면 실패로 표시됩니다. 장 마감 뒤에 다시 실행하면 통과합니다.

## 파일 구조

| 경로 | 역할 |
|---|---|
| `db.py`, `db_schema.sql` | 저장소 모듈과 표 정의. 읽기용 파일 생성, 버전 관리, 백업·복원, 일봉 캐시 |
| `facts.py` | 사실 등록·재사용·교정, 검증 대기열, 판정 기록, 판정 검사, 주문 전·후 결정 |
| `migrate.py`, `testkit.py` | 파일 원장에서 저장소로의 일회성 이전, 테스트용 임시 저장소 |
| `kis_client.py` | 증권사 API 연동. 기본 설정은 모의계좌이며 실계좌는 별도 허용 필요 |
| `ingest.py`, `dart_feed.py`, `fetch.py` | 잔고·시세·공시 수집, 링크 본문과 PDF 읽기. 키가 없으면 '미수집'으로 표시 |
| `market_map.py`, `scenarios.py`, `theses.py`, `allocation.py` | 시장 지도와 요인 상태, 시나리오·사건, 투자 근거와 매매 조건, 자산 배분 판단 |
| `base_rates.py`, `price_levels.py` | 유사 조건의 과거 수익률 분포, 가격 기준 계산 |
| `verify_numbers.py`, `crosscheck.py`, `note_lint.py` | 숫자 대조, 도구 결과와 노트의 대조, 노트의 매매 필수 요소 검사 |
| `risk_guard.py` | 주문 규칙 검사. 네트워크·LLM 호출 없음 |
| `execute.py`, `fill.py`, `stops.py`, `refill.py` | 주문 전송(기본은 모의 실행), 체결 확인, 장중 매도 감시, 매도 뒤 재투자 |
| `journal.py`, `portfolio.py`, `review.py`, `regret.py` | 자산 곡선·고점·주간 리포트, 통합 자산과 수익률, 회고, 놓친 기회 집계 |
| `feedback.py`, `loss_review.py` | 주간 피드백의 원인 분석과 변경 기록, 손실 거래의 판단 검토 |
| `run_auto.py`, `stage.py`, `sessions.py` | 무인 실행, 단계 전환과 노트 생성·마감, 거래 세션의 현지 날짜 |
| `universe_apply.py`, `universe_review.py`, `main_names.py` | 매매 대상 편입·제외 판정, 양방향 검토, 시가총액 상위 종목 |
| `account_switch.py`, `account_status.py`, `real_check.py`, `real_probe.py` | 계좌 전환, 계좌 현황 블록, 실전 점검표, 실계좌 조회 점검 |
| `costs.py`, `tax_ledger.py`, `support_break.py`, `screen_treasury.py` | 매매 비용, 해외주식 양도세 원장, 지지 구간 이탈 재판정, 자사주 소각 스크린 |

| `_archive/srcledger.py`, `testdata/db_schema_v1.sql` | 테스트가 형식 비교와 이전 검사에 쓰는 보관 모듈과 옛 스키마 |

프로그램이 사용하는 계좌·시세 스냅샷과 AI가 읽는 뉴스 자료는 별도 파일에 둡니다. 주문 검사는 스냅샷을 읽고, AI는 그 값을 수정하지 않도록 합니다.

## 비공개 자료

이 폴더에는 개인 학습 노트와 구독 뉴스레터 원문, 실제 분석·매매 기록과 데이터베이스, 인증 정보를 넣지 않았습니다. 공개할 수 있는 분석·평가 사례만 [실제 기록 발췌](../examples/실제_기록_발췌.md#investment)에 요약했습니다. `data/`, `analysis/`, `signals/`, `journal/`, `logs/`, `_raw_sources/`에는 실제 운영 자료를 넣지 않았으며 실행 시 생성됩니다. 실제 매매 대상 목록과 편입 사유, 개발 일지도 비공개입니다. 필요한 키는 저장소 루트의 `.env.example`을 참고해 `.env`에 입력합니다.
