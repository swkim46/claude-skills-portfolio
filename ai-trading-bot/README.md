# 뉴스 분석과 모의매매 시스템

뉴스와 시장 데이터를 분석해 투자 시나리오를 수립하고 모의매매를 진행합니다. AI가 제안한 주문은 단계별 검사와 주문 규칙을 통과한 경우에만 전송하며, 접수와 체결 결과를 구분해 기록합니다.

모의투자 시스템의 공개용 코드입니다. 작업 절차와 판단 기준은 [trade-run 스킬 문서](../.claude/skills/trade-run/SKILL.md), 설계 근거는 [저장소의 설계 문서](../docs/)에 정리했습니다. Python 3.9 이상에서 표준 라이브러리만 사용합니다. 실제 자료 수집과 주문에는 한국투자증권 모의투자 API 키가 필요하며, 주문 규칙 검사와 테스트는 키 없이 실행할 수 있습니다.

## 실행 중지와 재개

```bash
touch config/KILL   # 전면 중지. 시그널을 읽기 전에 판정하므로 어떤 주문도 나가지 않는다
rm config/KILL      # 재개
```

자동 실행이 연속 3회 실패하면 KILL 파일을 생성해 중지합니다. 원인을 확인하고 해당 파일을 삭제해야 재개할 수 있습니다.

## 실행 방식

실행은 사람이 시작하며 개별 주문에 대한 수동 승인 단계는 없습니다. 단계별 검사와 주문 규칙으로 전송 여부를 결정합니다. 상시 운영 서버로 이전한 뒤 예약 실행을 적용할 계획입니다.

```bash
python3 run_auto.py --self-test             # 환경 점검. 주문·LLM 호출 없음
python3 run_auto.py --market kr --no-send   # 전 과정을 돌리되 주문만 보내지 않음
python3 run_auto.py --market kr             # 주문 전송까지
```

Claude Code 세션에서는 `/trade-run kr` 또는 `/trade-run us`로 같은 절차를 실행합니다. `run_auto.py`는 자료 수집, 분석 세션 실행, 검사 통과 확인, 주문 전송, 실패 시 중지를 순서대로 수행하며 서버 이전 후에도 사용할 예정입니다. AI 세션은 분석과 제안을 담당하고, `risk_guard`·`execute`·`journal`은 세션 밖에서 실행됩니다. "AI는 제안만 한다"는 원칙에 따라 프로세스의 역할을 분리했습니다.

## 실행 단계

여섯 단계로 구성되며, 각 단계가 끝나면 검사 엔진(`../.claude/skills/_stepgate/stepgate.py`)의 통과 기록이 있어야 다음 단계로 진행합니다.

| 단계 | 작업 내용 | 주요 스크립트 |
|---|---|---|
| 1 수집·측정 | 잔고·시세·공시·뉴스레터 수집, 전 업종 등락 측정 | `ingest.py`, `market_map.py board`, `srcledger.py` |
| 2 이전 실행 확인 | 직전 실행 회고, 대기 중인 매매 조건·시나리오 점검, 자산 배분 판단 인계 | `stage.py`, `scenarios.py`, `theses.py`, `allocation.py` |
| 3 시장 분석·조사 | 거시 사건과 개별 종목의 영향 관계 분석, 일정 점검, 추가 조사 | `market_map.py chains/gaps`, `corpus.py`, `crosscheck.py` |
| 4 분석 노트 | 분석 노트 작성, 숫자 대조, 출처 검증 | `verify_numbers.py`, `extract_ai_claims.py`, `base_rates.py`, `price_levels.py` |
| 5 결정 | 시그널 작성, 주문 규칙 검사, 전송 전 모의 실행 | `risk_guard.py`, `execute.py`(dry-run), `req_audit.py` |
| 6 주문·체결 확인 | 주문 전송, 체결 확인, 기록 | `execute.py --send`, `fill.py`, `journal.py`, `review.py` |

장중에는 `stops.py`가 매도 가격 조건을 별도로 확인해 실행합니다. 이 과정에는 AI의 판단이 개입하지 않습니다.

## 주문 검사와 중지 조건

의도하지 않은 주문을 막기 위해 다음 검사를 항상 수행합니다.

| 검사 | 내용 |
|---|---|
| 중지 파일 | `config/KILL`이 있으면 시그널을 읽기 전에 중지 |
| 실계좌 잠금 | `real_trading_enabled=false`. 실계좌 키가 있어도 전송하지 않음 |
| 시그널 형식 | 스키마 버전, 필수 항목, 자산 배분 판단 블록이 없으면 전체 거부 |
| 시그널 유효 시간 | 생성 후 180분이 지난 시그널과 승인 후 30분이 지난 승인 파일은 무효 |
| 매매 대상 목록 | 목록에 없고 보유하지 않은 종목은 주문 거부. 편입·제외는 `universe_apply.py`가 `config/universe_rules.json`에 따라 판정 |
| 근거 확인 | 출처 검증에서 불일치로 판정된 근거를 사용한 제안은 거부 |
| 자산 배분 판단의 연속성 | 직전 판단을 이어받지 않거나 근거 없이 변경한 시그널은 거부 |
| 한도 파일 대조 | `config/limits.json`의 해시를 승인 파일에 기록하고 전송 직전에 다시 대조 |
| 예수금 확인 | 예수금 조회에 실패하면 0으로 처리하지 않고 매수만 보류 |

2026년 9월 23일 기준 설정은 `config/limits.json`에 있습니다. 고정 비율 손절과 추적 손절은 비활성화돼 있으며, 종목별 투자 시나리오의 매도 조건을 적용합니다. 모의계좌에는 일일 주문 상한을 두지 않았고 실계좌 전환 시에는 설정해야 합니다. 매수 제안의 1차 목표가가 현재가에서 3% 안에 있으면 거부합니다. 한 종목의 비중이 20%, 한 거시 사건의 비중이 40%를 넘으면 사유를 기록해야 합니다. 투자 비중이 목표보다 낮으면 국내 2건, 미국 3건 이상의 제안을 요구합니다. 레버리지 ETF의 예상 투자 기간은 10일로 제한합니다.

## 테스트

```bash
python3 test_risk_guard.py
```

2026년 9월 23일 기준 테스트는 109건이며, 주문 규칙과 단계별 검사 코드의 동작을 확인합니다. 분석 정확도와 투자 수익성을 평가하는 테스트는 아닙니다. 네트워크와 API 키 없이 실행할 수 있으며, 실제 실행 산출물이 필요한 항목 하나는 공개본에서 건너뜁니다.

## 파일 구조

| 경로 | 역할 |
|---|---|
| `kis_client.py` | 증권사 API 연동. 기본 설정은 모의계좌이며 실계좌는 별도 허용 필요 |
| `ingest.py` | 잔고·시세·공시 수집. 코드용 스냅샷과 AI 분석용 자료를 각각 생성 |
| `dart_feed.py` | 공시 수집. 키가 없으면 '미수집'으로 표시해 공시가 없는 경우와 구분 |
| `market_map.py` | 업종별 등락, 거시 사건과 종목의 관계, 관련 일정 관리 |
| `theses.py`, `scenarios.py`, `allocation.py` | 매매 조건, 시나리오, 자산 배분 판단 기록 |
| `base_rates.py`, `price_levels.py` | 유사 조건의 과거 수익률 분포와 가격 기준 계산 |
| `verify_numbers.py`, `srcledger.py`, `crosscheck.py` | 숫자 대조, 사실의 세 가지 시점 기록, 조사 결과의 분석 반영 확인 |
| `risk_guard.py` | 주문 규칙 검사. 네트워크·LLM 호출 없음 |
| `execute.py`, `fill.py` | 주문 전송과 체결 확인. 기본 설정은 주문을 전송하지 않는 모의 실행 |
| `journal.py`, `review.py`, `regret.py` | 실행 기록, 주간 리포트, 회고, 놓친 기회 분석 |
| `run_auto.py` | 전체 절차의 순차 실행 |
| `config/limits.json`, `config/watchlist.json` | 주문 한도, 매매 대상 목록(공개본은 견본) |

코드가 사용하는 스냅샷과 AI가 읽는 자료는 별도 파일로 관리합니다. 주문 규칙 검사가 뉴스 본문의 영향을 받지 않고, AI가 잔고 값을 수정하지 못하도록 분리한 구조입니다. `journal/`의 시장 지도와 투자 근거 파일은 테스트용 가상 데이터입니다.

## 비공개 자료

개인 학습 노트, 구독 뉴스레터 원문, 실제 분석·매매 기록과 인증 정보는 포함하지 않았습니다. `data/`, `analysis/`, `signals/`, `journal/`, `logs/`, `_raw_sources/`에는 실제 운영 자료를 넣지 않았으며 실행 시 생성됩니다. 실제 매매 대상 목록과 편입 사유, 설계 근거 조사 문서, 개발 일지도 비공개입니다. 필요한 키는 저장소 루트의 `.env.example`을 참고해 `.env`에 입력합니다.
