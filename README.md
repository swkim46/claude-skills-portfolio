# 금융 뉴스레터를 학습과 투자에 활용하는 AI 시스템

금융·경제 뉴스레터로 학습 노트를 작성하는 **world-study**와 뉴스·시장 데이터를 분석해 모의투자를 진행하는 **trade-run**을 개발해 운영하고 있습니다. Claude Code에 작업 절차와 판단 기준을 정의하고, Python으로 자료 수집·검사·주문 처리를 구현했습니다.

- **world-study**는 뉴스의 배경과 경제 개념을 설명하는 학습 노트를 작성합니다. AI가 추가한 설명은 원문에 있는 내용과 구분하고, 별도로 출처를 확인합니다.
- **trade-run**은 뉴스에서 투자 시나리오를 도출하고 매매 조건을 설정합니다. AI가 제안한 주문은 단계별 검사와 사전에 정한 규칙을 통과한 경우에만 모의계좌로 전송합니다.

이 저장소에는 두 시스템의 설계 과정과 각 결정의 근거를 담았습니다. 정보를 검증하는 방법, 조사 결과를 분석에 반영하는 절차, 작업 수행 여부를 확인하는 방식을 설명합니다.

개발 배경과 초기 설계는 [프로젝트 배경과 설계 과정](docs/00_프로젝트_배경과_설계.md)에 정리했습니다.

## 설계 과정에서 다룬 여섯 가지 질문

### 1. AI가 덧붙인 설명을 어떻게 검증할까?

학습 노트를 검토하다가 용어의 정의와 배경 설명에서 오류를 발견했습니다. 자연스럽게 읽히는 문장도 출처와 대조하면 내용이 일치하지 않았습니다.

검증 대상을 구분하기 위해 원문에 있는 내용, AI가 추가한 사실 설명, 해석을 각각 표시했습니다. AI가 추가한 사실 설명에는 `[AI]`, 해석에는 `[추정]`을 붙입니다. `[AI]` 문장은 출처에 접근할 수 있는지, 주장을 뒷받침하는 내용이 있는지, 현재에도 유효한 정보인지, 해당 사실을 확인하기에 적절한 출처인지 검토합니다.

매매 분석에 쓰인 숫자는 원자료와 대조합니다. 출처를 확인하지 못한 상태와 내용이 틀린 상태도 구별해 기록합니다.

[정보의 출처와 내용을 검증하는 방법](docs/01_정보_검증.md)

### 2. 분석의 근거를 어떻게 확인할까?

초기 모의매매에서는 '이미 가격에 반영됐다', '발표를 기다려야 한다'는 설명으로 매매를 보류하는 일이 있었습니다. 어떤 데이터를 근거로 판단했는지, 어떤 조건에서 판단을 바꿀지 제시하지 않아 타당성을 검토하기 어려웠습니다.

이후에는 뉴스를 해석하기 전에 업종별 가격 변화를 먼저 확인하도록 했습니다. 유사한 조건에서 나타난 과거 결과와 계산 가능한 가격 기준을 함께 검토하고, 결론을 바꿔야 할 조건도 명시합니다. 과거 사례를 사용할 때는 표본 수와 비교 조건을 확인합니다.

학습 노트에서도 사건을 나열하는 데서 끝나지 않도록 했습니다. 원인과 결과가 어떻게 연결되는지 설명하고, 그 설명을 뒷받침하는 근거를 확인합니다.

[분석에 필요한 근거와 비교 기준](docs/02_분석_근거와_비교_기준.md)

### 3. 뉴스를 투자 시나리오로 어떻게 연결할까?

뉴스레터를 받는 시점에는 사건이 이미 알려져 있고, 가격에도 일부 반영돼 있을 수 있습니다. 뉴스에 등장한 기업을 바로 매수하는 방식으로는 더 빠르게 정보를 접한 참여자보다 앞서기 어렵다고 판단했습니다.

먼저 사건이 산업과 기업에 미치는 영향을 단계별로 확인합니다. 각 연결을 뒷받침하거나 반박하는 자료를 조사한 뒤, 매수 조건과 판단을 철회할 조건을 정합니다. 사건의 2차·3차 영향, 제도 변경에 따른 변화, 일정이 공개된 발표를 중심으로 대응을 미리 준비합니다.

이 조건을 미리 기록해 두고, 이후 가격 변화나 예정된 발표가 조건에 부합하는지 확인합니다. 뉴스의 의미를 해석하는 작업과 주문 여부를 결정하는 작업을 구분한 이유입니다.

[투자 시나리오와 매매 조건을 설정하는 방법](docs/03_투자_시나리오_설계.md)

### 4. 자료가 부족할 때 조사를 어떻게 이어갈까?

필요한 명단을 구하지 못했다며 조사를 중단한 적이 있었습니다. 확인해 보니 해당 명단은 전날 저장한 자료에 있었습니다. 이미 확보한 자료를 충분히 검색하지 않은 것이 문제였습니다.

이후에는 기존 자료를 먼저 검색하고, 답을 찾지 못하면 검색어와 조사 대상을 넓히도록 했습니다. 직접적인 자료가 없을 때는 관련 기업이나 사업의 자료를 통해 확인할 수 있는지도 검토합니다.

끝내 확인하지 못한 내용은 미확인 상태로 남기고, 다시 조사할 시점이나 조건을 기록합니다. 새로 찾은 정보가 실제 분석과 판단에 반영됐는지도 점검합니다.

[자료 탐색과 추가 조사를 이어가는 방법](docs/04_추가_조사_절차.md)

### 5. 필요한 작업이 실제로 끝났는지 어떻게 확인할까?

완성된 노트만 검사하던 방식으로는 앞선 단계에서 발생한 자료 누락이나 확인 절차의 생략을 잡아내기 어려웠습니다.

모의투자의 여섯 단계 사이에 검사를 배치했습니다. 각 단계의 파일과 기록을 확인하고 필요한 조건을 충족해야 다음 단계로 진행합니다. 내용은 AI가 검토하고, 파일에서 확인할 수 있는 항목은 코드로 다시 검사합니다. AI에는 검사 질문만 제시하고 합격 기준은 알려 주지 않으며, 코드의 파일 검사는 AI의 답변과 별도로 수행합니다.

매매를 하지 않기로 한 경우에도 판단 근거를 확인합니다. 주문을 보낸 경우에는 접수 여부와 실제 체결 결과를 구분해 기록합니다.

[단계별 검사와 실행 기록을 설계한 이유](docs/05_단계별_검사.md)

### 6. 시스템이 제 역할을 하는지 무엇으로 판단할까?

개발 전 검토한 공개 사례에서는 거래 비용을 반영한 AI의 초과수익 수치를 찾지 못했습니다. 초기에는 매매 규칙을 지키고 실행 과정을 기록하는 데 집중했습니다. 그러나 매매 보류가 반복되면서, 규칙 준수만으로는 투자 시스템의 성과를 설명하기 어렵다는 문제가 드러났습니다.

현재 모의투자 시스템의 목표는 수익성 검증입니다. 규칙 준수, 주문 오류 방지, 기록의 완전성은 운영 조건으로 관리합니다. 성과는 비교 기준으로 정한 시장 지수의 수익률과 함께 기록합니다. 시나리오를 사전에 수립했는지, 실제 전개가 예상에 부합했는지도 평가합니다.

학습 노트는 뉴스의 배경과 개념을 이해하는 데 필요한 설명이 담겼는지, 추가한 설명에 근거가 있는지를 검토합니다. 두 시스템 모두 목적에 맞는 평가 기준을 정하고, 운영 과정에서 그 기준을 보완하고 있습니다.

[성과를 평가하는 기준과 현재 검증 범위](docs/06_성과_평가_기준.md)

## 가상 사례로 보는 판단 과정

하나의 가상 뉴스를 검토해 학습 노트와 투자 시나리오를 만드는 과정을 정리했습니다. 단계별로 확인한 내용, 판단의 근거, 수정하거나 보류할 조건을 설명합니다.

기업·수치·계좌 정보는 모두 시연용으로 구성했습니다. 전체 사례는 설계된 절차를 설명하는 예시이며, 실제 코드를 실행한 부분은 별도로 표시했습니다.

[가상 뉴스 한 건을 검토하는 과정](examples/가상_사례_판단_과정.md)

## 운영 현황

*2026년 9월 27일 기준*

- **학습 노트:** 2026년 8월 28일부터 평일마다 운영하고 있습니다. 작성 규칙은 직접 작성한 학습 기록 177개 항목과 뉴스레터 원문 57통을 대조해 정리했습니다.
- **모의투자:** 2026년 9월 8일 첫 모의매매를 진행했습니다. 실행은 사람이 시작하고, 이후 검사와 주문 판단은 자동으로 이루어집니다. 예약·무인 실행으로 전 과정을 완료한 기록은 아직 없으며, 주문 처리 오류의 원인을 점검하고 있습니다.
- **검증 범위:** 뉴스에서 도출한 시나리오가 적절한 종목 선정과 매매로 이어지는지, 그 결과 수익성이 있는지 검증하고 있습니다. 실제 계좌 정보와 성과 수치는 공개하지 않습니다.
